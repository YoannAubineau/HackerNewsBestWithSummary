## Résumé de l'article

Common Lisp est un langage de programmation standardisé depuis 1994, basé sur le traitement de listes où code et données partagent la même structure. L'auteur argue que ses caractéristiques le rendent particulièrement adapté au développement avec les LLM : absence de distinction nette entre compilation et exécution, gestion d'erreurs sans crash de programme, et capacités de macro pour créer des langages spécialisés.

- **Boucle de feedback rapide** : Common Lisp fonctionne en mémoire vivante ; les modifications de fonctions prennent effet immédiatement sans redémarrage, accélérant les itérations de développement avec les LLM
- **Gestion d'erreurs non fatale** : le programme s'arrête et ouvre un débogueur interactif au lieu de crasher, permettant au LLM de voir l'état complet et de corriger sans relancer
- **Macros et langages spécialisés** : les macros permettent de transformer le code à la compilation ; l'auteur suggère que les entreprises peuvent construire des langages de domaine pour leurs produits, facilitant les adaptations par LLM
- **Concision du code** : selon l'auteur, les programmes Common Lisp sont 6 à 7 fois plus courts que leurs équivalents Python, réduisant les tokens consommés par les LLM et leur coût
- **Stabilité linguistique** : la norme ANSI inchangée depuis 1994 garantit qu'aucune modification de langage ne cassera le code utilisateur construisant sur des domaines spécialisés

## Discussion sur Hacker News (327 commentaires)

**Avis positifs** :
- Common Lisp's live debugging and REPL capabilities enable rapid iteration with LLMs: pause execution, inspect state, make fixes, and resume without restarting, unlike most languages
- Concise code via macros reduces token usage, which directly impacts LLM development costs and context window requirements
- Image-based development and hot-reloading allow LLMs to modify running systems in real-time without full recompilation cycles
- Homoiconicity (code-as-data) makes it natural for LLMs to manipulate and generate code, particularly for domain-specific languages and abstractions
- Stability since 1994 ANSI standard means predictable behavior and abundant training data for LLMs to learn from

**Avis négatifs** :
- Strong static type systems (Rust, OCaml, Haskell) provide compiler feedback that guides LLMs better and prevents hallucination errors compared to dynamic typing
- Lack of ecosystem forces LLM-driven reimplementation of libraries from scratch, consuming far more tokens than using existing well-tested packages
- Lisp's ad-hoc macro culture and lack of standardized patterns make code harder for LLMs to reason about consistently compared to opinionated languages like Go or Rust
- Common Lisp remains niche with limited training data; popular languages with large codebases give LLMs better patterns to learn from
- The claim conflates human programming preferences (macros, REPL workflow) with actual LLM optimization; most arguments apply equally to other dynamic languages
