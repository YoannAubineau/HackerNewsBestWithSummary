## Résumé de l'article

L'article critique les systèmes de mémoire actuels pour agents IA, qui reposent sur des bases de données vectorielles et la recherche par similarité (RAG). L'auteur soutient que cette approche résout le mauvais problème : au lieu de capturer et récupérer des fragments de conversations passées, les agents ont besoin d'une documentation structurée et auditable qu'ils peuvent consulter, mettre à jour et partager.

- Les plugins de mémoire actuels utilisent tous le même modèle : analyser les transcriptions, générer des extraits, les indexer dans une base de données vectorielle, et injecter les résultats les plus similaires à chaque invite (RAG)
- Cette approche présente des failles majeures : la similarité ne garantit pas l'exactitude, le contexte se perd dans les fragments, le code change constamment rendant les mémorabilisations obsolètes, et les agents ne savent pas quand chercher
- La solution proposée est une mémoire basée sur des documents Markdown structurés : instructions, spécifications, décisions, index que l'agent peut lire avant de travailler et mettre à jour après
- L'auteur a développé un système appelé Operator Memory (open source) qui remplace les bases vectorielles par des documents lisibles, versionnables et partageables avec l'équipe
- Le workflow passe de « prompt → construire → oublier » à « prompt → consulter → construire → mettre à jour », transformant la mémoire d'un système boîte noire en un espace de travail transparent

## Discussion sur Hacker News (129 commentaires)

**Avis positifs** :
- La documentation structurée et queryable est plus efficace que des systèmes de mémoire opaques et non curés qui deviennent rapidement obsolètes ou pollués
- Les approches basées sur des fichiers bien organisés (README, AGENTS.md, ADR, principes versionnés) permettent aux agents de mieux découvrir et respecter les intentions du projet
- La documentation en tant que source de vérité unique (code, tests, specs dans le repo) évite la duplication d'état et les incohérences entre mémoire et réalité
- Les modèles modernes peuvent maintenir la cohérence documentaire sans outils complexes de mémoire si le contexte est bien structuré et accessible
- Organiser les décisions et principes comme références versionnées plutôt que comme mémoire brute permet une relégitimation des décisions quand les règles changent

**Avis négatifs** :
- Les agents ignorent systématiquement la documentation existante (ADR, AGENTS.md, skills) pour générer des scripts ad-hoc, ce qui rend la documentation documentée inopérante
- La simple documentation ne suffit pas si les agents ne la consultent pas ou ne la suivent pas ; il faut des mécanismes d'application stricter (hooks, linters avec messages guidés)
- La documentation rédigée par les agents a tendance à se diluer, à contenir des extrapolations non demandées et du bloat qui revient comme un boomerang
- Créer et maintenir une documentation de qualité demande des efforts humains significatifs que la plupart des utilisateurs ne font pas, d'où le besoin de contourner la documentation
- Les systèmes de documentation n'offrent pas la flexibilité de requête et les liens sémantiques que pourrait fournir une base de données (graphe de raisons, contexte de cause/effet)
