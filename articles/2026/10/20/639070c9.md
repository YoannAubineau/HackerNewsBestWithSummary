## Résumé de l'article

Un développeur a installé Arch Linux ARM sur un laptop ASUS ProArt P16 équipé de 128 GB de RAM et d'une GPU RTX pour contourner l'absence de support officiel non-Windows. Ce projet a permis d'accéder à 116 GiB de mémoire partagée entre CPU et GPU, contre une division restrictive sous Windows.

- Les performances CPU en compression 7-Zip sont comparables à Windows, voire 3-5% supérieures en multi-thread, tandis que la configuration Linux rapporte 116 GiB de mémoire CUDA disponible contre 109,7 GiB maximum sur Windows
- L'installation requiert des patches du kernel NVIDIA, des modifications ACPI, du support HID-ASUS pour le clavier et un driver audio personnalisé, tous distribués via un dépôt public avec build scripts
- L'auteur a réussi à faire tourner le modèle Qwen 3.8B quantifié en FP4 via vLLM en temps réel sur le laptop, allouant près de 90 GiB à la fois au modèle et au cache KV, générant ~30 tokens/s en code review avec 100% de taux de réussite sur 171 inférences consécutives
- La mémoire partagée CPU-GPU élimine le besoin de redémarrer pour ajuster les réservations dédiées, contrairement à Windows
- Le display fonctionne à 3840×2400 en 120 Hz, avec NetworkManager, PipeWire et Podman rootless pour les conteneurs GPU

## Discussion sur Hacker News (110 commentaires)

**Avis positifs** :
- L'auteur a des raisons légitimes au-delà du simple obstacle technique : privacy, publicités Windows, refus de la dépendance au cloud, et elle est mainteneur Arch Linux avec expertise réelle
- Windows impose de plus en plus une connexion cloud obligatoire, même sur les versions Home ; contourner cela nécessite des manipulations complexes ou des scripts externes
- Le travail technique accompli (patches pour booter Linux, repo GitHub documenté) a une valeur pour ceux sans intérêt à utiliser Windows sur ce matériel
- Un cas d'usage solide existe : pouvoir exécuter localement des modèles IA, fine-tuning et quantisation sur un laptop puissant pour quelqu'un publiant des quants sur Hugging Face

**Avis négatifs** :
- Le RTX Spark a une bande passante mémoire limitée (seulement ~30 tok/s sur Qwen 3.8) comparé aux alternatives AMD ou Intel avec GPUs dédiés, rendant le rapport prix/performance médiocre
- Pour 6000$ on peut obtenir bien mieux : un Zephyrus G16 avec RTX 5080 et 64GB, un mini PC AMD puissant, ou attendre les MacBook Pro M7 ; le RTX Spark manque de proposition claire pour son marché cible
- Créer un compte Microsoft gratuit aurait résolu l'enjeu plus rapidement qu'une installation Linux complexe ; presenter cela comme blocage majeur minimise la réalité des alternatives
- Windows on ARM a des problèmes de compatibilité logicielle et de performance pour le gaming malgré le marketing NVIDIA, contrairement aux GPUs discrets ou aux solutions Apple Silicon
- Le design ARM64 a ~3 ans et reste moins compétitif ; pas de support Linux mature pré-installé officiellement, contrairement aux DGX Spark déjà disponibles avec Ubuntu et support NVIDIA
