I saw this LinkedIn post from a Meta engineer and it resonated with me:

https://www.linkedin.com/posts/ali-hamie\_im-an-engineer-at-m...

\> I'm an engineer at Meta and I never felt this uncomfortable doing my job. I'm writing code these days and it all feels like a black box. This new standard of shipping with AI is moving so fast that if we're going to spend our time checking each line of code, it's going to take forever. That means you can end up with systems you've built where you don't truly understand how all the code works. You understand the high level, but not every detail. And maybe this is becoming the new standard. It goes against every instinct of being a software engineer. I'm used to understanding what I'm building. Now I'm trying to figure out how much I need to understand before I'm comfortable moving forward. Are other engineers feeling this too?

How are you handling this?

## Discussion sur Hacker News (388 commentaires)

**Avis positifs** :
- Les tests exhaustifs et les approches rigoureuses (vérification multi-architecture, gates de qualité) permettent de valider le code généré sans nécessairement en comprendre chaque ligne, similaire à la confiance accordée aux collègues.
- Cette transition reflète l'évolution naturelle des abstractions en informatique (compilateurs, frameworks, langages haut niveau) : on n'a jamais compris tout ce qu'on shippe, et déléguer l'implémentation aux agents libère du temps pour la conception et les décisions architecturales.
- Les équipes expérimentées peuvent exploiter efficacement les LLM en définissant clairement les responsabilités : concevoir l'architecture, établir les garde-fous, et laisser l'IA implémenter les détails, ce qui améliore la vélocité sans sacrifier la qualité.
- Investir davantage dans la vérification, la monitoring en production et les rollbacks permet de gérer le risque ; les problèmes remontent rapidement et peuvent être corrigés itérativement.
- L'IA excelle à expliquer son propre code et à aider à la documentation ; on peut demander des clarifications plutôt que de relire manuellement, ce qui rend l'apprentissage plus efficace.

**Avis négatifs** :
- Accepter du code sans le comprendre érode la capacité à concevoir de bonnes abstractions et à maintenir le système lors de crises ; on devient entièrement dépendant de l'IA pour toute modification.
- Les LLM produisent souvent du code mal architecturé, non maintenable, avec des abstractions pauvres qui rendent les refactoring futurs coûteux et complexes.
- Confier la rédaction des tests à la même IA qui écrit le code crée un faux sentiment de sécurité : les tests peuvent échouer ensemble aux mêmes endroits, ratant les vrais bugs.
- À grande échelle chez des géants comme Meta, la pression pour livrer rapidement crée une culture du slop sans planification ni revues sérieuses, sacrifiant la qualité à long terme.
- Les développeurs juniors qui n'ont jamais écrit de code à la main ne développent pas l'intuition nécessaire pour repérer les failles architecturales ou les décisions suboptimales de l'IA.
