## Résumé de l'article

Codex CLI est un outil en ligne de commande d'OpenAI pour interagir avec les modèles de langage. Depuis la version 0.157.0, l'ouverture d'une session Codex démarre automatiquement un daemon persistant qui fonctionne en arrière-plan, indépendamment de la fenêtre principale.

- Le daemon se lance automatiquement, continue de tourner après fermeture de toutes les fenêtres Codex, et ne s'arrête que manuellement ou au redémarrage du système
- Une copie complète du paquet (~374 MB) est téléchargée dans `~/.codex/packages/app-server-daemon/` et le daemon tourne depuis cette copie, découplé de la version CLI installée
- Un processus de mise à jour (`pid-update-loop`) vérifie les mises à jour toutes les heures et peut redémarrer le backend, interrompant potentiellement les sessions actives
- Les variables d'environnement de la première session qui a lancé le daemon (comme les paramètres proxy) restent figées, affectant toutes les connexions ultérieures
- L'utilisateur demande que `daemon_auto_start` soit désactivé par défaut pour la CLI ou au minimum que l'utilisateur soit interrogé avant son activation

## Discussion sur Hacker News (225 commentaires)

**Avis positifs** :
- Les mises à jour automatiques sont devenues standard dans les navigateurs et les outils modernes ; c'est une pratique industrielle normale pour maintenir la sécurité et la stabilité.
- Le daemon permet des cas d'usage professionnels comme la construction d'applications tierces sur le serveur daemon et facilite l'intégration avec d'autres harnesses.
- Les mises à jour peuvent être désactivées via des paramètres de configuration (`daemon_auto_start = false` dans `~/.codex/config.toml`) ou via l'option `--no-daemon`.
- Les harnesses offrent une facilité de configuration sans précédent : les utilisateurs peuvent demander à l'IA elle-même de modifier le comportement pour contourner les problèmes.
- OpenAI permet l'utilisation de harnesses alternatives comme Pi, offrant une flexibilité que certains concurrents n'accordent pas.

**Avis négatifs** :
- Les mises à jour automatiques non consentantes violent l'autonomie des utilisateurs et sont inadaptées aux outils professionnels, surtout pour les démonstrations ou projets critiques nécessitant la stabilité.
- Codex accumule massivement d'anciennes versions (12 GB observés), remplissant les disques durs de manière insensée pour un simple harness ; les binaires font ~300 MB chacun sans justification.
- La qualité générale du code de Codex est déplorable : bugs constants lors des mises à jour (permissions corrompues de .git, fenêtres PowerShell visibles, regains non fonctionnels, extension VSCode extrêmement instable).
- Le daemon s'exécute en arrière-plan sans contrôle de l'utilisateur et cause des problèmes sérieux : perte de variables d'environnement, interférences avec les workflows, utilisation abusive des ressources système.
- Les harnesses ne respectent pas les standards Unix/XDG et réinventent inutilement des solutions de mise à jour que les gestionnaires de paquets résoudraient mieux ; c'est une violation de la souveraineté utilisateur.
