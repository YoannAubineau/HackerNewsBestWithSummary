## Résumé de l'article

Une étude de Harvard analysant les données de 700 000 employés dans plus de 700 entreprises de logiciels montre que les agents d'IA de codage génèrent 30 % de code supplémentaire, mais ne créent pas plus de logiciels livrés. L'efficacité gagnée lors de la phase de codage est absorbée par l'augmentation du travail de révision de code, qui devient un goulot d'étranglement majeur.

- Les agents d'IA entraînent une augmentation de 30 % des lignes de code, 20 % des commits et 23 % des pull requests, sans changement statistique dans la résolution des issues et épics logiciels
- La révision de code est devenue un processus beaucoup plus long, avec davantage de demandes de révision et plus de commentaires des relecteurs
- L'étude s'appuie sur 300 millions d'événements de travail (commits, pull requests) et d'analyses GitHub de 2021 à mars 2026 dans 700 entreprises
- Aucune preuve que l'adoption d'outils d'IA augmente la production logicielle globale ou réduit l'emploi dans les firmes étudiées

## Discussion sur Hacker News (266 commentaires)

**Avis positifs** :
- Les agents d'IA capturent effectivement des bugs importants et permettent aux développeurs de gagner du temps sur des tâches répétitives et de configuration initiale.
- Les projets personnels et les startups produisent davantage de logiciels utiles grâce à l'IA, ce que les métriques corporatives classiques ne capturent pas.
- Le coût réduit de la génération de code permet d'explorer plus d'hypothèses et d'itérer plus rapidement sur les designs de produit.
- Les équipes performantes avec des processus solides et une architecture claire voient des gains de productivité substantiels en utilisant les agents correctement.

**Avis négatifs** :
- La revue de code devient un goulot d'étranglement majeur car les humains ne peuvent pas vérifier les énormes volumes de code générés, transférant plutôt que résolvant le problème.
- Le code généré tend à être verbeux, redondant, difficile à maintenir et accumule rapidement de la dette technique qui freine les équipes à long terme.
- Les bénéfices réels restent mineurs dans les grandes organisations (4-5% de gain de revenus) car la génération de code n'était jamais le vrai goulot : la conception, les exigences et la compréhension produit le sont.
- L'absence de vision stratégique et de revue humaine de la conception produit une prolifération de code fonctionnellement correct mais architecturalement problématique, amplifiant les mauvaises pratiques existantes.
