## Résumé de l'article

Cet article détaille les différences substantielles de conception et de fonctionnement des claviers entre Windows et Mac, pertinent notamment pour les applications web utilisant le même code sur les deux plateformes. Les divergences couvrent les noms des touches, les touches de modification, l'affichage des symboles, et le comportement des raccourcis clavier.

- **Noms des touches** : Windows appelle « Backspace » ce que Mac nomme « Delete » ; Windows dit « Enter » (⏎) là où Mac dit « Return » (⏎). Mac possède une touche Option (⌥) là où Windows a Alt, et Mac utilise Command (⌘) à la place de Ctrl pour les raccourcis applicatifs.
- **Symboles vs. texte** : Apple privilégie les symboles (⇧, ⌃, ⌥, ⌘) sur ses claviers, tandis que Windows utilise des mots abrégés (Ctrl, Shift, Alt) ; les symboles ne sont pas universellement compris entre les deux écosystèmes.
- **Raccourcis et conventions** : Windows affiche les combinaisons avec un plus (Ctrl+A), Mac les colle (⌘A) ; le redo est ⌘Z sur Mac et Ctrl+Y sur Windows ; F5 ou Ctrl+R rafraîchit sur Windows, ⌘R sur Mac.
- **Accès aux caractères spéciaux** : Mac offre des combinaisons Option+touche pour obtenir des caractères alternatifs (⌥Q = œ) ; Windows propose Alt+pavénumérique pour des codes de caractères, ou AltGr sur les claviers non-US pour des caractères localisés.
- **Navigation et comportement** : PgUp/PgDn scrollent le contenu sur Windows mais ne déplacent pas le curseur sur Mac ; Tab saute tous les éléments sur Windows mais uniquement les champs interactifs sur Mac (par défaut) ; Home/End se comportent différemment selon la plateforme et le contexte (champs de texte vs. vues).

## Discussion sur Hacker News (242 commentaires)

**Avis positifs** :
- macOS Command key placement and ergonomics for common shortcuts like Cmd+C/V are superior, using the thumb instead of pinky, reducing hand strain and enabling one-handed chords
- macOS modifier key philosophy is cleaner: Command for GUI shortcuts, Control for terminal/Emacs bindings, Option for alternatives, avoiding the Ctrl key overload seen in Windows/Linux
- macOS keyboard consistency across all applications means users learn one set of shortcuts (Q to quit, W to close window) that work everywhere, unlike Windows' scattered approach
- macOS supports native readline/Emacs shortcuts (Ctrl+A/E for line navigation, Ctrl+K to kill line) system-wide through AppKit, without extra configuration needed
- macOS Option key provides intuitive diacritics input (Option+N then N = ñ) that works across any keyboard language, superior to Windows' cumbersome language switching

**Avis négatifs** :
- Windows Home/End and arrow key navigation (Ctrl+Home/End for document start/end) are more direct and discoverable than macOS requiring Cmd+Up/Down combinations
- Ctrl+C dual meaning (both copy and process interrupt) is a legitimate historical artifact problem on Unix/Linux, creating context-dependent confusion versus macOS' clean separation
- macOS modifier key positions on laptops (Fn in bottom-left) disrupt muscle memory for people switching from Windows, requiring remapping that feels unintuitive initially
- macOS Delete key (backspace) naming and keyboard layout inconsistencies with Windows cause confusion; physical key positions differ unnecessarily between platforms
- Non-English keyboard layouts on macOS (German, Portuguese, French AZERTY) have fundamentally different symbol positions than Windows equivalents, making cross-platform work extremely frustrating
