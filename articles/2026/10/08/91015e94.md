## Résumé de l'article

Docker Agent est un plugin CLI Docker permettant de créer, exécuter et partager des agents IA intelligents à partir de configurations YAML, sans code requis. Les agents peuvent collaborer pour résoudre des problèmes complexes en utilisant une riche palette d'outils.

- Architecture multi-agent : créer des équipes d'agents spécialisés qui se délèguent automatiquement les tâches
- Configuration déclarative en YAML : versionnable, partageable et exécutable via `docker agent run`
- Support multi-modèles : OpenAI, Anthropic, Gemini, AWS Bedrock, Mistral, xAI, Docker Model Runner et autres
- Écosystème d'outils riche : outils natifs + serveurs MCP (locaux, distants ou Docker), avec RAG intégré (recherche BM25, embeddings, hybrid, reranking)
- Packaging et distribution : empaqueter et pousser des agents vers tout registre OCI, les exécuter n'importe où

## Discussion sur Hacker News (124 commentaires)

**Avis positifs** :
- Docker Agent répond à un vrai besoin : orchestrer les agents IA de manière reproductible et sécurisée, notamment via les sandboxes Docker
- L'approche YAML/configuration-as-code simplifie la définition des workflows agents comparée à du code traditionnel
- Le modèle de sandbox VM offre des garanties de sécurité et de contrôle d'accès importantes pour les agents autonomes
- L'intégration native avec Docker compose et l'écosystème Docker existant facilite l'adoption pour les équipes familières avec ces outils

**Avis négatifs** :
- Docker chasse la mode IA plutôt que de rester focus : le produit semble détaché du cœur métier (conteneurisation), rappelant les portails web des années 2000 qui perdaient leur identité
- Go manque d'une bonne histoire plugins/extensions comparé à TypeScript, rendant difficile pour les développeurs d'étendre le harness avec du code personnalisé
- Le produit est fragile : les sessions cassent fréquemment, notamment avec Codex, et n'utilise pas de protocoles standardisés comme ACP, préférant parser l'état interne de manière brittle
- La proposition de valeur reste floue : nombreux autres harness (Modal, E2B, Cloudflare, etc.) font déjà cela mieux, et la documentation sur la sécurité et les attaques potentielles est manquante
- Le YAML comme interface est discutable et certains utilisateurs questionnent le 'no code required' quand les agents génèrent déjà du code, créant une abstraction supplémentaire inutile
