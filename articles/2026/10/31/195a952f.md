## Résumé de l'article

Jeetu Patel, président et directeur produit de Cisco, a confié à Padmanabhan Krishnamurthy, un ancien cofondateur de 27 ans intégré lors de l'acquisition d'EzDubs en 2025, une mission ambitieuse de refonte du code legacy de l'entreprise avec des ressources IA illimitées. Patel estime que les jeunes talents offrent une perspective novatrice que les collaborateurs expérimentés ne peuvent pas apporter, remettant en question l'approche traditionnelle qui réserverait les grands projets aux seuls profils seniors.

- Krishnamurthy dispose d'un délai de quatre semaines pour prouver sa capacité à refactoriser 98% du code legacy de Cisco en 24 mois avec une équipe réduite à deux personnes
- Patel considère la tension productive entre générations comme bénéfique pour l'innovation, en distinguant la friction sur les idées de celle sur les personnalités
- D'autres leaders technologiques (Josh Kushner, Will.i.am, Alon Chen) adoptent la même stratégie en recrutant délibérément des talents Gen Z sans expérience pour leurs perspectives natives du digital et leur absence de limitations conventionnelles
- Patel structure son équipe en trois tiers égaux : opérateurs expérimentés, penseurs systémiques externes, et fondateurs/ingénieurs natifs de l'IA en mode startup
- La tendance reflète une conviction que l'accélération de l'innovation technologique nécessite une diversité d'expériences, et que l'IA amplifie le potentiel des jeunes talents

## Discussion sur Hacker News (344 commentaires)

**Avis positifs** :
- L'IA est particulièrement efficace pour les traductions de code et les refactorisations de langage/plateforme, avec des exemples concrets de réussite (portage ColdFusion vers Java en une semaine, réécriture d'applications en 2-3 mois)
- Les modèles actuels excellents à maintenir les contrats d'API, générer des cas de test exhaustifs, documenter les comportements accumulés et identifier une meilleure structure cohésive
- Le coût-opportunité des refactorisations a radicalement changé : avec l'IA, le temps requis s'effondre, rendant viables des projets autrefois gelés en 'paralysie d'analyse' pendant des années
- L'IA dispose d'une fenêtre de contexte suffisante pour englober des bases de code entières et les comparer ligne par ligne contre les spécifications du code original
- Pour le contexte de Cisco spécifiquement, le code est documenté via des protocoles standardisés et bien spécifiés, rendant les simulations et validations fonctionnelles possibles

**Avis négatifs** :
- Risque critique : l'IA reproduira tous les bugs existants 'bug pour bug', y compris les comportements accidentels devenus des dépendances externes invisibles, sans contexte métier pour distinguer bugs des fonctionnalités (loi de Hyrum)
- Un seul ingénieur de 27 ans sans expertise éprouvée du domaine ne possède pas la connaissance institutionnelle accumulée pour identifier les décisions de conception non documentées ou les contournements justifiés par des exigences oubliées
- Les tests générés par l'IA sont moins fiables pour identifier les comportements réellement importants ; l'IA encode souvent les bugs existants comme exigences de test plutôt que de les corriger
- Cisco accumule une réputation catastrophique en sécurité (milliers de CVE, comptes cachés, mots de passe en dur) ; une refonte complète risque de propager ces failles sur une plus grande surface plutôt que de les résoudre
- Validations insuffisantes : comparer une base de code refactorisée aux tests écrits par le même IA sur le même IA crée une fausse confiance ; le vrai test arrive en production avec des années d'interactions client imprévisibles
