## Discussion sur Hacker News (123 commentaires)

**Avis positifs** :
- EDG est l'un des quatre frontends C++ majeurs (avec GCC, Clang, MSVC) et sa libération en open source bénéficiera à la communauté C++, notamment grâce à sa réputation d'excellente conformité et de compatibilité avec les dialectes de multiples compilateurs
- Le frontend possède une capacité unique d'émulation : un seul exécutable peut reproduire le comportement de différentes versions de MSVC, GCC et Clang, ce qui le rend précieux pour le portage de code et le débogage multi-compilateur
- EDG a une influence historique majeure sur l'évolution de C++ (implémentation de l'export template C++98, prototypage de la réflexion static C++26) et offre des capacités de transformation source-à-source utiles pour l'analyse statique et l'instrumentation de code
- Le code compile extrêmement rapidement (quelques secondes pour une compilation complète), est écrit de manière portable principalement en C avec une structure claire, et la publication du code historique depuis 1990 préserve une part importante de l'histoire des compilateurs C++

**Avis négatifs** :
- EDG ferme ses portes et l'open source représente une solution transitoire pour que les clients migrent vers Clang, ce qui suggère plutôt une fin de vie qu'un nouveau départ pour le frontend
- Maintenir un frontend C++ est un effort massif nécessitant une expertise rare ; sans une équipe dédiée d'une grande entreprise technologique, il est peu probable que la communauté puisse le tenir à jour avec les nouvelles normes C++26/29+
- Le code utilise un style ancien (structure C-style, pas de stdlib C++, conventions de nommage spécifiques), ce qui peut le rendre difficile à modifier pour les contributeurs modernes habitués aux pratiques récentes
- Contrairement à GCC et Clang qui bénéficient d'écosystèmes florissants, il n'y a pas de communauté clairement émergente attendant cette libération, et les clients existants semblent peu nombreux (estimés à environ 50 à la fin) et diminuant
