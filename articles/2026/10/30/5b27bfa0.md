## Résumé de l'article

L'extension Claude Code for VS Code version 2.1.313 sur Cursor Marketplace contenait une porte dérobée SSH malveillante qui s'installait de manière persistante sur macOS, Linux et Windows. Phorion a découvert que le code malveillant s'exécutait immédiatement au chargement du module, avant même l'activation de l'extension, et s'exécutait avec les permissions de l'IDE et de l'utilisateur.

- Le malware ajoute une clé SSH publique à ~/.ssh/authorized_keys et établit un tunnel SSH inverse vers un serveur attaquant (134.209.82.225) pour donner un accès interactif persistant
- Sur macOS, un bug dans la vérification de l'état SSH empêche souvent l'activation du Remote Login, bien que la clé et la persistance soient toujours installées
- Le malware crée une persistence cross-platform : LaunchAgent déguisé sur macOS (com.apple.sysmond.plist), script cron sur Linux, et tâche planifiée sur Windows
- Une boucle de reconnexion détachée relance le tunnel toutes les 60 secondes, maintenant l'accès même après fermeture de l'IDE ou redémarrage
- Le malware envoie un beacon HTTP POST au serveur listant le hostname, les variables d'environnement contenant KEY|TOKEN|SECRET|PASS|AWS|GCP, et l'adresse IP publique pour inventorier les credentials accessibles

## Discussion sur Hacker News (332 commentaires)

**Avis positifs** :
- Une attaque de supply chain majeure confirmée : un acteur malveillant a publié une version compromise (2.1.313) de l'extension Claude Code sur le marketplace Cursor avec un backdoor SSH, affectant potentiellement des millions d'installations
- Les versions officielles non affectées : Anthropic confirme que les versions sur VS Code Marketplace et OpenVSX n'ont pas été compromises, limitant l'impact aux utilisateurs de Cursor spécifiquement
- Détection possible : les utilisateurs peuvent vérifier l'impact en cherchant la clé SSH 'svc-telemetry' dans ~/.ssh/authorized_keys, permettant une identification rapide des machines compromises
- Lien potentiel avec le hack de Binance : le timing et le contexte suggèrent une corrélation possible avec le vol massif chez Binance signalé le même jour, illustrant les conséquences réelles d'une telle attaque
- Besoin criant de sécurisation : l'incident expose les failles critiques d'OpenVSX (pas de signature d'extensions, vérification minimale) et souligne l'importance d'une isolation du développement (VMs, conteneurs, sandboxes)

**Avis négatifs** :
- Attribution confuse : plusieurs versions contradictoires circulent (Anthropic hackée vs Cursor hackée vs marketplace compromise), créant une confusion persistante sur qui est vraiment responsable et où s'est produite la faille
- Réponse vague d'Anthropic : la déclaration 'A malicious actor used access to Cursor's marketplace' soulève des questions sans réponses sur comment l'accès au marketplace a pu être obtenu et pourquoi aucun détail n'est fourni
- Problèmes systémiques non résolus : VS Code et les marketplaces manquent de mécanismes de base (pas de permission-system, pas de review rigoureux, auto-update sans délai pour certains éditeurs), rendant la confiance dans ces outils intrinsèquement problématique
- Paradoxe Anthropic : l'entreprise prétend avoir résolu les problèmes de sécurité et de prompt injection avec ses modèles frontier, mais ne peut pas sécuriser sa propre distribution de logiciels, remettant en cause sa crédibilité sur les promesses de sécurité
- Risques structurels non adressés : même en isolation (VM, container), les développeurs partagent souvent secrets et clés SSH, et les registres de paquets sont régulièrement compromis, suggérant que la sécurité réelle du développement logiciel reste une question sans solution pratique
