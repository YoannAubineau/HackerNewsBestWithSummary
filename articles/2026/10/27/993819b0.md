## Résumé de l'article

Ghostty est un émulateur de terminal moderne multiplateforme. La version 1.4.0, sortie le 27 octobre 2026, introduit des gains de performance significatifs, une implémentation à 100 % du protocole graphique Kitty (incluant animation et positionnement relatif), et des améliorations d'intérogation SSH, avec contributions de 172 contributeurs sur 2 889 commits.

- **Performance et mémoire** : I/O 25–55 % plus rapide sur macOS, traitement VT 6× plus rapide pour le texte ASCII, compression de l'historique réduisant l'usage mémoire de 70–90 %, valeur par défaut d'historique augmentée de 10 MB à 50 MB
- **Graphiques Kitty** : Support complet de l'animation, positionnement relatif, transferts d'image 16× plus rapides avec SIMD, conformité à 100 % de la spécification
- **Intégration SSH** : Nouvelle commande `ghostty +ssh` installant terminfo distant et intégrant shell, cache par hôte, comportement unifié sur tous les shells
- **Sécurité** : 10 correctifs de vulnérabilités incluant protections contre les commandes graphiques malveillantes, l'exécution de code arbitraire via hyperliens, et corruption mémoire
- **Compatibilité macOS 27** : Support du nouveau système, corrections d'apparence (onglets, barre de titre, icône)

## Discussion sur Hacker News (198 commentaires)

**Avis positifs** :
- libghostty s'impose comme une fondation technologique majeure : intégration dans les IDEs JetBrains (12,5M utilisateurs), Neovim, Emacs (Ghostel), et portage sur iOS, Android, WebAssembly et matériel nu.
- Performance supérieure confirmée : GPU accéléré, rendu fluide même avec les agents d'IA, réactivité nettement meilleure que les terminaux classiques (Konsole, Terminal.app).
- Configuration texte simple et versionnables dans les dotfiles, sans GUI à gérer ; accès immédiat aux polices Nerd intégrées et aux paramètres par défaut sensés.
- Expérience cross-platform native : même terminal sur macOS et Linux sans traitement de second ordre ; alternatives viables aux iTerm2 obsolète et à Terminal.app très limité.
- Écosystème en expansion : support croissant des protocoles modernes (Kitty graphics, OSC8, Symbols for Legacy Computing), muliplexage, intégration SSH native.

**Avis négatifs** :
- Configuration 'zéro config' trompeuse : fichier de configuration vide par défaut, impossible de connaître les noms des clés sans documentation web externe ; contrairement à iTerm2, pas de GUI ou de fichier de défaut généré pour la découverte.
- Fragmenté et instable selon certains utilisateurs : 'quirks' de rendu (autocomplete mal positionné, raccourcis clavier globaux dysfonctionnels), problèmes SSH avec terminfo custom non reconnu à distance.
- Zig comme dépendance de compilation fragile : compilateur qui change rapidement, recommandation explicite contre la compilation manuelle ; dépendance externe moins stable que C pur.
- Consommation mémoire élevée dans certains cas (jusqu'à 2GB rapporté), dépassant alternatives comme iTerm2 ; malgré les réductions annoncées, reste un problème résiduel.
- Fonctionnalités manquantes vs alternatives : pas de 'Hints mode' comme Kitty, session restoration sans contenu terminal (seulement répertoire), restauration d'état global imparfaite entre redémarrages.
