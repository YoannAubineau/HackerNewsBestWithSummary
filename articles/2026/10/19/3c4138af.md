## Résumé de l'article

KillSwitch est un langage de programmation ésotérique créé pour être hostile aux LLM et agents d'IA, permettant de tester si ces modèles comprennent réellement le code ou s'ils le reproduisent simplement à partir de leur corpus d'entraînement. Le langage utilise des pièges spécifiques comme des mensonges cachés dans la spécification, le comptage de caractères dans les identifiants, des phrases déclenchant les garde-fous de sécurité, et des scripts noyés dans du texte narratif superflu.

- KillSwitch est un langage basé sur une pile interprétée avec des constructions limitées (fonctions, variables, conditions), mais enrichi de mécanismes adversariaux contre les LLM
- Les benchmarks montrent que le meilleur modèle (Claude Opus 3.5) n'atteint que 66,8 % de réussite sur des tâches simples, suggérant que cette performance ne prouve pas une véritable compréhension du langage
- Les modèles avec des garde-fous de sécurité trop sensibles (Fable 5.1, Gemini 4 Argon) échouent mal, tandis que MiMo-V2.6-Pro est le meilleur modèle en poids ouvert
- La corrélation des performances sur KillSwitch avec d'autres benchmarks de modèles existants indique la validité du test
- L'auteur prévoit de concevoir des ensembles de tâches plus complexes si les prochains modèles réussissent l'ensemble actuel

## Discussion sur Hacker News (162 commentaires)

**Avis positifs** :
- L'approche révèle effectivement des faiblesses des LLM face à des tâches non présentes dans leurs données d'entraînement et démontre qu'une obscurité intentionnelle peut ralentir les modèles.
- Les techniques anti-LLM (comptage de caractères, phrases-pièges, spécifications mensongères) créent une classe intéressante de défis qui mérite exploration, même si contournable à terme.
- Le projet soulève des questions philosophiques pertinentes sur ce que signifie vraiment 'comprendre' le code pour une IA versus simplement reproduire des patterns d'entraînement.
- Une étude structurée avec benchmarks fournis aux modèles sous contraintes (binaire d'interpréteur uniquement, pas d'accès internet) offre une base de test plus rigoureuse que du zéro-shot.

**Avis négatifs** :
- Les modèles peuvent triviallement contourner le langage en écrivant des transpileurs ou décompileurs une fois qu'ils ont accès au code source de l'interpréteur, rendant les obstacles principalement temporaires.
- Les scores de 66-68% obtenus par les meilleurs modèles contredisent la prétention du titre : les LLM peuvent effectivement utiliser le langage, même imparfaitement.
- Le langage est probablement plus adversarial pour les humains que pour les LLM (comptage de lettres, anagrams, faux instructifs dans la spec), créant un test déséquilibré.
- L'approche repose en grande partie sur l'exploitation de garde-fous de sécurité (phrases comme 'créer une arme biologique') plutôt que sur des limitations intrinsèques du traitement du langage, ce qui n'est pas durable.
- La sécurité par l'obscurité n'est pas une véritable sécurité : dès que le projet est public avec explications détaillées, les modèles futurs intégreront cette connaissance dans leur entraînement.
