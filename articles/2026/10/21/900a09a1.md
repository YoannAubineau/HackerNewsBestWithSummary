## Résumé de l'article

DuckDB 2.0.0 LTS est une version long terme (supportée jusqu'octobre 2027) qui introduit plus de 19 000 commits de nouvelles fonctionnalités majeures. DuckDB est une base de données relationnelle en processus destinée à l'analyse de données et aux requêtes OLAP.

- Le protocole Quack reçoit une version stabilisée permettant un mode client-serveur traditionnel avec une nouvelle instruction CONNECT pour basculer entre bases de données distantes
- L'I/O asynchrone pour Parquet, CSV et le format natif améliore massivement les performances sur objets distants (s3://) en parallélisant les lectures
- Le type VARIANT stocke des données semi-structurées sans schéma (JSON) avec performances colonnaires en détectant et comprimant les structures communes
- Le parseur SQL bascule d'un modèle dérivé de PostgreSQL à un parseur PEG moderne permettant aux extensions de modifier la grammaire SQL elle-même
- Les triggers (CREATE TRIGGER) supportent les opérations BEFORE/AFTER avec tables de transition pour cas d'audit et peuvent maintenir des vues matérialisées de façon incrémentale

## Discussion sur Hacker News (41 commentaires)

**Avis positifs** :
- Performances significativement améliorées sur machines multi-cœurs : le parallélisme s'étend jusqu'à 192vCPU (contre 64 auparavant), permettant des workloads massifs (1 milliard d'enregistrements traités en 10 minutes avec Splink)
- Architecture client-server légère et flexible : peut être déployée comme service HTTP avec load balancing et scaling à zéro, sans infrastructure lourde
- Polyvalence d'usage : ingestion/reshaping de données, requêtes ad-hoc sur archives cloud, compression de données (7TB en 2.5% en parquet), federation de sources hétérogènes, intégration dans navigateurs via duckdb-wasm
- I/O asynchrone pour Parquet et CSV améliore significativement les performances sur accès réseau (S3, HTTP) et utilisation de la bande passante
- Triggers et architecture client-server positionnent DuckDB comme véritable data warehouse autonome, remplaçant potentiellement des stacks complexes basées sur Spark ou infrastructure centralisée

**Avis négatifs** :
- Performance sub-linéaire au-delà d'un certain nombre de cœurs : l'overhead de parallélisation peut ralentir les workloads malgré une utilisation CPU à 100%, particulièrement sur instances AWS avec CPU Steal et contention
- Format natif DuckDB ne supporte pas encore l'I/O asynchrone (uniquement Parquet/CSV) ; roadmap incertaine pour les extensions tierces
- Pas de support SQL pour KQL, limitant l'adoption par certains utilisateurs habitués à cet écosystème
- Utilité réelle difficile à identifier pour certaines organisations : manque de cas d'usage évidents par rapport aux solutions établies
- Contraintes d'utilisation : modèle single-writer en mode transactionnel; support client limité pour le protocole Quack natif malgré amélioration en 2.0
