## Résumé de l'article

PingCAP Inc., fournisseur de TiDB Cloud (version managée de la base de données distribuée open-source TiDB), a subi une fuite de données massive affectant ses clients (banques, studios de jeux, plateformes e-commerce). Environ 10,6 TB de données ont été exfiltrés, incluant le plan de contrôle cloud, les données de facturation, les logs de connexion de quatre ans, le code source, et les données de services AWS, GCP et Azure.

- L'accès aux données s'est poursuivi pendant près de deux mois (8 septembre au 30 septembre 2026) sans détection, avec 88 exports consécutifs de la base de données du plan de contrôle toutes les six heures contenant les identifiants de clients, clés API et credentials des clusters.
- Les clients exposés incluent des entreprises majeures : Mercari, PayPay, Fujitsu, Square Enix, Konami, Airbnb, Pinterest, Databricks, Baidu, LINE et autres, avec leurs identifiants VPC, versions de cluster et hostnames.
- Les engineers de PingCAP ont régulièrement stocké les credentials de production des clients dans les tickets Jira, exposant des clés AWS, tokens GitHub, clés API et chaînes de connexion MySQL en clair depuis 2023.
- Un problème de sécurité documenté par l'équipe sécurité de PingCAP en 2022 (SECURITY-22) montrait que tout membre d'une organisation client pouvait réinitialiser le mot de passe root de tous les clusters sans restriction, donnant accès administrateur complet.

## Discussion sur Hacker News (62 commentaires)

**Avis positifs** :
- La fuite est massive et sans précédent : accès complet au plan de contrôle TiDB Cloud, aux données de facturation, aux clés API, aux identifiants des clients et à 4 ans de logs de connexions
- L'incompétence opérationnelle est flagrante : credentials stockées dans les dépôts Git, une pipeline de réplication malveillante active 22 jours sans détection, credentials en clair dans les tickets Jira
- Le rapport de sécurité de NCC Group s'avère insuffisant : une audit source-code ne suffit pas si les opérations sont compromises, illustration du fossé entre certifications de sécurité et réalité
- La réponse officielle de PingCap minimise l'incident : affirmation qu'aucune donnée n'a été impactée malgré l'existence de tarballs complets, ce qui semble malhonnête
- Le problème révèle des failles systémiques plus larges : industrie du pentest surfiée par l'automatisation, complexité logicielle incontrôlable, culture de sécurité défaillante même chez les éditeurs de bases de données

**Avis négatifs** :
- Les données client réelles sont ambiguës : la majorité du leaked concerne des métadonnées (10.6TB est raisonnable pour une grande entreprise de bases de données), pas nécessairement les données utilisateur stockées dans TiDB
- L'efficacité réelle des audits externes est débattue : certains commentaires nuancent que les audits source-code et conformité n'ont jamais prétendu couvrir toute la sécurité opérationnelle, le problème était attendu
- Les solutions proposées (davantage d'IA, simplification) restent spéculatives et peu convaincantes : il n'est pas clair qu'ajouter de l'IA pour défendre contre l'IA soit viable, la simplification est un idéal rarement applicable
- La complaisance des auditeurs (Big Four) n'est pas spécifique à PingCap : ce sont des problèmes systiques de l'industrie du conseil depuis 15+ ans, pas une particularité de ce cas
