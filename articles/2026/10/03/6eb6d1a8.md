## Résumé de l'article

Muse est un appareil ou une plateforme permettant d'automatiser les appareils connectés d'un foyer. En le connectant au Wi-Fi de votre domicile, il peut interagir avec les dispositifs déjà présents ou intégrés via une API HTTP locale.

- Muse communique avec les appareils compatibles du réseau domestique et accepte les intégrations personnalisées via API HTTP
- Des compétences développées par la communauté étendent ses capacités (allumer des lumières, contrôler un téléviseur, envoyer des documents à une imprimante, etc.)
- Les fonctionnalités précises dépendent de la configuration matérielle et logicielle de chaque utilisateur

## Discussion sur Hacker News (104 commentaires)

**Avis positifs** :
- Plateforme accessible pour les débutants en microcontrôleurs et IoT, inspirante et motivante pour apprendre l'électronique embarquée
- Approche audacieuse et pragmatique de Meta pour construire un écosystème matériel autour de ses agents IA, contrairement à ses concurrents qui restent sur le modèle API
- Code open source et SDK permettant une certaine flexibilité, avec possibilité théorique de pointer vers ses propres serveurs locaux
- Idée amusante et engageante pour les bricoleurs amateurs, rappelant l'époque des débuts des assistants vocaux avec plus de capacités IA
- Potentiel d'intégration matérielle créative pour des cas d'usage domestiques simples (affichage de rappels, contrôle de lumières)

**Avis négatifs** :
- Modèle de propriété illusoire : tokens requis, limite de 50 appareils, impossibilité de reflasher le firmware, service peut s'arrêter sans préavis, dépendance d'abonnement — plus proche d'une location que d'une véritable possession
- Grave préoccupation de confidentialité : historique d'incidents où Muse a révélé des adresses personnelles, risques significatifs avec une IA incontrôlée ayant accès à domiciles intelligents et données réseau
- Mascarade de transparence : présenté comme 'fait par des hackers pour des hackers' dans un dépôt Meta, en réalité c'est un client open source pour un service propriétaire fermé de Meta
- Stratégie typique d'enshittification : Meta accumule les données des utilisateurs et bricoleurs via cette initiative, puis fermera progressivement le système une fois la part de marché établie
- Confiance envers Meta systématiquement remise en question : antécédents de désinformation, surveillance massive, pratiques éthiques douteuses rendent tout produit Meta inacceptable pour un nombre significatif d'utilisateurs
