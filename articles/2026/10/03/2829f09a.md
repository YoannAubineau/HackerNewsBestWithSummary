## Résumé de l'article

Supabase a annoncé l'acquisition de Turso, une plateforme de base de données cloud construite sur SQLite. Turso est une plateforme qui permet de gérer des millions de bases de données légères sur un seul serveur en les chargeant à la demande, tandis que Supabase se concentre historiquement sur PostgreSQL.

- Les deux plateformes conserveront leurs technologies respectives (SQLite pour Turso, PostgreSQL pour Supabase) et continueront à servir leurs utilisateurs existants sans changement
- L'acquisition vise à créer une infrastructure unifiée adaptée aux agents IA, qui créent des millions de bases de données pour des prototypes, explorations et applications légères
- Turso a conçu une architecture permettant de provisionner une base de données à la demande avec un coût minimal, idéale pour les petites charges de travail des agents, tandis que PostgreSQL restera la solution pour les applications en production à grande échelle
- Supabase lance déjà plus d'un million de bases de données par semaine et anticipe une explosion de la demande avec la multiplication des agents IA
- Les fondateurs de Turso, Glauber Costa et Pekka Enberg, rejoignent Supabase pour diriger cet effort d'infrastructure pour agents IA

## Discussion sur Hacker News (113 commentaires)

**Avis positifs** :
- L'acquisition renforce la confiance dans Turso pour les utilisateurs inquiets de la viabilité d'un projet trop dépendant d'une seule entreprise ; elle ouvre aussi des perspectives intéressantes pour un écosystème Supabase/SQLite/Postgres adapté à chaque étape de croissance.
- Turso/SQLite comble un besoin réel pour les petits workloads, les agents IA et les environnements éphémères où Postgres serait surdimensionné ; c'est une meilleure expérience développeur pour le prototypage et le déploiement léger.
- L'équipe Turso a démontré une croissance solide (5x de revenus cette année) et du talent technique reconnu ; Supabase apporte des ressources pour accélérer le développement et améliorer les performances.
- Turso reste open source (MIT), conserve son autonomie et sa mission SQLite-first au sein de Supabase, qui offre un chemin clair de progression (SQLite → Turso managé → Postgres managé) pour les utilisateurs.
- Le projet bénéficie d'une communauté open source dynamique avec des contributeurs externes ; l'acquisition permet d'améliorer les outils, les benchmarks et les cas d'usage sans compromettre l'accès au code.

**Avis négatifs** :
- Les acquisitions technologiques échouent souvent, les entreprises mères tuant les produits acquis après les avoir promis de les maintenir ; l'histoire montre des exemples répétés de technologies abandonnées post-acquisition.
- Turso a connu des problèmes de performance et de stabilité documentés (très lent sur ClickBench, problèmes d'ingestion de données, latence élevée dans certaines régions) qui soulèvent des questions sur la qualité de l'exécution et la pertinence de cette acquisition.
- Réécrire SQLite, l'un des logiciels les mieux testés et les plus stables du monde, relève du doute technique ; certains arguent qu'il faut laisser les projets proven seuls plutôt que de les réinventer.
- L'acquisition crée une ambiguïté stratégique : Supabase est fundamentalement une plateforme Postgres hébergée ; intégrer Turso/SQLite risque de diluer la mission ou de transformer Turso en simple complément plutôt qu'en produit autonome.
- Pour les utilisateurs auto-hébergés ou critiques de la consolidation VC, cette acquisition diminue la attractivité de Turso comme alternative indépendante, même si l'open source persiste : on perd une option sans dépendance d'entreprise.
