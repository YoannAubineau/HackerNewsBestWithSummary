## Résumé de l'article

Llmspeed est un outil qui fournit des estimations de performance pour exécuter des modèles de langage locaux sur différents appareils. Il agrège des benchmarks communautaires provenant de sources comme r/LocalLLaMA et localscore.ai, complétés par des projections basées sur des configurations similaires ou des spécifications matérielles.

- Permet de tester virtuellement la vitesse d'exécution d'un modèle sur un appareil avant d'investir
- Combine des données mesurées de benchmarks communautaires avec des estimations dérivées de configurations comparables
- Code source disponible en open source sur GitHub

## Discussion sur Hacker News (68 commentaires)

**Avis positifs** :
- L'outil répond à un vrai besoin : permettre d'évaluer avant d'acheter du matériel coûteux (10k+$) sans télécharger tous les modèles sur Hugging Face
- Les utilisateurs apprécient la capacité à comparer différentes quantifications et configurations pour comprendre les trade-offs réels (ex: Q8 vs Q4)
- Le concept est utile pour démystifier les performances réelles : les MOE models surpassent souvent les attentes théoriques, les anciennes GPUs (RX580, GTX1070) fonctionnent mieux que prévu
- L'ajout de nouveaux modèles comme Qwen 3.8 Flash et benchmarks multi-GPU est apprécié et en cours de développement

**Avis négatifs** :
- Les estimations de vitesse sont significativement inexactes : utilisateurs rapportent des écarts importants (80 tk/s réel vs 20-30 simulés pour Qwen 27B Q4 sur 4090), avec variations selon les versions de drivers et harness
- Manquent des configurations populaires : dual-GPU (2x4090), Nvidia Spark, Snapdragon X Elite, GPU Intel Arc, et les setups hybrides CPU+GPU
- Ne capture pas les cas réels : contextes larges (60-140k tokens) utilisés en production, parallélisation du prefill, cache KV management, et l'impact des harnesses sur les performances réelles
- Les calculs de mémoire semblent inexacts pour KV cache et certains modèles (Gemma vs Qwen), et le message d'erreur contradictoire (dit qu'aucune quantization ne marche, mais Q8_0 marche)
- Omet les facteurs importants : qualité des modèles, speculative decoding, context windows variés, et ce qui importe vraiment (prefill parallelization vs output speed pour les agents)
