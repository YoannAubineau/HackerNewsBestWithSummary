## Résumé de l'article

Le rendu logiciel est une technique où le processeur dessine chaque pixel directement, sans recourir à une carte graphique — c'est le mode utilisé par les jeux DOS classiques comme Quake, Doom et Blood. L'auteur défend cette approche esthétique pour ces jeux rétro, malgré la possibilité de les jouer en mode accéléré 3D avec une carte graphique.

- Le rendu logiciel offre une image plus nette (textures pixel-parfait) et plus granuleuse (limitation des 256 couleurs créant du lissage de couleurs visible) que le rendu accéléré des années 1990, qui lissait les textures de manière floue.
- Ces jeux ont été conçus autour de leurs rendus logiciels : Quake et Doom ont d'abord été sortis en logiciel, donnant au rendu logiciel un avantage artistique pour certains titres.
- Le rendu logiciel nécessite une CPU très rapide, car chaque pixel supplémentaire demande du calcul processeur ; les résolutions VESA élevées (1600×1200) demandent même aux processeurs modernes (Xeon quad-core à 3,3 GHz) une performance proche de la limite.
- L'auteur privilégie les versions DOS originales sur matériel réel plutôt que les ports logiciels modernes ou DOSBox, pour conserver l'expérience d'origine et la compatibilité exacte.

## Discussion sur Hacker News (176 commentaires)

**Avis positifs** :
- Software rendering offre un débogage simplifié : pas de quirks de drivers, pas de compilations de shaders bizarres, les erreurs proviennent clairement du code mathématique.
- L'esthétique des jeux software-rendus (textures pixelisées nettes, couleurs riches sans lissage) a un attrait nostalgique et artistique reconnu, même 30 ans après.
- Comparé aux GPU, les software renderers sont plus prévisibles et portables : fonctionne sur diverses architectures sans problèmes de compatibilité matérielle.
- Les renderers CPU modernes (LLVMpipe, OpenSWR) restent pertinents pour les cas sans GPU et certains contexts (systèmes embarqués, expériences distribuées).
- Le software rendering permet une compréhension pédagogique profonde du pipeline 3D et des optimisations, comme l'illustre l'héritage du Graphics Programming Black Book.

**Avis négatifs** :
- L'esthétique appréciée (textures nettes, pas d'anti-aliasing) n'est pas inhérente au software rendering mais au choix de configuration ; elle est totalement réalisable sur GPU moderne.
- Les performances CPU sont largement insuffisantes comparées au GPU pour la 3D temps-réel ; même des Xeon modernes multi-cœurs ne surpassent pas une carte graphique.
- Les avantages debuggabilité et contrôle ne justifient pas d'abandonner l'efficacité énergétique massive et la puissance du GPU pour les jeux modernes.
- Attribuer l'apparence rétro au software rendering confond le médium avec les contraintes technologiques de l'époque ; c'est surtout un choix d'art et de configuration.
- L'affirmation que le rendu CPU serait impossible aujourd'hui est exagérée : certes les OS utilisent le GPU, mais les renderers CPU purs restent possibles, juste inefficaces.
