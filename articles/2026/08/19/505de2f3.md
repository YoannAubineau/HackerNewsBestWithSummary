## Discussion sur Hacker News (241 commentaires)

**Avis positifs** :
- L'augmentation massive du trafic (14x de commits en un an) due aux outils d'IA generative est un défi d'infrastructure légitime et sans précédent à cette échelle
- GitHub Actions et les webhooks, features n'existant pas avant l'acquisition Microsoft, constituent une part importante des pannes et complexifient significativement l'architecture
- Les ingénieurs de GitHub sont exceptionnels et ont réalisé des améliorations constantes d'infrastructure documentées publiquement; une croissance 14x n'aurait pas pu être gérée sans leur travail préalable
- La migration vers Azure parallèlement à la surcharge de trafic est un défi opérationnel majeur sans précédent, exécuté sous pression extrême
- Avant l'acquisition Microsoft, GitHub était stable mais stagnant en termes de fonctionnalités; l'expansion massive du produit était impossible sans Microsoft

**Avis négatifs** :
- Les problèmes de stabilité ont commencé bien avant le boom de l'IA (dès 2020), suggérant une cause plus profonde qu'une simple surcharge de trafic
- Microsoft, ayant investi massivement dans l'IA, aurait dû anticiper cette explosion d'activité; l'absence de préparation infra est un manquement à la planification stratégique
- Ruby on Rails n'est pas le problème, mais la gestion chaotique du produit l'est : ajouter des features (Actions, Copilot, etc.) en sacrifiant la fiabilité du cœur montre des priorités mal alignées
- Azure lui-même semble problématique : ses pages de statut ne reflètent pas les incidents en temps réel, et la migration vers Azure coïncide avec la dégradation massive de la stabilité
- GitHub devrait implémenter des limitations (par utilisateur, par repo, tarification progressive) pour contrôler la charge plutôt que de laisser les serveurs s'effondrer sous du code généré d'IA massif et peu valorisé commercialement
