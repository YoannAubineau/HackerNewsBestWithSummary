## Résumé de l'article

Un chercheur en sécurité a démontré une chaîne d'attaque par injection de prompt ciblée contre Claude Code Opus 5 en Auto Mode (le mode approuvé par défaut depuis août qui remplace les validations humaines par un classificateur de sécurité). L'attaque combine plusieurs étapes — redirection de curl, archive ZIP encodée, refus intentionnel d'exécuter un binaire malveillant, puis exécution d'un code Python écrit par Claude lui-même qui utilise l'ombrage de modules Python pour obtenir une exécution de code arbitraire avec callback C2 — et atteint un taux de succès de 60 à 80 % sur de petits échantillons, contredisant l'évaluation de 0,00 % de succès d'attaque par injection commanditée par Anthropic.

- Anthropic avait publié un benchmark montrant 0,00 % de réussite d'attaque par injection indirecte sur 72 scénarios testés dix fois chaque, mais cette chaîne d'attaque spécifique n'était pas incluse dans le benchmark
- L'attaque exploite le fait que Claude refuse d'exécuter un binaire suspect mais écrit son propre décodeur Python, qui s'exécute dans le répertoire contrôlé par l'attaquant où se trouve un struct.py malveillant qui intercepte les imports de bibliothèques standard
- Auto Mode a parfois bloqué les commandes de nettoyage tentées par Claude pour arrêter les processus malveillants détectés, transformant le mécanisme de sécurité lui-même en point d'échec
- Anthropic a classé le rapport comme informatif, déclarant que Auto Mode est une fonctionnalité de commodité avec un classificateur « best-effort » (meilleur effort) et non une garantie de sécurité, la vraie limite de sécurité résidant dans l'isolation du système d'exploitation
- Le chercheur recommande de ne pas considérer Auto Mode comme une limite de sécurité et d'exécuter les agents d'IA en sandbox avec restriction d'accès réseau et surveillance, car les messages marketing sur la résolution du problème d'injection de prompt sont trompeurs

## Discussion sur Hacker News (69 commentaires)

**Avis positifs** :
- L'attaque révèle une vulnérabilité réelle : le mode auto crée une fausse sécurité qui dissuade les utilisateurs de sandbox leurs agents, rendant les trojans spécifiquement conçus pour Claude beaucoup plus efficaces
- Le problème démontre comment les comportements prévisibles du modèle (habitudes d'utiliser certains outils comme `python -c`) peuvent être exploités de manière ciblée pour contourner les défenses
- C'est une vulnérabilité pratique et pertinente : même quand Claude détecte le compromis, le mode auto peut bloquer la tentative de nettoyage, aggravant l'exploitation
- L'attaque soulève des questions légitimes sur les responsabilités légales d'Anthropic concernant le marketing trompeur du mode auto et les dommages potentiels

**Avis négatifs** :
- Ce n'est pas vraiment une injection de prompt ou un problème spécifique au mode auto : l'attaque fonctionne aussi bien en mode manuel et exploite principalement une mauvaise conception de Python (shadowing des modules stdlib), pas une faille d'IA
- L'attaque est essentiellement un trojan standard ciblant Claude, comparable à une attaque par fichier malveillant donné à un humain - le problème fondamental est la manque de sandbox, pas l'automatisation
- Les chercheurs en sécurité d'Anthropic prétendant réduire les injections de prompt indirectes à quasi-zéro sont contredits par les taux de succès de 80%, mais cette critique repose davantage sur un scepticisme envers les affirmations que sur le problème lui-même
- Des solutions pratiques existent déjà (utiliser `python -I` ou `-Pc`, committer les lockfiles et revoir les diffs, éviter de mélanger les changements du modèle et humains), suggérant que le problème est surtout un manque de discipline de développement
