## Résumé de l'article

GitHub Actions subit une panne affectant les workflows et les runners. Les déclencheurs par webhook sont limités à 15% de leur capacité normale, ce qui empêche la plupart des événements (push, pull requests) de lancer des exécutions.

- Environ 65% des jobs en attente réussissent actuellement, en amélioration depuis 30-40% au début de l'incident
- Les runners GitHub-hosted et self-hosted sont bloqués en tentant de relancer des jobs qui ne sont plus disponibles
- Copilot code review, Copilot coding agent et les migrations via GitHub Enterprise Importer sont également affectés

## Discussion sur Hacker News (252 commentaires)

**Avis positifs** :
- Les défaillances répétées de GitHub Actions sont bien documentées et systémiques, confirmant un problème structurel grave affectant même les clients payants et les runners auto-hébergés
- La migration vers Azure de Microsoft est directement corrélée à la dégradation de la fiabilité, particulièrement observable depuis 2024-2025 avec des pics d'incidents
- L'augmentation exponentielle de la charge (14 milliards de commits projetés pour 2025, 2,1 milliards de minutes Actions par semaine) dépasse clairement la capacité d'infrastructure actuelle
- Les alternatives auto-hébergées (Forgejo, Gitea, GitLab self-hosted, Woodpecker) offrent une fiabilité supérieure avec des coûts maîtrisables pour les organisations de taille moyenne

**Avis négatifs** :
- GitHub Actions reste compétitif malgré les pannes car les alternatives (CircleCI, GitLab Cloud, Codeberg) présentent des compromis significatifs en fonctionnalités ou en maturité, notamment pour les runners Windows
- Le coût de migration totale vers une solution alternative (conception, migration d'workflows, formation, maintenance) peut dépasser celui toléré par une indisponibilité occasionnelle pour de nombreuses entreprises
- Les pannes peuvent aussi résulter de charges imprévisibles liées aux agents IA, pas uniquement de défauts d'ingénierie Microsoft; cette charge était difficilement prévisible il y a quelques années
- Même l'auto-hébergement présente des risques opérationnels non triviaux (maintenance, expertise en interne, continuité de service) que les organisations avec peu de ressources DevOps ne peuvent gérer facilement
- La corrélation entre AI et dégradation n'est pas établie avec certitude : l'architecture Azure et les choix architecturaux peuvent suffire à expliquer les problèmes indépendamment de la charge AI
