## Résumé de l'article

Celld est un daemon open-source édité par Deno Land qui permet d'exécuter Cloudflare Workers et Durable Objects sur vos propres machines. Chaque objet fonctionne comme sa propre base de données SQLite répliquée vers un bucket S3-compatible ; les nœuds se coordonnent uniquement via ce bucket sans contrôle centralisé ni consensus.

- L'architecture élimine les points de contention et les défaillances en cascade : chaque application est automatiquement fragmentée par construction, chaque objet étant une petite base de données indépendante
- Les nœuds exécutent des bundles Wrangler avec V8 intégré ; un seul nœud possède une cellule à la fois, garanti par des opérations compare-and-swap sur le stockage objet, sans protocole d'adhésion ni service de consensus
- L'installation se fait via un script unique ; celld s'exécute en ligne de commande ou en conteneur Docker, en s'appuyant sur les credentials AWS standard
- Les cellules inactives hiberner à zéro coût ; le déploiement s'effectue via `celld deploy` suivi du lancement d'une flotte de nœuds sur un bucket partagé
- La sécurité requiert des réseaux privés de confiance (WireGuard, Tailscale) pour la communication inter-nœuds ; les contributions se font par patch formaté git, sans pull requests ouvertes

## Discussion sur Hacker News (48 commentaires)

**Avis positifs** :
- Celld offre une alternative open-source viable aux Durable Objects de Cloudflare, permettant l'auto-hébergement sans dépendre d'un seul fournisseur cloud
- L'architecture est élégante : utiliser S3 comme couche de coordination élimine le besoin d'un plan de contrôle complexe (etcd, zookeeper), ce qui la rend opérationnellement simple à déployer
- Le concept des Durable Objects (chaque objet comme sa propre base de données SQLite distribuée) s'avère être une abstraction de valeur éprouvée pour les applications avec état partagé et concurrence élevée
- L'utilisation des isolates V8 au lieu des VMs offre un coût d'inactivité très faible et permet le déploiement sur infrastructure partagée sans complexité de virtualisation imbriquée
- Pour de nombreux cas d'usage, Celld représente une solution suffisante et moins coûteuse que les services cloud propriétaires à grande échelle

**Avis négatifs** :
- Celld n'égale pas la portée mondiale et la réplication géographique instantanée de Cloudflare, limitant son applicabilité pour les applications nécessitant une véritable distribution planétaire
- La fiabilité dépend entièrement de la cohérence et de la correction de la couche S3 sous-jacente : risque important si on utilise des implémentations S3 compatibles sans garanties de cohérence forte
- Le déploiement multi-régional sur Kubernetes ou bare metal remains coûteux et complexe comparé au pricing à la demande de services comme Cloudflare Durable Objects pour les petites échelles d'usage
- Manque de benchmarks de performance comparant directement Celld aux Durable Objects de Cloudflare, rendant difficile l'évaluation objective des compromis
- La politique de contributions via email et le refus des pull requests soulève des questions sur la maintenabilité et l'ouverture réelle du projet pour les contributeurs externes
