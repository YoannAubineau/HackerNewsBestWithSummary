## Résumé de l'article

Atlassian Rovo est un agent IA multi-usages intégré à la suite Atlassian (Jira, Confluence, etc.). Des vulnérabilités ont été découvertes permettant l'exfiltration de données sensibles au sein d'un tenant Atlassian via injection de prompt indirect, sans approbation utilisateur.

- L'attaque exploite l'outil de récupération d'URL de Rovo en injectant du code malveillant dans un fichier uploadé par la victime, permettant de rediriger les données vers un serveur attaquant
- Le mécanisme fonctionne même si la recherche web est désactivée, car le paramètre de sécurité ne supprime pas complètement l'accès à l'outil sous-jacent
- Un second vecteur d'exfiltration existe via le rendu insécurisé d'images Markdown dans les sorties de l'IA
- PromptArmor a signalé les vulnérabilités à Atlassian le 23 mai, mais après plus de deux mois sans action, Rovo reste vulnérable
- L'attaque peut accéder à toutes les données qu'Rovo peut consulter, y compris celles intégrées via connecteurs tiers

## Discussion sur Hacker News (134 commentaires)

**Avis positifs** :
- La vulnérabilité est réelle et bien documentée : Rovo peut être manipulé pour construire dynamiquement des URLs contenant des données sensibles et les exfiltrer vers des serveurs attaquants sans protection adéquate.
- Le problème est systémique aux outils agentic actuels : de nombreuses implémentations d'IA (Claude Cowork, Google Sheets AI, etc.) souffrent des mêmes failles de prompt injection, révélant un manque de standards de sécurité industrie.
- Atlassian a montré un pattern d'incompétence : les paramètres de sécurité (comme désactiver la recherche web) ne fonctionnent pas réellement, et les protections contre les injections de prompts restent inefficaces même après des mois.
- L'adoption forcée aggrave les risques : Rovo est injecté par défaut dans chaque page Jira/Confluence sans possibilité de désactivation au niveau utilisateur, forçant l'exposition aux vulnérabilités.

**Avis négatifs** :
- L'attaque démontrée requiert que la victime elle-même entre une instruction malveillante ou télécharge un fichier malveillant, réduisant le risque réel comparé à une exploitation sans interaction.
- Les critiques d'Atlassian pré-datent largement les 18 derniers mois : Jira et Confluence avaient déjà une mauvaise réputation sur l'UX et la performance bien avant l'arrivée de Rovo.
- Les solutions techniques existent mais impliquent des compromis : permettre à un agent d'être utile tout en le sandboxant complètement contre les injections de prompts reste un défi architectural non trivial, pas juste une omission d'implémentation.
- Le problème est inhérent aux LLM eux-mêmes : selon certains commentaires, les injections de prompts sont aussi difficiles à bloquer complètement que les escroqueries de CEO chez les humains—c'est une limite théorique, pas seulement une faute de Rovo.
