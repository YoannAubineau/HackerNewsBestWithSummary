## Résumé de l'article

Claude Code est un outil de codage alimenté par l'IA qui facture à l'utilisation en fonction du nombre de jetons traités. L'article explique comment réduire les coûts en gérant efficacement le contexte et le cache d'invite.

- Les jetons d'entrée et de sortie ont des prix différents (sortie ~5x plus cher), et les modèles plus grands coûtent davantage ; la mise en cache des invites à 0,1x le prix de l'entrée permet d'économiser considérablement sur les tours ultérieurs
- La mise en cache se brise si le modèle, le niveau d'effort, ou le fichier CLAUDE.md change, forçant une nouvelle préfacturation complète ; utiliser /clear entre les tâches, /compact pour les pauses longues, et /rewind plutôt que /compact après quelques tours améliore les coûts
- Chaque fichier lu et résultat de commande reste en contexte pour tous les tours suivants ; mentionner les fichiers avec @ au lieu de chemins, utiliser des drapeaux silencieux, et définir les commandes courantes dans CLAUDE.md réduisent les sorties inutiles
- Les sessions longues coûtent beaucoup plus cher que plusieurs sessions courtes car le contexte s'accumule ; les sous-agents offrent un isolement du contexte pour les tâches bruyantes qui produisent beaucoup de résultats inutiles
- Les quatre principaux leviers d'optimisation sont : modifier les modèles/niveaux d'effort au début ou après /clear, utiliser /context pour vérifier le contenu initial, spécifier les fichiers précisément pour éviter les lectures supplémentaires, et fragmenter les tâches longues

## Discussion sur Hacker News (142 commentaires)

**Avis positifs** :
- Les optimisations décrites (cache prompt, /compact, @-mention de fichiers) sont des conseils utiles et applicables à tout système d'agents suffisamment avancé, pas seulement Claude Code.
- La gestion efficace des tokens a un vrai intérêt économique : réduire les coûts de calcul bénéficie à la fois aux utilisateurs et à Anthropic, les incitations sont alignées sur ce point.
- Les utilisateurs rapportent des résultats concrets en appliquant ces stratégies : workflows structurés, handoff files, sessions courtes et bien contextualisées produisent de meilleures sorties.
- L'article reconnaît implicitement une réalité : les outils LLM requièrent une certaine expertise pour être utilisés efficacement, ce qui est normal pour tout système complexe.

**Avis négatifs** :
- Le blog post illustre le problème fondamental : Anthropic devrait automatiser ces optimisations plutôt que de les confier à l'utilisateur (c'est du 'You're holding it wrong').
- Nombreux bugs documentés (cache corruption, /clear qui perd les sessions, /btw qui explose les écritures de cache sans raison claire) suggèrent que l'outil n'est pas assez stable pour exiger autant de configuration manuelle.
- Les changements constants du modèle et des mécanismes (effort busting cache, modifications de system prompt) rendent l'apprentissage de ces 'tricks' obsolète rapidement, contrairement aux outils traditionnels.
- Le modèle tarifaire basé sur les tokens avec limits stricts (5h/semaine en gratuit) crée perversement une incitation : Anthropic gagne davantage quand vous utilisez plus de tokens, donc l'automatisation des optimisations réduirait leurs revenus.
- Des utilisateurs rapportent que des alternatives (Qwen 3.8, modèles open-source, ChatGPT sans limits aussi strictes) offrent meilleur rapport qualité-prix-flexibilité, sans nécessiter ce travail de configuration.
