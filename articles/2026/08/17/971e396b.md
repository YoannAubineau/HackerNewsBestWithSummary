## Résumé de l'article

Wiz Research a découvert une vulnérabilité d'injection de script dans un workflow GitHub Actions du dépôt public snowflake-connector-net de Snowflake. Cette vulnérabilité, introduite par un commit co-écrit par l'outil Copilot Autofix de GitHub, a permis à un attaquant non authentifié d'exécuter des commandes arbitraires et de voler des credentials Jira donnant accès à des projets sensibles. La faille a été exposée pendant cinq jours avant sa découverte et correction le même jour par Snowflake.

- Un commit Copilot Autofix a remplacé un motif d'entrée sécurisé (env + jq) par une interpolation directe de chaîne, créant une vulnérabilité d'injection de shell
- L'outil autonome Red Agent de Wiz a découvert la faille, l'a exploitée, et a exfiltré des credentials Jira authentifiés pour qa@snowflake.net
- Le workflow contenait aussi une condition de sécurité inefficace qui était toujours vraie pour les événements de création d'issue
- Snowflake a patchié la vulnérabilité le même jour (23 juin 2026) et confirmé que seuls les chercheurs de Wiz y ont accédé durant l'exposition
- Cet incident illustre les risques d'utiliser des outils IA générateurs de code sans surveillance rigoureuse et la nécessité de gardes-fous contre les régressions de sécurité introduites par l'IA

## Discussion sur Hacker News (109 commentaires)

**Avis positifs** :
- La vulnérabilité aurait pu être évitée avec des outils d'analyse statique existants (zizmor, actionlint, shellcheck) qui détectent ce type d'injection de template dans les GitHub Actions
- Le problème révèle un défi plus large : le coût de révision du code n'a pas baissé alors que le coût de génération diminue, créant un goulot d'étranglement critique pour la sécurité
- La pratique des révisions superficielles (LGTM !) qui existait bien avant l'IA s'aggrave : les humains n'examinaient déjà pas vraiment le code, et l'IA amplifie ce problème
- GitHub Actions lui-même porte une part importante de responsabilité : le design mélangeant code et données (interpolation directe de chaînes) est défectueux et encourage les vulnérabilités

**Avis négatifs** :
- Le blâme attribué à Copilot est probablement incorrect : le commit initial introduisant la vulnérabilité a été écrit par un humain, pas par l'IA, bien que Copilot ait validé le changement
- Les erreurs d'injection de commande existent depuis des décennies et ne sont pas nouvelles ; présenter ceci comme spécifiquement un problème d'IA exagère et manque de contexte sur les vulnérabilités humaines existantes
- L'article peut être du contenu généré par IA lui-même (LLM slop) avec des simplifications excessives, notamment sur les conditions de protection qui n'avaient jamais vraiment ce rôle
- Le problème fondamental n'est pas l'IA mais l'absence de révision humaine adéquate et la désresponsabilisation des processus : c'est avant tout une défaillance organisationnelle de Snowflake
