## Résumé de l'article

Ce projet convertit le code source original de Microsoft Word pour Windows 1.1a en une application 64-bit Windows native exécutable, en remplaçant l'assembleur 16-bit et la gestion de mémoire segmentée par des équivalents modernes, tout en conservant l'interface utilisateur et les fonctionnalités originales.

- Le port traduit les points d'entrée en assembleur 16-bit en C/C++ et adapte la gestion de mémoire segmentée à l'environnement x64
- La compilation utilise CMake 3.25+ avec Visual Studio 2022, les commandes étant fournies pour les builds debug et release
- L'adaptation couvre aussi le démarrage Win16, la messagerie, les graphiques et les APIs de fichiers pour les rendre compatibles avec Win32 actuel
- Une suite de tests complète valide le runtime porté, les structures de données originales, et les workflows d'interface utilisateur (saisie, formatage, boîtes de dialogue)
- Les fichiers source C et ressources originaux restent l'implémentation de référence, tandis que l'assembleur historique est archivé mais non compilé dans les binaires

## Discussion sur Hacker News (71 commentaires)

**Avis positifs** :
- Le projet démontre la faisabilité technique de porter des applications Windows 16-bit en x64 natif, avec des implications intéressantes pour la réutilisation de logiciels historiques
- Word 1.1a offrait déjà une interface graphique sophistiquée avec éléments 3D, montrant l'innovation des années 1980 (via CTL3D.DLL)
- Les anciennes versions de Word/Excel (1998 et antérieures) sont souvent préférées pour leur interface utilisateur supérieure aux versions modernes avec le ruban, et une solution native x64 les rendrait accessibles
- L'utilisation d'LLM pour des tâches de portage devient progressivement viable et pourrait faciliter la conversion d'applications Win16 vers Win64
- Le projet a une valeur académique et historique significative pour comprendre l'évolution des logiciels et des interfaces

**Avis négatifs** :
- La licence n'est pas vraiment open source mais seulement 'source disponible' avec restrictions non-commerciales sévères, interdisant la distribution et violant les définitions standard du libre
- Utiliser WINE pour faire fonctionner des versions 16-bit de Word est déjà une solution fonctionnelle et plus simple que ce portage, sans nécessiter d'efforts de développement
- Des problèmes pratiques subsistent : icônes mal redimensionnées, bugs de portage, absence de binaire compilé, et le projet est incomplet avec des dépendances manquantes
- Les vieux logiciels Office contiennent des exploits non corrigés qui pourraient compromettre la sécurité du système si utilisés avec des fichiers non fiables
- La restriction de licence sur la distribution des travaux dérivés sur GitHub semble déjà violée par la publication du projet lui-même
