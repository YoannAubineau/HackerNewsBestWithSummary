## Résumé de l'article

L'application Météo de Windows 11 consomme plus de 1 GB de RAM lors de l'affichage d'une prévision météorologique, soit environ cinq fois plus que l'équivalent natif d'Apple sur macOS. Cette surconsommation mémoire contraste avec les efforts de Microsoft pour optimiser Windows 11 sur les machines à ressources limitées.

- L'app dépasse régulièrement 1,2 GB de RAM en utilisation normale, occupant jusqu'à 20 % de la mémoire sur un PC doté de 8 GB
- La consommation élevée provient du fait que Météo n'est pas une application Windows native, mais une webapp MSN construite sur le framework WebView2 (basé sur Chromium)
- Sur les machines d'entrée de gamme (8 à 16 GB de RAM), cette consommation peut augmenter la pression mémoire et ralentir le système via le fichier d'échange
- L'application intègre également de la publicité sponsorisée directement dans le flux de prévisions
- Cette situation contredit les déclarations de Microsoft concernant l'amélioration de l'efficacité de Windows 11 sur le matériel moins puissant

## Discussion sur Hacker News (196 commentaires)

**Avis positifs** :
- L'application Météo de Windows utilise effectivement une quantité anormale de RAM (1+ GB) comparée à des équivalents natifs (Apple ~250 MB, applications légères ~30-100 MB), ce qui témoigne d'une architecture inefficace basée sur Chromium/WebView2.
- Des alternatives minimalistes existent et fonctionnent parfaitement (wttr.in, applications en Rust ~200 KB, scripts shell), prouvant qu'une application météo ne devrait consommer que quelques mégaoctets au maximum.
- Le problème reflète un manque d'optimisation systémique chez Microsoft : les applications sont construites comme des wrappers web bloatés au lieu d'utiliser les outils natifs Windows disponibles.
- Cette inefficacité s'ajoute à d'autres problèmes de Windows 11 (publicités intégrées, surveillance) et illustre comment les grandes organisations laissent les ingénieurs produire du code peu efficace sans contraintes réelles.
- Le workaround simple (utiliser uBlock Origin dans Edge via PWA) ramène la consommation à 130 MB, confirmant que le problème vient de la structure de l'app et non d'une nécessité technique.

**Avis négatifs** :
- Les comparaisons nostalgiques aux années 90 sont trompeuses : les applications modernes doivent gérer des résolutions d'écran bien plus élevées (4K vs 800x600), des interfaces composées avec GPU, des animations fluides et des assets haute définition qui consomment naturellement plus de mémoire.
- 100-300 MB pour une application météo moderne avec interface graphique riche, images d'arrière-plan animées et widgets stylisés est raisonnable ; c'est le 1 GB qui est excessif, pas nécessairement toute augmentation par rapport aux standards historiques.
- Les mesures de RAM dans Task Manager peuvent être trompeuses : elles ne distinguent pas toujours la mémoire partagée avec d'autres processus, la mémoire virtuelle, ou les composants du système d'exploitation potentiellement réutilisés par plusieurs applications.
- Blâmer simplement les développeurs ignore les incitations organisationnelles réelles : les équipes optimisent selon des KPIs qui ne valorisent pas l'efficacité mémoire, et les gestionnaires rapportent des métriques sans lien avec la consommation réelle.
- Les frameworks modernes (Qt, GTK) consomment eux-mêmes 40+ MB même vides ; exiger moins de 1 MB pour une application GUI complète est irréaliste avec les outils et les attentes UX actuels.
