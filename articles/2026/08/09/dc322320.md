## Discussion sur Hacker News (151 commentaires)

**Avis positifs** :
- Les LLMs démocratisent la création d'outils : des utilisateurs sans expertise peuvent générer des applications fonctionnelles en minutes, ouvrant la programmation à un public beaucoup plus large.
- Les capacités des modèles s'améliorent rapidement : en 4 ans, on est passé de zéro à des outils permettant même à des enfants de créer des applications interactives, avec des progrès constants en précision et élimination des hallucinations.
- Les LLMs offrent une meilleure expérience utilisateur que la recherche traditionnelle : reformuler une question complexe en conversation naturelle est plus ergonomique et donne des réponses mieux adaptées au contexte que de parcourir des résultats Google.
- La qualité du code généré dépend de la qualité des directives : un codeur expert peut obtenir du code bien structuré en guidant correctement le modèle, tout comme les humains produisent du code spaghetti sans bonnes pratiques.
- Le problème de la dette technique n'est pas nouveau : les humains aussi créent du code difficile à maintenir, mais plus lentement, et les LLMs pourraient aussi corriger leurs propres messes rapidement grâce à leur contexte illimité.

**Avis négatifs** :
- Le code généré par les LLMs s'accumule rapidement en dette technique : les modèles produisent du code non maintenable à une vitesse telle que les humains ne peuvent pas le corriger assez vite, créant une accumulation de charges pour le futur.
- Les prétendus progrès des modèles masquent des préoccupations commerciales : Anthropic et OpenAI sont davantage incités par la capture réglementaire que par l'amélioration réelle des modèles, comme le montre la dégradation des performances (Opus 5 vs générations antérieures).
- Les LLMs ne font que réinventer des solutions existantes : les suggestions de Claude pour trouver des téléphones via Bluetooth RSSI sont des techniques connues depuis 20 ans, disponibles dans de nombreuses applications existantes, masquant un manque de véritable innovation.
- Comparer le code LLM au code compilé est fallacieux : contrairement aux compilateurs qui appliquent des règles déterministes et correctes pour un problème défini, les LLMs produisent du code probabiliste sans garantie de correction dans des spécifications complexes ou ambiguës.
- Les applications complètes générées deviennent rapidement ingérables : quand un utilisateur voudra étendre une application simple, la croissance du code rendra impossible à maintenir par les LLMs eux-mêmes, entraînant une accumulation d'erreurs et d'incohérences impossibles à démêler.
