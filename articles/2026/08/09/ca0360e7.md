## Résumé de l'article

Triton est un pilote Windows DirectX 11 pour QEMU qui apporte l'accélération graphique moderne aux machines virtuelles Windows. Développé en complément du protocole Neptune (couche de redirection Direct3D pour VirtIO), il implémente les interfaces DDI (Device Driver Interface) plutôt que les API DirectX, permettant aux appels DDI d'être transformés en appels API DirectX et sérialisés via le protocole Neptune existant, sans nécessiter de format de transport intermédiaire.

- Triton implémente l'interface DDI (Device Driver Interface) de DirectX 11 côté guest, transformant les appels DDI en appels API DirectX que Neptune peut sérialiser, contrairement aux approches précédentes qui remplaçaient simplement les fichiers d3d11.dll et dxgi.dll
- Le projet gère le bytecode shader DXBC en reconstruisant les métadonnées attendues par d3d11.dll sans transcompilation, ce qui améliore la compatibilité et réduit les risques d'erreurs
- Sur macOS, Triton s'appuie sur DXMT ou D3DMetal (du Game Porting Toolkit d'Apple) pour le rendu, avec émulation des textures partagées et des fences entre processus puisque l'architecture isolée de virglrenderer requiert un partage inter-processus
- La pile complète combine le pilote Windows Triton, le protocole Neptune, le KMD (pilote en mode noyau), l'interface VirtIO, et virglrenderer côté hôte pour transformer les appels DirectX en commandes exécutables
- Tout le code est open source et disponible pour les contributeurs ; l'intégration dans UTM est en cours pour permettre aux utilisateurs d'accélérer l'exécution sans compilation manuelle

## Discussion sur Hacker News (39 commentaires)

**Avis positifs** :
- Comble un besoin réel : absence de solution graphique 3D décente pour les VMs Windows sous Linux, particulièrement pour les machines avec GPU unique
- DirectX 11 est le choix pragmatique : c'est l'API 3D la plus utilisée sur Windows avec des milliers de jeux compatibles, contrairement à DirectX 12 ou Vulkan qui en ont beaucoup moins
- S'inscrit dans une dynamique positive : fait suite à des projets similaires réussis comme VirGL et Venus pour OpenGL/Vulkan, prouvant la faisabilité de ce type de solution
- Ouvre des possibilités pour l'émulation rétro : pourrait permettre de supporter des anciennes versions de Windows et API DirectX (DX3-7) pour les jeux rétro, domaine où il existe un vide important

**Avis négatifs** :
- Requiert une optimisation substantielle pour être réellement utile : avoir une implémentation fonctionnelle ne suffit pas, il faut que les performances soient acceptables
- Coût énergétique et environnemental significatif : développer avec des agents IA implique une consommation d'énergie importante et émissions de CO2 supplémentaires, d'autant que cela nécessite la construction de nouveaux data centers et centrales électriques
- DirectX 12 serait plus pertinent techniquement mais beaucoup plus complexe : l'implémentation de DX12 est très supérieure en difficulté, ce qui explique aussi pourquoi Parallels et VMware se limitent à DX11
- Risque d'opaacité si utilisé avec agents IA : un développement entièrement automatisé par agents pourrait produire du code que personne ne comprendrait réellement, rendant la maintenance et l'optimisation très difficiles
