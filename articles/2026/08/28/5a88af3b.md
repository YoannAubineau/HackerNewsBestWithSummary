## Résumé de l'article

htmx 4.0.0 est une nouvelle version majeure de la bibliothèque JavaScript pour améliorer les interactions HTML, développée après 8 mois de travail. Elle migre en interne de XMLHttpRequest vers l'API fetch(), tout en conservant une compatibilité comportementale largement similaire à la version 2.x.

- L'héritage des attributs devient explicite par défaut (ajout du suffixe `:inherited` requis), changeant majeur nécessitant une migration des templates
- Les noms d'événements sont standardisés selon le schéma `htmx:phase:action[:sub-action]`, supprimant les événements `htmx:xhr:*` et `htmx:validation:*`
- La gestion de l'historique n'utilise plus `localStorage` par défaut, favorisant des refetch lors de la navigation arrière pour éviter les conflits avec les bibliothèques tierces
- Deux nouvelles fonctionnalités majeures : le morphing de DOM (`morph` swaps) intégré et la balise `<hx-partial>` pour les swaps hors-bande
- De nombreuses extensions ont été créées ou mises à jour (hx-preload, hx-download, hx-sse, hx-ws, hx-multipart, et la nouvelle solution hx-live pour le scripting front-end)
- htmx 2.x reste marquée comme version « latest » sur NPM jusqu'en 2027 ; un outil d'upgrade en ligne de commande aide à identifier les changements nécessaires

## Discussion sur Hacker News (81 commentaires)

**Avis positifs** :
- HTMX offre une architecture web plus simple et maintenable que les frameworks JavaScript complexes comme React, en restant performant et adapté aux besoins modernes
- La combinaison HTMX + backend simple (Go, Django, Rails) + SQLite crée une stack productive et rapide, particulièrement appréciée pour les prototypes et les applications de production
- Les modèles d'IA (Claude, GPT) génèrent naturellement et préfèrent du code HTMX pour les projets de taille petite à moyenne, validant son approche hypermedia
- HTMX résout le problème fondamental de réduire la complexité architecturale, un avantage que les LLM ne peuvent pas éliminer même en générant du JavaScript
- La culture et l'approche du projet reflètent l'internet originel sans formalisme corporate, avec une communauté engagée et reconnaissante

**Avis négatifs** :
- Avec les LLM capables de générer du JavaScript fluide, l'avantage de l'abstraction simple de HTMX s'érode pour certains développeurs qui peuvent générer du code aussi facilement
- HTMX pose des défis de testabilité comparé à des frameworks plus structurés ; les tests au-delà de la manipulation DOM restent difficiles même avec les LLM
- L'intégration avec Alpine.js peut être maladroite et nécessiter du code JavaScript supplémentaire pour obtenir le contrôle fin requis
- Le changement de version 4 concernant l'héritage d'attributs explicite pourrait dérouter les modèles d'IA entraînés sur du code HTMX antérieur, réduisant temporairement leur efficacité
- Certains développeurs préfèrent d'autres approches : SSR avec Alpine.js léger, applications JS complètes typées (Elm, ReScript) ou frameworks structurés offrant plus de rigueur
