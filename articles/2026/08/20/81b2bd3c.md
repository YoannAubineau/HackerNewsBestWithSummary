## Résumé de l'article

Un utilisateur demande l'adoption du format AGENTS.md, un fichier Markdown standardisé que plusieurs outils d'IA (Codex, Amp, Cursor) utilisent pour documenter un codebase et faciliter la compréhension par des agents de codage.

- AGENTS.md émerge comme un standard interopérable dans l'écosystème des outils de développement assisté par IA
- CLAUDE.md est perçu comme trop spécifique à Claude Code et limite la collaboration avec les développeurs utilisant d'autres outils
- L'adoption du format standardisé améliorerait la compatibilité entre différents assistants et équipes de développement

## Discussion sur Hacker News (191 commentaires)

**Avis positifs** :
- Support de AGENTS.md est le standard de l'industrie : pratiquement tous les autres harness (Codex, OpenCode, Pi, etc.) le reconnaissent automatiquement, rendant Anthropic isolée et incompatible avec l'écosystème
- Configuration multi-harness devient difficile : les développeurs utilisant plusieurs outils doivent maintenir des fichiers séparés (CLAUDE.md, .cursor/rules, .github/copilot-instructions.md, etc.), ajoutant une friction inutile
- Amélioration de l'expérience utilisateur avérée : les utilisateurs rapportent que AGENTS.md réduit la phase de rassemblement de contexte et aide les agents (y compris les sous-agents) à s'orienter plus efficacement dans les projets
- Les workarounds existants sont fragiles : symlink, références @AGENTS.md ou fichiers passoires ne fonctionnent pas avec certaines fonctionnalités de Claude Code comme le lazy loading de fichiers imbriqués

**Avis négatifs** :
- Le changement de nom de fichier est trivial à contourner : un simple symlink (ln -s AGENTS.md CLAUDE.md), copie ou référence (@AGENTS.md) dans CLAUDE.md résout le problème en secondes sans intervention d'Anthropic
- AGENTS.md peut contenir du contexte obsolète ou mal adapté : certains contenus rédigés pour d'autres modèles ou périodes peuvent confondre Claude plutôt que l'aider, justifiant une approche prudente
- Les études empiriques montrent des résultats mitigés : une recherche récente suggère que la plupart des contenus dans ces fichiers ne produisent pas d'amélioration mesurable de performance, voire ont un effet marginal négatif
- Surestimation du problème : le refus d'Anthropic, bien qu'agaçant, n'est pas une barrière réelle au switching—c'est un inconvénient mineur facilement contournable, pas une raison crédible de changer d'outil
