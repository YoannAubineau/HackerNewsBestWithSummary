## Résumé de l'article

Un développeur exprime son frustration face à la multiplication des pull requests géantes, souvent générées par des outils d'IA, qui rendent la revue de code exponentiellement plus difficile et chronophage. Il plaide pour un retour aux petites PR, non pas parce qu'elles sont plus faciles à écrire, mais parce qu'elles sont plus faciles à comprendre et à évaluer.

- Les PR énormes (mille à trois mille lignes) dépassent la capacité cognitive pour les examiner correctement, même si elles accomplissent techniquement une tâche complète
- La complexité de compréhension augmente exponentiellement avec le nombre de lignes, pas linéairement
- Les commentaires excessifs ne compensent pas une mauvaise organisation ; une bonne dénomination des variables suffit généralement
- Utiliser une IA pour diviser automatiquement une grande PR en petits changements revue-friendly serait plus respectueux que de soumettre au jugement humain
- Le problème n'est pas l'IA en soi, mais l'acceptation d'une régression dans les pratiques de revue sous prétexte que les outils sont plus rapides

## Discussion sur Hacker News (103 commentaires)

**Avis positifs** :
- Les limites de taille des PRs pourraient être automatisées via CI, mais nécessitent un effort de prompt engineering sérieux pour vraiment fonctionner efficacement.
- Certains développeurs ont du succès en demandant à l'IA de découper le code après sa génération complète, ou en utilisant des outils/skills personnalisés pour orchestrer les commits atomiques et les PRs stackées.
- Les PRs peuvent être cassées en commits logiques et atomiques, ce qui améliore significativement la révision même si la taille totale reste importante.
- L'approche itérative (générer en entier, puis découper en PR révisionables avec une bonne narration) peut fonctionner si l'humain investit du temps dans le rework.
- Les outils modernes comme les PRs stackées de GitHub facilitent la gestion de grands changements en les forçant à passer CI individuellement.

**Avis négatifs** :
- Les LLMs manquent gravement de capacité à planifier et séquencer logiquement le travail pour créer de petites PRs cohérentes et racontant une histoire—c'est un manque fondamental, pas juste une question de prompting.
- Découper les PRs sans coordination conduit à des stacks incompréhensibles où chaque PR a besoin des autres, créant une mauvaise expérience de révision ; forcer la taille crée plus de problèmes que de solutions.
- Les tests générés par l'IA sont souvent vides ou hallucinés, donc les humains ne peuvent pas compter sur le CI seul pour valider ces énormes PRs ; la révision humaine reste critique.
- Le vrai problème est culturel/organisationnel : beaucoup d'entreprises utilisent l'IA pour contourner les processus d'ingénierie sérieux plutôt que d'adapter les standards à la nouvelle réalité.
- Si une PR est trop grande pour être révisée par un humain, elle est aussi trop grande pour qu'on en comprenne le code sans l'IA—cela crée une dépendance dangereuse et élimine toute responsabilité collective.
