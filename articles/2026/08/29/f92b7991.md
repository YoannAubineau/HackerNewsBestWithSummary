## Résumé de l'article

vphone-cli est un outil de recherche permettant de créer et d'exécuter des machines virtuelles iOS complètes sur Mac Apple Silicon via le framework Virtualization d'Apple, avec support du jailbreak et accès SSH/VNC.

- Installation requise : macOS 15+ Sequoia, Xcode, désactivation partielle ou totale de SIP et AMFI pour autoriser les binaires non signés avec entitlements PV=3
- Une seule commande (`vphone-cli vm create myphone -V jb`) automatise tout le pipeline : téléchargement du firmware iOS, patching, restauration DFU, installation du custom firmware et premier démarrage
- Cinq variantes de patch disponibles offrant différents niveaux de contournement de sécurité (jailbreak SSH, SSH root, VNC) ; les données des VM sont stockées dans `~/.vphone/` et restent portables hors du bundle signé
- L'outil expose un socket de contrôle pour l'automatisation programmatique (captures d'écran, touches, touches matérielles) et peut être intégré via MCP pour des tests E2E pilotés par IA
- Limitations connues : impossibilité d'imbrication de VMs, incompatibilité avec certaines configurations régionales iOS, incompatibilité avec les systèmes d'exploitation imbriqués

## Discussion sur Hacker News (73 commentaires)

**Avis positifs** :
- Ouvre des possibilités majeures pour les tests et l'ingénierie inverse, particulièrement en recherche de sécurité et automation, sans limitation du simulator
- Permet de tester avec des configurations réelles (App Store, iCloud, extensions réseau) impossibles sur le simulator qui n'est qu'une alternative window manager macOS
- Résout les écarts entre le simulator et les devices réels (crashes, comportements différents selon la langue/région, limitations Metal et GPU)
- Fournit un environnement jailbreaké pour les dernières versions iOS, contrairement aux alternatives disponibles, et permet l'installation d'IPAs via Sileo/Trollstore
- Particulièrement utile pour les tests de caméra, VPN extensions, et débogage kernel impossibles ou limités dans le simulator

**Avis négatifs** :
- Nécessite de désactiver partiellement le SIP, ce qui limite l'utilisation à des machines personnelles et empêche l'usage en environnement professionnel ou corporatif
- Compatibilité limitée avec les services Apple (App Store, iCloud) actuellement non fonctionnels, ce qui réduit les cas d'usage réels
- Apple trouvera probablement le moyen de le casser, et peut l'interdire comme elle a tenté de le faire pour Corellium, malgré l'ironie qu'elle fournisse elle-même les composants
- Les applications peuvent facilement détecter qu'elles tournent sur une machine virtuelle plutôt qu'un vrai device, rendant les tests moins représentatifs
- Pas de virtualisation du modem/baseband, ce qui limite les tests liés aux télécommunications réelles
