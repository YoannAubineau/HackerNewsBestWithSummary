## Résumé de l'article

ssh.place est un canvas partagé en ligne de 200×60 cellules où n'importe quel utilisateur peut dessiner directement via SSH sans créer de compte ni installer de logiciel. Chaque participant doit attendre 15 secondes entre chaque action (limité par sa clé SSH), et seules les couleurs sont acceptées, pas le texte.

- Accès immédiat : taper `ssh ssh.place` suffit, n'importe quelle clé SSH fonctionne
- Navigation et dessin : mouvements au clavier (flèches, WASD, HJKL), sélection de couleurs (0-9), dépôt de blocs avec la barre d'espace
- Limitation par cooldown : chaque utilisateur doit attendre 15 secondes entre les actions, non réinitialisable par reconnexion
- Restrictions : seules les couleurs sont dessinables, tout caractère texte est rejeté par le serveur
- Persistance : les modifications ne se font que via SSH, la page web affiche seulement le canvas

## Discussion sur Hacker News (108 commentaires)

**Avis positifs** :
- Le projet est apprécié pour son originalité et son approche créative utilisant SSH comme interface, s'inscrivant dans une tendance émergente des applications SSH ludiques (late.sh, shellbox.dev, pico.sh, etc.)
- La démocratisation via SSH offre une accessibilité simple : un seul commande SSH suffit pour participer, sans nécessité de comprendre la technologie sous-jacente ou de créer un compte
- L'aspect collaboratif et social en temps réel attire les utilisateurs, rappelant le succès de r/place avec ses dynamiques organiques et compétitives entre groupes
- Le code entièrement open source et les déploiements transparents (GitHub Actions) renforcent la confiance et permettent aux développeurs d'apprendre des technologies modernes (Wish, Bubbletea, Lipgloss)

**Avis négatifs** :
- Le projet est rapidement infesté de bots qui compromettent l'expérience utilisateur humaine, problème inévitable mais insuffisamment adressé par les mécanismes de limitation actuels
- Des préoccupations de sécurité légitimes : connexion à des serveurs SSH aléatoires expose les utilisateurs à des risques théoriques d'exploitation (vulnérabilités client OpenSSH, escape sequences de terminal), bien que mineurs comparés à la navigation web
- Manque de mécanisme PKI robuste pour vérifier l'authenticité du serveur ; la confiance repose sur TOFU (Trust On First Use), ce qui pourrait être problématique pour les paiements ou transactions sensibles
- La palette de couleurs est jugée limitée et déprimante ; problèmes de compatibilité d'affichage selon les terminaux, avec des teintes identiques ou invisibles chez certains utilisateurs
- Le contenu marketing généré par IA (probablement Claude) utilisé pour présenter le projet manque d'originalité et adoptent un style cliché répétitif, ce qui pourrait détourner de la qualité réelle du projet
