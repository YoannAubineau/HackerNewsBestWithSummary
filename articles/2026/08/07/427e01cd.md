## Résumé de l'article

Herdr est un runtime (environnement d'exécution) open source pour les agents de codage CLI, créé par Can en tant que projet solo. Le projet rejoint Y Combinator (batch F26) avec l'objectif de devenir une entreprise construisant des outils pour développeurs, tandis que le runtime reste libre et open source sous licence Apache-2.0.

- Herdr offre un runtime persistant où les agents IA peuvent s'exécuter longtemps dans des terminaux avec une interface TUI (terminal user interface) bundlée, sans dépendre d'applications externes
- Le projet a atteint 25 000 étoiles et 340 000 téléchargements, avec plus de 500 extensions créées par la communauté (Raycast, Stream Deck, app iOS)
- Le runtime reste gratuit et open source (Apache-2.0) ; l'auteur a basculé de AGPL pour permettre une utilisation librement accessible
- La stratégie consiste à garder le core du runtime petit et lean tout en construisant des fonctionnalités supplémentaires payantes pour une version commerciale, notamment la connexion de plusieurs machines et clients
- L'équipe devrait rester petite, concentrée sur la robustesse et l'extensibilité du runtime plutôt que sur l'ajout constant de fonctionnalités

## Discussion sur Hacker News (175 commentaires)

**Avis positifs** :
- Herdr remplit un besoin réel : meilleure visibilité et navigation entre plusieurs agents avec affichage du statut en temps réel, contrairement à tmux où il faut cliquer manuellement sur chaque terminal
- Le projet reste open source et peut être forké facilement si des problèmes surgissent ; plusieurs utilisateurs expriment leur confiance dans la capacité de la communauté à maintenir une version deshittifiée si nécessaire
- Des exemples positifs existent de projets YC/VC restant fidèles à leurs valeurs (Proxmox VE, certaines entreprises FLOSS 100% bootstrappées dans leur batch YC actuel)
- L'auteur a clairement indiqué garder le runtime open source ; le passage d'AGPL à Apache montre une volonté de favoriser l'adoption plutôt que de verrouiller le code

**Avis négatifs** :
- Le pattern est bien établi : VC finance pour construire une base utilisateurs, puis monétisation et enshittification suivent ; l'historique (Warp, Terraform, Vault) le confirme régulièrement
- Herdr souffre déjà de bugs (problèmes d'auth MCP, erreurs dans les sessions terminales) ; les pertes de focus qualité post-financement sont courantest dans l'industrie
- La communauté open source n'a jamais volontairement payé pour Herdr malgré sa popularité ; l'absence visible de bouton donation/sponsor rend la monétisation inévitable mais crée une asymétrie
- Le titre maladroit ('The runtime stays open') et le marketing lourd suggèrent une influence IA/startup typique ; cette rhétorique préfigure souvent des changements d'orientation commerciale
- YC a masssivement financé des concurrents directs (Superset, cmux, Emdash, Orca, Bullet, Conductor) dans le même espace ; la saturation accélère généralement la course au profit et à la fermeture des features
