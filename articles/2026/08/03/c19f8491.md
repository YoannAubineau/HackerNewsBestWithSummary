## Résumé de l'article

Un développeur explique sa stratégie pour utiliser les assistants de codage IA sur ses projets personnels sans perdre la compréhension de son code : plutôt que de copier-coller directement ou de réviser des centaines de lignes générées, il demande à l'IA de produire le code puis le retape manuellement dans son éditeur.

- Cette approche ralentit le flux de travail (environ 2x plus rapide au lieu de 10x) mais offre une meilleure compréhension du code et de son intégration dans la base de code existante
- En retapant chaque ligne, le développeur peut détecter les hallucinations de l'IA, améliorer la qualité du code et construire un modèle mental spatial de son architecture logicielle
- Cette méthode ressemble au processus d'apprentissage traditionnel des programmeurs (retaper les exemples plutôt que les copier-coller) et aide à créer une carte mentale du projet pour les modifications futures
- L'auteur craint que l'industrie accumule une importante dette cognitive en s'appuyant trop sur les IA sans comprendre le code généré, ce qu'il considère comme une faute professionnelle

## Discussion sur Hacker News (201 commentaires)

**Avis positifs** :
- Retyper du code LLM force à examiner chaque ligne et les décisions sous-jacentes, créant une compréhension plus profonde que le copier-coller, similaire aux conseils historiques de programmation
- La pratique combat la "dette cognitive" en construisant un modèle mental du code et de ses interactions avec la base de code existante, permettant d'identifier des bugs et de poser des questions sur les API
- Utile pour apprendre à partir d'un code fonctionnel comme point de départ plutôt que de zéro, comprimant la courbe d'apprentissage tout en conservant l'engagement actif du cerveau
- Offre un équilibre entre la productivité des LLM et la compréhension profonde : environ 2x plus rapide que sans IA, mais plus lent que l'acceptation aveugle, avec une compréhension significativement meilleure

**Avis négatifs** :
- La dactylographie elle-même est mécanique et inefficace pour l'apprentissage ; c'est le temps passé à réfléchir qui compte, pas le fait de taper, rendant la retypage inutile comparé à écrire le code soi-même
- Laisser les LLM générer puis retyper crée un faux sentiment de productivité sans créer réellement une réflexion originale, contrairement à écrire du code à partir de sa propre logique
- Insoutenable en environnement professionnel où la vitesse est prioritaire ; justifier auprès de la direction pourquoi on passe des heures à retyper du code déjà généré est irréaliste
- C'est une fausse solution au problème réel qui est de comprendre profondément ; focaliser sur la retypage distrait de véritables pratiques d'apprentissage comme poser des questions ou valider via des tests exécutables
