## Résumé de l'article

Un passionné a construit un radar d'avions fonctionnel basé sur un ESP32-C3 et un écran rond de 1,28 pouces qui affiche en temps réel le trafic aérien ADS-B nearby. Le projet a été assemblé en environ 15 minutes après soudure, puis flashé avec le firmware en moins de 30 secondes via l'outil web ESPHome.

- Le dispositif trace chaque aéronef par distance et orientation, et affiche les détails sur l'écran ; le modèle 3D original présentait des tolérances trop strictes pour les cartes reçues
- Le firmware a été considérablement amélioré avec contexte de vol (origine et destination plutôt que numéro de queue), types d'aéronefs détaillés et données météo locales
- L'interface web permet maintenant de modifier les coordonnées après installation initiale, de changer les options d'affichage sans réinitialiser la Wi-Fi, et d'ajuster unités, pistes, météo et format horaire
- Le texte est augmenté de 10 % par défaut avec un curseur persistant 80–130 % pour l'ajustement
- Le firmware supporte désormais les mises à jour OTA authentifiées par navigateur, sans connexion USB requise

## Discussion sur Hacker News (37 commentaires)

**Avis positifs** :
- C'est un projet sympa et impressionnant qui montre comment les ESP32 modernes deviennent suffisamment puissants pour des applications complexes
- La tendance des projets ESP32 avec affichage radar aérien se confirme ; c'est facile à réaliser et les composants sont très bon marché (moins de 20 dollars)
- Le décodage ADS-B est techniquement réalisable sur ESP32 avec les bonnes optimisations, même si c'est un défi intéressant
- Les mises à jour OTA par navigateur offrent une expérience utilisateur plus polie, comparable aux produits commercialisés

**Avis négatifs** :
- Utiliser l'API adsb.fi pour afficher les données plutôt que de décoder réellement ADS-B en temps réel est une simplification (du « cheating »)
- Appeler cela un « radar » est techniquement incorrect ; c'est plutôt un affichage ADS-B secondaire, pas un vrai radar primaire
- Il faut entrer manuellement les coordonnées GPS, alors que l'ESP32 pourrait gérer lui-même la géolocalisation par WiFi
- Un Raspberry Pi Zero avec un récepteur RTL-SDR offrirait probablement plus de capacités dans un format comparable
