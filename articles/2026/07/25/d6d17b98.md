## Résumé de l'article

Buz est un fork expérimental de Bun basé sur la dernière version antérieure à la réécriture en Rust, porté pour construire avec Zig. Le projet vise à devenir un remplacement compatible de Bun tout en nettoyant la base de code et en réduisant la dette technique.

- Le système de compilation a été unifié dans build.zig avec les sources embarquées de JavaScriptCore, permettant des reconstructions incrémentielles sous 1 seconde
- Plus de 11 000 lignes de code mort ont été supprimées et des parties du code ont été réécrites pour utiliser davantage la stdlib de Zig
- Le projet n'accepte pas de contributions humaines pour le moment ; seules les LLM sont utilisées pour moderniser le code existant
- L'objectif est de proposer dans quelques semaines ou mois une base de code viable compatible avec Bun 1.4.0 et exempte de « slop »
- Des tests importés de Bun Rust (nouveaux et anciens) sont inclus, bien que beaucoup ne passent pas encore

## Discussion sur Hacker News (162 commentaires)

**Avis positifs** :
- La réduction drastique du code mort (11K lignes) et la refonte du codebase démontrent qu'une seule personne peut nettoyer efficacement des années de négligence, ouvrant la voie à une maintenance plus durable
- Les temps de build sous 1s en incrémental prouvent que les problèmes de performance de Bun venaient de pratiques de développement négligentes, pas de limitations techniques inhérentes
- L'approche rigoureuse sans contributions humaines jusqu'à stabilisation évite l'accumulation de nouveaux problèmes et force une véritable amélioration de la qualité du code plutôt qu'une croissance chaotique
- Bun était devenu un projet de bloatware avec des dépendances inutiles ; une refonte ciblée en Zig offre une alternative légère et performante pour les cas d'usage simples

**Avis négatifs** :
- Sans écosystème établi et avec une seule personne aux commandes, ce fork affrontera une fragmentation du marché comme Deno ; les utilisateurs de Bun resteront sur Bun, les autres iront sur Node.js/Deno
- La tâche de maintenir un runtime JS entier est colossale pour une personne ; le projet risque l'abandon à long terme malgré un bon démarrage initial
- Node.js + npm/pnpm + vite + vitest offrent une flexibilité supérieure et un support mature ; prétendre qu'un seul outil résoudrait mieux tous les problèmes relève de la pensée magique habituelle aux runtimes JavaScript
- L'obsession pour les temps de build sub-secondes relève de l'optimisation prématurée ; la vraie contrainte pour la plupart des projets n'est pas là, et les bénéfices réels sont marginaux
