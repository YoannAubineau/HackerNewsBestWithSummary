## Résumé de l'article

Misago, un logiciel de forum en ligne, abandonne React.js au profit d'Htmx, une petite bibliothèque JavaScript qui permet au serveur de mettre à jour sélectivement des zones de la page sans rechargement complet. L'approche actuelle de Misago rend les pages deux fois (en templates Django et composants React), ce qui crée des problèmes de maintenance, de performance et de complexité pour les développeurs de plugins.

- L'architecture actuelle charge une page HTML complète depuis Django, puis remplace la majorité du contenu avec des composants React, créant une duplication de code et une confusion pour les utilisateurs qui personnalisent les templates
- Htmx permet de spécifier certaines zones HTML comme « îles dynamiques » qui se rechargent seulement au besoin (changement de catégorie, notification, vote) sans recharger la page entière
- Cette approche élimine la nécessité de sérialiser JSON, de maintenir une API dédiée, de compiler React, et de dupliquer les fichiers de traduction
- Htmx reprend le concept de jQuery Turbolinks d'il y a 20 ans : une simple requête serveur retourne seulement le HTML de la zone à mettre à jour
- Les logiciels de forum existants fonctionnent déjà avec cette architecture serveur-centric et les utilisateurs en sont satisfaits, sans besoin de rechargement de page intégrale

## Discussion sur Hacker News (172 commentaires)

**Avis positifs** :
- HTMX convient parfaitement pour les applications de contenu classiques (forums, pages CRUD) où la majorité des sites web n'ont pas besoin de frameworks complexes et bénéficient d'une réduction du JavaScript côté client
- Les performances perçues s'améliorent notablement : moins de code JavaScript à télécharger, temps de rendu initial plus rapide, meilleur support des connexions réseau lentes et des appareils bas de gamme
- L'approche hypermedia-driven est légitime et ancrée dans les standards web ; les créateurs de HTMX cherchent même à standardiser ces concepts dans les spécifications HTML officielles
- HTMX réduit la charge serveur par fragmentation HTML cacheable, pagination intelligente et meilleure gestion des ressources par rapport aux SPAs lourdes basées sur React
- L'architecture server-side rendering + HTMX élimine les problèmes de synchronisation d'état client complexes et les dépendances multiples que React exige, tout en restant maintenable

**Avis négatifs** :
- HTMX reprise largement les mêmes concepts qu'Angular 1.0 avec ses attributs HTML pour la logique, aboutissant aux mêmes problèmes de maintenance et de scalabilité sur des applications complexes et haute fréquence
- Inadapté pour les applications hautement interactives : scroll infini, filtrage dynamique avec état côté client, ou UI riches où React excelle grâce à sa réconciliation DOM et gestion d'état systématique
- Les performances réelles se dégradent rapidement à haut trafic (>10k req/s) car chaque interaction requiert un rendu HTML serveur, éliminant les avantages du cache CDN et créant des goulets verseur
- Manque d'outillage et d'écosystème matures (exemple : pas d'équivalent Storybook), complexité de composition et réutilisation de composants, et nécessité de coupler la logique frontend au backend
- La synchronisation d'état complexe (notifications + messages chat dépendants) échoue silencieusement avec HTMX, comme le montrent les bugs récurrents de GitHub ; React résout systématiquement ces problèmes
