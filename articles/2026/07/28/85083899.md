## Résumé de l'article

Codex Security est une interface en ligne de commande et un SDK TypeScript d'OpenAI permettant de détecter, valider et corriger les vulnérabilités de sécurité dans le code. L'outil peut scanner des dépôts, examiner les changements, suivre les découvertes au fil du temps et s'intégrer dans des pipelines CI/CD.

- Installation via npm avec Node.js 22+ et Python 3.10+ requis ; l'authentification se fait par ChatGPT ou clé API OpenAI
- Scan des répertoires via `npx codex-security scan .` avec historique des analyses stocké localement
- Support des environnements CI/CD en utilisant la variable d'environnement OPENAI_API_KEY plutôt que l'authentification interactive
- Intégration TypeScript possible avec la classe `CodexSecurity` pour les scans programmatiques
- Documentation officielle disponible pour l'installation complète, l'authentification, les options de scan et la configuration CI

## Discussion sur Hacker News (60 commentaires)

**Avis positifs** :
- L'outil fournit une valeur réelle via son infrastructure : déduplication entre scans, suivi des faux positifs, contrôles de budget et intégration CI, au-delà du simple scanner sous-jacent
- L'open-sourcing permet une flexibilité accrue, notamment pour intégrer des modèles LLM locaux compatibles OpenAI ou des alternatives via des modifications du code
- Les définitions de compétences en langage naturel qui guident le modèle représentent une approche optimisée et réutilisable pour d'autres contextes d'IA

**Avis négatifs** :
- Des problèmes critiques d'authentification, de taux limites et de gestion d'erreurs : scans abandonnés après 1 heure, coûts importants (~$13-50% de quota hebdomadaire) sans résultats exploitables
- Nécessite des identifiants OpenAI et crée des obstacles à l'adoption en entreprise (upload de code vers le cloud, incompatibilité avec les politiques d'entreprise restreignant ChatGPT)
- C'est essentiellement un wrapper autour des modèles existants plutôt qu'une innovation fondamentale ; les entreprises héritent toujours des risques de confiance liés aux modèles d'OpenAI
- Paradoxe : les équipes d'OpenAI reconnaissent avoir besoin d'outils et de harnachements sophistiqués pour rendre les modèles LLM pratiques, contredisant les promesses marketing selon lesquelles les programmeurs ne seraient plus nécessaires
