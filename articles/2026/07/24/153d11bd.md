## Résumé de l'article

98.css est une bibliothèque CSS sans JavaScript permettant de créer des interfaces visuelles fidèles à Windows 98 en utilisant du HTML sémantique. Le projet privilégie l'accessibilité et la compatibilité avec les frameworks frontend modernes.

- La bibliothèque fournit des styles pour composants courants (boutons, cases à cocher, champs texte, listes déroulantes, curseurs) et éléments de fenêtres (barre de titre, barre d'état, arborescence, onglets, tableaux)
- Les entrées doivent utiliser des éléments HTML sémantiques (button, input, label, fieldset) avec des attributs d'accessibilité appropriés (aria-label, for)
- Les composants supportent des états visuels distincts : enfoncé, désactivé, survolé, focalisé, reproduisant l'apparence Windows 98
- La classe field-row organise l'espacement cohérent entre les éléments groupés ; field-row-stacked positionne les labels au-dessus des champs
- Le projet est sous licence MIT, disponible sur npm et unpkg, et accueille les contributions open-source sur GitHub

## Discussion sur Hacker News (105 commentaires)

**Avis positifs** :
- Excellente fidélité visuelle et pixel-perfect : le CSS récréé authentiquement l'esthétique Windows 98 avec des dégradés, des effets de beveau et les astuces de box-shadow très bien exécutées
- Pur CSS sans JavaScript : l'absence de dépendances externes et la complexité technique de reproduire les effets 3D en CSS seul est impressionnante et montre une vraie maîtrise
- Redécouverte de bonnes pratiques UX oubliées : boutons désactivés visibles, onglets multi-lignes qui « marchent bien », suffisamment d'indices visuels (contraste, profondeur) pour naviguer intuitivement
- Cas d'usage authentiques et polyvalents : des développeurs l'ont utilisé pour des prototypes, des sites personnels, des thèmes Winamp, prouvant son utilité au-delà de la nostalgie pure
- Gestion communautaire exemplaire : l'auteur maintient activement le projet, examine les pull requests et délègue les commits de qualité, garantissant la pérennité

**Avis négatifs** :
- Efficacité spatiale insuffisante : comparé à Windows 95/98 qui maximisait l'espace (résolutions 800×600), cette implémentation gaspille trop d'espace blanc, pas adapté aux vrais contraintes d'époque
- Précision incomplète : certains éléments manquent (dropdowns natifs, radio buttons, groupes), les onglets multi-lignes ne se déplacent pas aléatoirement comme prévu, certains comportements (TrackBar) divergent de l'original Win32
- Les efforts retro-design perpétuent une illusion : la nostalgie masque que les interfaces Windows 98 n'étaient pas vraiment supérieures en UX, juste familières ; ce n'est pas une solution aux vrais problèmes actuels (flat design, manque de feedback)
- Impact limité sur les véritables problèmes UI : ces projets divertissent mais ne remettent pas en cause les mauvaises tendances modernes (boutons cachés au lieu de désactivés, absence de tooltips, métriques privilégiant le temps sur page)
- Accessibilité et compatibilité problématiques : certains rapports de bugs (onglets non-réactifs sur Firefox Android), pas de support complet des navigateurs, relique plutôt que solution pratique pour la web contemporaine
