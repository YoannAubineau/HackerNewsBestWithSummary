## Résumé de l'article

Scriptc est un compilateur TypeScript créé par Vercel qui transforme du code TypeScript ordinaire en binaires natifs petits et rapides, sans inclure Node, V8 ou de moteur JavaScript. Le compilateur décide construct par construct ce qui peut être compilé en code natif statique, et signale précisément ce qui ne peut pas l'être.

- Le code TypeScript standard s'exécute byte-for-byte identique à Node, sans modification ni annotation requise, typechecké par le compilateur TypeScript réel
- Trois niveaux explicites : compilation statique native (par défaut), exécution dynamique via un moteur JavaScript embarqué (quickjs-ng, ~620 KB), ou rejet avec message d'erreur spécifique
- Couvre le langage TypeScript complet et la stdlib standard (classes, closures, génériques, async/await, regex, fs, http, crypto, fetch, etc.)
- Les binaires résultants sont petits (~178 KB pour un exemple simple), se lancent très rapidement (~2ms), et ne lisent jamais node_modules à l'exécution
- Deux mécanismes de vérification garantissent la fiabilité : tests différentiels (800+ programmes doivent donner résultats identiques à Node) et vérification de sécurité mémoire avec AddressSanitizer

## Discussion sur Hacker News (111 commentaires)

**Avis positifs** :
- Compiling TypeScript to native binaries sans runtime permet des exécutables plus petits et rapides, comparable aux avantages de Go/Rust pour les outils serveur
- Pour des projets TypeScript sans dépendances externes, l'approche élimine le besoin d'embarquer Node.js complet (100+ MB) et pourrait simplifier le déploiement
- L'idée d'un compilateur TypeScript natif est longtemps recherchée; disposer d'un exécutable statique unique facilite la distribution et le déploiement
- Le projet accepte activement les contributions et démontre une volonté d'amélioration continue (correction du README par exemple)

**Avis négatifs** :
- L'immense majorité de l'écosystème TypeScript/JavaScript utilise des dépendances non typées; fallback sur QuickJS (ou autre moteur JS) réduit drastiquement les bénéfices de performance promis
- Les décisions architecturales soulèvent des préoccupations: utiliser des floats par défaut au lieu d'entiers, dépendre de QuickJS pour les codes `any`, et absence de nombre optimisation d'entiers compromettent les performances revendiquées
- 800k+ lignes de code générées en une semaine suscitent des doutes majeurs sur la qualité et la maintenabilité; comparaison peu flatteuse avec Porffor (68% du Test262) sans justification transparente des progrès si rapides
- Historique de Vercel Labs (zerolang abandonné mi-juin, autres projets oubliés) suggère une stratégie de buzz court-termiste plutôt qu'un engagement long-terme vers une production réelle
- Impossible en pratique sur les projets réels: l'écosystème npm/TypeScript repose sur des dépendances massives en JavaScript pur, rendant ce compilateur peu pertinent pour 99% des cas d'usage
