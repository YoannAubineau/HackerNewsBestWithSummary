## Résumé de l'article

Bun est un runtime JavaScript moderne. Un article d'analyse critique examine les affirmations concernant la réécriture du projet Bun en Rust à l'aide d'outils d'IA d'Anthropic, initialement présentée comme achevée en 11 jours pour 165 000 dollars.

- Le coût réel du projet dépasserait largement la somme annoncée : six semaines après la fusion en branche principale, aucune version n'a été publiée, et les employés d'Anthropic restent activement impliqués, suggérant des coûts cachés potentiellement autour de 800 000 dollars
- Le projet génère 2 475 demandes de fusion ouvertes attribuées à Claude (un proxy pour les PR générées par IA), dont le traitement par les vérifications Buildkite prendrait environ 86 jours en continu
- Les allégations selon lesquelles cette réécriture prouverait que l'IA peut remplacer les mainteneurs open-source sont considérées comme des justifications de valorisations élevées non entièrement documentées
- L'absence de version officielle depuis plus de 11 semaines et l'activité continue d'Anthropic suggèrent que le projet n'est pas aussi achevé qu'annoncé publiquement

## Discussion sur Hacker News (207 commentaires)

**Avis positifs** :
- La récriture en Rust fonctionne bien en pratique : elle est utilisée en production par Claude Code depuis plus d'un mois sans problèmes majeurs signalés par les utilisateurs, ce qui démontre une certaine robustesse.
- L'approche pragmatique adoptée (traduction mécanique avant refonte idiomatique) est justifiée : garder la structure similaire permet à l'équipe de maîtriser rapidement la nouvelle base de code, comme cela s'est avéré efficace dans d'autres réécritures pré-LLM.
- C'est un exploit technique remarquable : traduire un runtime complexe de 500k LOC avec des tests passants 100% en quelques mois, même avec des LLM, reste impressionnant et montre les capacités de ces outils guidés par des développeurs expérimentés.
- La méthodologie rigoureuse (test suites complètes, CI/CD exhaustif, révisions) renforce la confiance : les tests qui passent fournissent une preuve objective que les refactorisations futures réduisant les `unsafe` peuvent être faites de façon sécurisée.
- Les retards de release sont normaux et prudents : une période de canary release prolongée est justifiée pour un runtime critique, et ne signifie pas un échec du projet.

**Avis négatifs** :
- L'absence de release depuis deux mois est anormale pour ce projet, suggérant que la récriture reste instable ou incomplète malgré les déclarations optimistes, masquant potentiellement des problèmes techniques.
- Le code n'est pas idiomatique Rust : il garde une structure similaire au Zig d'origine (lui-même une mauvaise traduction du Go d'esbuild), avec beaucoup de `unsafe` qui aurait pu être évité, limitant les bénéfices de sécurité attendus de Rust.
- L'absence de transparence d'Anthropic sur les coûts réels, les bugs découverts et l'état technique futur alimente la méfiance, contrastant avec la communication très publique sur la récriture elle-même.
- Une seule utilisation en production (Claude Code) n'est pas représentative : c'est une application TUI spécialisée qui n'exercerait qu'une fraction mineure de l'API Node.js, masquant les problèmes qui affecteraient les utilisateurs réels.
- La question de la maintenabilité à long terme reste ouverte : l'équipe a peu d'expérience Rust, et les coûts énormes de CI/CD (~800k$ estimés) suggèrent des problèmes cachés plutôt qu'un succès triomphal.
