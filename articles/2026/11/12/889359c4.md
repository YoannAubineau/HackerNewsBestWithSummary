## Résumé de l'article

AWS Emulator est un émulateur local des APIs AWS qui permet de tester des logiciels sur sa propre machine ou en intégration continue sans appeler AWS réellement et sans avoir besoin d'un compte AWS. Il fonctionne comme un programme local qui expose un endpoint API AWS, se configure via variables d'environnement, et propose un mode embarqué pour exécuter des tests isolés.

- Installation disponible sous forme de paquets précompilés (RPM, Debian) ou conteneur Docker, avec configuration via AWS CLI ou SDK
- Les scores de fidélité par service sont publiés à chaque release, et les lacunes sont suivies dans le dépôt GitHub avec distinction entre fonctionnalités non implémentées et celles corrigées
- Le mode embarqué compile l'émulateur directement dans le binaire de test, mais demande d'importantes ressources de compilation (100 GB disque, plusieurs cœurs CPU)
- La collecte de télémétrie est activée par défaut mais peut être désactivée via options de ligne de commande, variables d'environnement ou fichier de configuration
- L'utilisation est réservée au développement et aux tests ; elle n'est pas destinée aux charges de production ou aux tests de sécurité

## Discussion sur Hacker News (189 commentaires)

**Avis positifs** :
- Réponse officielle d'AWS à un besoin réel : les alternatives comme Localstack, Floci et Ministack manquaient de support pérenne et de compatibilité complète
- Approche innovante par agents IA pour générer et maintenir le code : boucles de test fermées et vérifiables rendent ce cas d'usage particulièrement adapté aux agents autonomes
- Basé sur les spécifications Smithy internes d'AWS et validation exhaustive contre les APIs réelles, garantissant une meilleure couverture que les émulateurs communautaires
- Compatible avec des outils existants (CDK, Terraform, testcontainers) et offre un mode Rust embarqué intéressant pour les tests d'intégration
- Cas d'usage parfait pour les boucles de développement par agents : tâche délimitée, facilement vérifiable, avec retours rapides des tests

**Avis négatifs** :
- Manque de polish apparent : documentation de GitHub insuffisante, matrice de compatibilité absente, absence de benchmarks ou de support clairement annoncé
- Couverture d'émulation fragmentée et imprécise : certains services critiques comme S3, Lambda, IAM à ~50-70%, beaucoup d'autres à 20-40%, avec des raccourcis importants (les services ne se parlent pas via APIs)
- Ne peut pas tester les politiques IAM, KMS, S3 bucket policies ni les appels multi-comptes/régions — limitations majeures pour le test de sécurité réaliste
- Problème de maintenance incertain : produit généré entièrement par IA, peu clairement documenté sur l'engagement long terme, capacité réelle à gérer les évolutions futures des services AWS douteuse
- Approche purement d'émulation d'API insuffisante : les instances EC2 lancées ne s'exécutent pas réellement, ne teste que le chemin heureux pour beaucoup de cas, accumule 6500 problèmes non triés
