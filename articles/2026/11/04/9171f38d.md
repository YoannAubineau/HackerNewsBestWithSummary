## Résumé de l'article

Les laptops Nvidia RTX Spark (comme le MSI Prestige N16 Flip AI Plus) peuvent exécuter Linux avec accélération GPU, mais rencontrent un problème critique : quand le laptop est branché sur secteur, le GPU se verrouille à environ 780 MHz au lieu de 2+ GHz sous Windows, réduisant les performances d'inférence de 65 tokens par seconde à 14. Cette limitation provient d'un composant firmware appelé Nvidia Platform Controllers and Framework, spécifique à Windows, qui gère le partage de puissance entre CPU et GPU via une table de paramètres chiffrée que seul le driver Windows peut déverrouiller.

- La cause : une table de puissance chiffrée dans le firmware que Windows déchiffre mais Linux ne peut pas accéder, forçant le GPU à une fréquence très basse sur secteur (780 MHz vs 2,2 GHz sous Windows).
- Sur batterie, Linux retrouve des performances proches de Windows (61-67 tokens/sec), confirmant que le problème est lié à la gestion de puissance secteur, pas à Linux lui-même.
- WSL (Windows Subsystem for Linux) offre une solution intermédiaire pragmatique : il hérite de la pile driver Windows et conserve les performances complètes du GPU tout en permettant d'exécuter des outils Linux comme vLLM.
- L'installation de Linux nécessite des contournements : adaptateur Ethernet USB pour le Wi-Fi, configuration des réservations mémoire GPU depuis Windows (96 GB par défaut réservés au GPU), et utilisation d'une distribution comme Omarchy pour les drivers.
- Une solution définitive dépend d'Nvidia : portage de la logique de gestion de puissance du Platform Controller dans le driver Linux open-source.
