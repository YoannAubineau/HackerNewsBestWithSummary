## Résumé de l'article

Stalwart est un serveur de messagerie open source qui implémente désormais les protocoles Exchange (MAPI over HTTP, EWS, ActiveSync, Autodiscover), permettant aux clients Outlook, Apple Mail et aux applications mobiles de se connecter à Stalwart comme à un serveur Exchange natif, sans modification de la part des utilisateurs.

- Les organisations peuvent migrer leurs données depuis Exchange Server ou Microsoft 365 vers Stalwart tout en conservant les mêmes clients, grâce à la compatibilité complète avec les protocoles Exchange et l'outil de migration Vandelay.
- Les clients Exchange (Outlook Windows/Mac, Apple Mail, applications mobiles) se connectent nativement via MAPI over HTTP, EWS ou ActiveSync ; les tâches, calendriers, contacts et notes restent synchronisés entre tous les protocoles (IMAP, JMAP, CalDAV, CardDAV).
- Le code Exchange représente 200 000 lignes ajoutées mais est isolé dans un module optionnel désactivé par défaut, sans impact sur les déploiements qui n'utilisent pas Exchange ; les métadonnées spécifiques à Exchange peuvent être supprimées facilement.
- La nouvelle version 1.2.0 ajoute aussi des règles de messagerie côté serveur, les accusés de réception (MDN), la gestion des heures de travail et des ressources de réunion, ainsi qu'une amélioration de 4,5 à 6,9 fois en débit pour le client FoundationDB.
- Le nouveau Outlook Windows n'est pas compatible, car Microsoft l'a conçu uniquement pour accéder aux données via le cloud ; la version classique d'Outlook reste soutenue jusqu'à 2029.

## Discussion sur Hacker News (267 commentaires)

**Avis positifs** :
- Stalwart offre une solution open source AGPL et une alternative viable pour les organisations refusant de migrer vers Microsoft 365 Cloud, notamment les institutions publiques et universités affectées par les changements de licence Microsoft
- Le serveur en un seul binaire, la configuration simplifiée, l'intégration native de JMAP, DKIM/SPF/DMARC automatiques et la consommation réduite de ressources constituent une amélioration tangible par rapport aux stacks Postfix+Dovecot+Rspamd fragmentées
- L'adoption par des projets établis comme Thunderbird Mail et Kagimail valide la qualité technique et la fiabilité du serveur en production réelle
- Pour les PME et organisations en Europe craignant la dépendance aux services cloud américains, Stalwart représente une option de conformité réglementaire et de souveraineté des données
- Le support multi-protocoles (MAPI, ActiveSync, JMAP, IMAP) et la migration progressive des clients existants rendent la transition moins disruptive que prévu

**Avis négatifs** :
- Le risque d'adopter un serveur mail critique non audité à grande échelle reste prohibitif pour les entreprises ; aucun manager ne prendra ce risque sans années de déploiements réussis d'autres organisations
- La majorité des grandes organisations restera verrouillée dans l'écosystème Microsoft 365 complet (Teams, Office, calendrier partagé, gestion des ressources) dont Stalwart n'est qu'une pièce, rendant le remplacement incomplet et coûteux en réadaptation
- Le code massivement généré par IA soulève des doutes sur la qualité, la maintenabilité et la sécurité pour une infrastructure email sensible ; la documentation Claude-générée renforce ces préoccupations
- L'absence de support Kerberos et d'intégration Active Directory native limite l'adoption en entreprise ; la licence AGPL effraie les avocats d'entreprise malgré l'existence d'options commerciales
- New Outlook abandonnera bientôt les options de configuration d'Exchange on-premise et Classic Outlook disparaîtra en 2029, créant un casse-tête client que Stalwart ne résout pas seul
