## Discussion sur Hacker News (73 commentaires)

**Avis positifs** :
- La disparition soudaine sans avertissement préalable d'un dépôt majeur (22k stars) pose un vrai problème pour les pipelines en production qui en dépendaient
- Une possible compromission de sécurité ou d'une vulnérabilité critique pourrait justifier le retrait, mais l'absence de communication est problématique même dans ce cas
- Cet incident illustre les risques de dépendre directement de dépôts GitHub; le vendoring local ou l'utilisation de registres intermédiaires reste la meilleure pratique
- Plusieurs implémentations alternatives (Tract, RTen, WONNX, Burn) existent et pourraient servir de remplaçants pour certains cas d'usage
- Les packages binaires restent disponibles sur PyPI, Maven Central et autres registres, donc le code ne disparaît pas complètement

**Avis négatifs** :
- Il n'existe aucune preuve confirmée d'une compromission; une simple consolidation de repos ou restructuration interne pourrait aussi expliquer la situation
- L'hypothèse d'une attaque de chaîne d'approvisionnement est mal appliquée ici: retirer un dépôt ne correspond pas au modèle classique où l'attaquant injecte du code malveillant dans les livraisons
- Le développement d'ONNX Runtime était déjà devenu lent avant cette disparition, suggérant un manque d'investissement plutôt qu'une urgence de sécurité
- Les rumeurs de compromission (Agent Framework) ne sont pas confirmées pour ONNX Runtime lui-même; attribuer la disparition à un compte Microsoft hacké reste spéculatif
- La mention de télémétrie dans ONNX Runtime est contrée par l'existence de mécanismes établis pour la désactiver (variables d'environnement, API dédiées)
