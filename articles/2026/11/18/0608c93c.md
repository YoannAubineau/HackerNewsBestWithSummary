## Résumé de l'article

jQuery 4.1.0 est une nouvelle version mineure de la bibliothèque JavaScript populaire. Cette version apporte des améliorations de performance, des correctifs de sécurité et des ajouts d'API dans plusieurs domaines clés.

- Ajax : ajout du champ responseURL à jqXHR et support d'une API de callback alternative pour les transports
- Sélecteurs : correction d'une vulnérabilité ReDoS, optimisation du tri unique, contournement d'un bug de l'interpréteur regex de Safari
- Core : refactorisation des boucles pour éviter les dépassements de limites de tableau, remplacement de getElementsByTagName et getElementsByClassName par querySelectorAll
- CSS : amélioration de la gestion des tests de sondage et support amélioré des documents XML via createElementNS
- Couverture de tests : expansion significative des tests unitaires pour Ajax, animation, données SVG et le module serialize

## Discussion sur Hacker News (175 commentaires)

**Avis positifs** :
- jQuery reste massivement utilisé (63-64% des sites web), particulièrement via WordPress et les sites legacy, justifiant ainsi sa maintenance continue
- L'API de jQuery est élégante et bien pensée (interfaces fluides, méthode chaining, collections utiles), inspirant les frameworks modernes et restant supérieure à l'API DOM vanilla pour certains cas d'usage
- jQuery résout toujours des problèmes pratiques : code plus concis que vanilla JS, gestion d'événements custom sur objets non-DOM, manipulation de collections d'éléments sans boucles explicites
- La transition des vieux projets jQuery vers vanilla JS est devenue faisable grâce aux LLM et aux APIs JavaScript modernes (querySelector, classList, etc.)
- jQuery reste utile pour les petites améliorations interactives (menus déroulants, diaporamas) sur sites statiques, sans les surcharges des frameworks modernes

**Avis négatifs** :
- jQuery est devenu obsolète : les APIs JavaScript modernes (querySelector, fetch, Promises, async/await) et les frameworks réactifs (React, Alpine, HTMX) offrent les mêmes capacités sans dépendance externe
- Utiliser jQuery aujourd'hui c'est ajouter une surface d'attaque CVE supplémentaire et une dépendance inutile quand vanilla JS fait le même travail, surtout pour du code généré par IA
- jQuery UI a échoué à livrer à temps ses promesses (refonte complète en pièces détachées trop lente), ternissant la réputation de jQuery et montrant les limites du projet
- Le vrai problème de jQuery n'était pas l'absence de fonctionnalités mais la couverture navigateurs imparfaite ; aujourd'hui, des polyfills atomiques sont une meilleure solution que jQuery entier
- La progression des standards web a rendu jQuery redondant : les navigateurs modernes standardisés éliminent le principal avantage historique de jQuery (compatibilité cross-browser) sans justifier le surcoût de performance ou de maintenance
