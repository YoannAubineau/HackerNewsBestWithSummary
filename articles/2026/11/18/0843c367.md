## Résumé de l'article

Solid est un framework JavaScript qui utilise la réactivité fine (signals) pour construire des interfaces utilisateur performantes. Solid 2.0, publié après cinq ans de développement depuis la version 1.0, introduit l'async directement dans le graphe réactif, intègre les Server Functions au cœur du framework, et améliore significativement la détection d'erreurs pour les agents IA.

- L'async est désormais une primitive du graphe réactif, permettant de gérer les promesses et itérateurs asynchrones avec gestion automatique des race conditions et du state spéculatif
- Les Server Functions, emprunts aux patterns popularisés par SolidStart, supportent maintenant les appels RPC sur Request/Response et les connexions persistantes par Server Sent Events
- Le framework détecte les erreurs réactives à la compilation et à l'exécution (waterfalls, boucles d'effets mal construites, problèmes de scalabilité du graphe) et fournit des suggestions de correction
- La surface API s'est réduite : createResource, batch, startTransition, on, produce, createComputed, createMutable et autres primitives moins nécessaires ont été supprimées
- Le metaframework SolidStart a été retiré en faveur de primitives fournies dans le cœur et des plugins Vite agnostiques, permettant à l'écosystème de construire des solutions adaptées sans réimplémenter l'infrastructure

## Discussion sur Hacker News (115 commentaires)

**Avis positifs** :
- Solid 2.0 représente une avancée majeure avec son graphe réactif unifié intégrant l'asynchrone, permettant de détecter les waterfalls et les inefficacités de manière impossible avec React ou d'autres frameworks
- L'approche JSX pure sans tooling spécialisé offre une meilleure intégration avec l'écosystème TypeScript/IDE standard comparé à Svelte ou Vue, tout en étant plus performant que React
- Le composant serveur RPC et les fonctions 'live'/'broadcast' offrent une solution plus naturelle et élégante pour le problème frontend-backend que Remix ou HTMX/DataStar
- Solid 2.0 améliore la maintenabilité et la debuggabilité du code, bénéfices qui s'appliquent aussi bien aux agents qu'aux développeurs humains, renforçant les bonnes pratiques à grande échelle
- Le rendeur universel de Solid 2.0 ouvre de nouvelles possibilités comme les interfaces natives watchOS avec le même JSX, avantage que React n'a jamais offert proprement

**Avis négatifs** :
- Les bundles Solid 2.0 sont significativement plus gros (20.3 KiB brotli vs 4.8 KiB en v1.9.18), ce qui peut être problématique pour ceux sensibles aux tailles de bundle et aux coûts de tokens
- La documentation contient du 'slop' confus et difficile à comprendre, particulièrement sur les concepts de 'broadcast' et 'live', rendant l'apprentissage frustrant
- Le focus sur 'Built to Be Written by Agents' soulève des doutes quant à la maintenabilité long-terme, notamment concernant si une base de code aussi complexe reste vraiment soutenable même avec un code bien examiné
- Certains utilisateurs trouvent que l'approche Solid est encore moins intuitive que Svelte pour des cas d'usage simples, particulièrement avec les conditions d'early return nécessitant 20+ lignes au lieu de 4
- Les préoccupations géopolitiques autour de Vercel limitent l'attractivité de l'écosystème UI proposé
