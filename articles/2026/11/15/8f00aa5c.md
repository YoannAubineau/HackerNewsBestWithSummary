## Résumé de l'article

L'auteur défend l'idée que le code généré par l'IA devrait être obligatoirement publié en Open Source, en s'appuyant sur des arguments éthiques, légaux et pratiques.

- Les modèles d'IA ont été entraînés sur d'énormes corpus de code Open Source scraté sans permission ni attribution, ce qui constitue une forme de « license laundering » en transformant ce savoir collectif en code propriétaire.
- Sur le plan légal, le code purement généré par l'IA ne devrait pas être copyrightable puisqu'il n'a pas d'auteur humain, un principe établi par la jurisprudence américaine (affaire du Monkey Selfie) et reconnu par l'U.S. Copyright Office.
- Pour assurer l'équité entre juridictions aux lois différentes et honorer l'écosystème Open Source qui a rendu l'IA possible, le code généré par l'IA devrait être explicitement publié sous licence Open Source ou dédié au domaine public via CC0.
- Le code généré par l'IA avec peu d'intervention humaine au-delà de la rédaction de prompts devrait particulièrement être Open Source, même s'il n'est pas 100% automatisé.

## Discussion sur Hacker News (328 commentaires)

**Avis positifs** :
- Les modèles d'IA ont été entraînés sur des masses de code open source sous licences copyleft (GPL, AGPL) sans attribution ni respect des termes, ce qui constitue une violation de licence similaire à du blanchiment d'argent logiciel.
- Si le code purement généré par l'IA n'est pas protégeable par le droit d'auteur (selon la jurisprudence US), le maintenir propriétaire crée une incohérence : sans copyright, les licenses open source deviendraient pertinentes pour clarifier les droits d'utilisation et de modification.
- Les entreprises qui utilisent l'IA extraient massivement la valeur du travail gratuit des développeurs open source passés, puis verrouillent le résultat, créant un cercle vicieux d'extraction de commons sans compensation ni retour.
- Étendre l'obligation d'open source au code généré par IA enraierait le risque que les entreprises contournent intentionnellement les licences copyleft (comme AGPL) en utilisant l'IA pour 'cloner' et propriétariser des logiciels existants.
- Il s'agit d'une question de fairness : les humains qui ont appris sur du code open source ne devraient pas être obligés d'open sourcer, mais les modèles IA qui font exactement cela à l'échelle industrielle devraient l'être pour préserver l'écosystème.

**Avis négatifs** :
- Si le code généré par l'IA n'est pas protégeable par copyright, une licence open source n'a aucun effet légal ; imposer une licence sur du domaine public est juridiquement vide et contradictoire.
- Les humains apprennent également à partir de code open source et de Stack Overflow ; appliquer une règle différente à l'IA serait arbitraire et contraire aux précédents établis en matière de droit d'auteur (fair use, clean room design).
- Le code généré par l'IA est souvent de faible qualité et peu utile ; forcer son open sourcing encombrerait les dépôts de 'slop' sans valeur, contrairement à du code humain peaufiné avec soin et itérations.
- Beaucoup de code propriétaire interne aux entreprises contient des secrets commerciaux et des données confidentielles ; forcer l'open source éliminerait la confidentialité des données métier, ce qui est impraticable et socialement nuisible.
- L'application d'une telle règle est impossible et inévitable : quasi tout le code futur sera mélangé d'IA et d'humain, les modèles locaux peuvent exécuter n'importe où, et les entreprises bien financées pourront toujours contourner ou ignorer l'obligation.
