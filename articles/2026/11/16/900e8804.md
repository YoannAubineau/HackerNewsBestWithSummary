## Résumé de l'article

Une faille de sécurité critique a été trouvée dans uBlock Origin (version MV2 pour Firefox), permettant à un site malveillant de forcer l'extension à ajouter des filtres arbitraires de confiance qui peuvent injecter du code JavaScript sur n'importe quel site. La vulnérabilité a été corrigée et documentée dans un avis GitHub de sécurité.

- Un site malveillant peut extraire l'UUID aléatoire de l'extension en interceptant les requêtes XHR effectuées par les filtres uBlock existants
- L'attaquant crée ensuite un iframe invisible du sélecteur d'éléments et communique avec lui via postMessage pour injecter des filtres contenant du code JavaScript malveillant
- Les filtres ajoutés par le sélecteur d'éléments sont automatiquement marqués comme « de confiance » et peuvent donc exécuter du code JavaScript arbitraire
- L'attaque ne nécessite qu'un clic accidentel de l'utilisateur sur la page, car l'iframe peut être positionnée de façon invisible ou superposée pour capturer le clic sur le bouton de création du filtre
- Un correctif a été implémenté en exigeant un mot de passe secret que seul le vrai sélecteur d'éléments reçoit du content script

## Discussion sur Hacker News (109 commentaires)

**Avis positifs** :
- La vulnérabilité démontre bien pourquoi les extensions ayant accès au DOM des pages représentent un risque : elles doivent injecter leur UI dans la page, ce qui les expose aux manipulations des sites malveillants
- Le blocage d'annonces est une mesure de sécurité essentielle, car les publicités sont devenues un vecteur majeur de malwares et d'arnaques
- Les extensions partageant le même DOM que la page peuvent involontairement révéler des informations sensibles (UUIDs, comptes existants) au site visité
- Le correctif rapide et la transparence du rapport (prose humaine, POC généré par IA) constituent des signaux positifs de qualité
- L'architecture actuelle des extensions web est problématique : les navigateurs devraient fournir des APIs dédiées (overlays, UIs sandboxées) plutôt que forcer les extensions à modifier le DOM

**Avis négatifs** :
- Le DNS-based blocking reste une approche valide et complémentaire, particulièrement pour les utilisateurs peu exposés aux sites modernes comme YouTube
- Firefox et autres navigateurs pourraient simplement intégrer des fonctionnalités de blocage d'annonces natives plutôt que dépendre d'extensions tiers, éliminant une classe entière de vulnérabilités
- Les extensions représentent une augmentation massive de la surface d'attaque ; beaucoup d'utilisateurs en installent des douzaines sans évaluer les risques réels
- Chrome/Manifest V3 visait à réduire les permissions des extensions, ce qui est une approche raisonnable même si imparfaite
- Le problème des malwares dans les extensions est systémique et ne sera pas résolu par des correctifs techniques seuls
