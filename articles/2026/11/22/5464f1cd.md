## Discussion sur Hacker News (52 commentaires)

**Avis positifs** :
- Approche innovante comme couche de traduction légère (12 MB) plutôt que conteneur complet, permettant l'exécution dans un navigateur web
- Potentiel intéressant pour les téléphones Linux et les environnements cloud/sandbox où l'émulateur Android traditionnel est trop lourd ou lent
- Projet ambitieux et créatif explorant les limites du possible, avec plusieurs implémentations alternatives émergentes (droidloom, Lepton, innkeeper) stimulant l'innovation
- Avantage architectural par rapport à Waydroid : pas de conteneur complet, exécution cross-platform en Rust, pas de dépendances root complexes

**Avis négatifs** :
- Très précoce et instable : la plupart des APK testés par les utilisateurs ne fonctionnent pas, avec erreurs fréquentes d'exécution (DEX, touch dispatch, ViewRoot)
- Incompatibilité majeure : limité aux APK 64-bit, pas de support NDK complet pour les bibliothèques natives, APIs Android manquantes ou cassées
- Sécurité gravement insuffisante : les applications peuvent lire les données d'autres apps, pas de sandboxing réel malgré les promesses de permissions d'accès aux fichiers
- Cas d'usage peu convaincants face aux alternatives établies : Waydroid offre une meilleure compatibilité sur Linux desktop, Android réel reste supérieur sur téléphone pour gestion d'énergie et d'apps
- Documentation et clarté insuffisantes : confusions sur le nom du projet (ressemble à Wine pour Windows), interface utilisateur déroutante, peu d'explications techniques sur l'architecture
