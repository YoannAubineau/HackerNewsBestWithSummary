## Résumé de l'article

Rust 1.100.0 est une nouvelle version du langage de programmation Rust. Elle introduit plusieurs stabilisations majeures et améliore l'écosystème de compilation.

- Le never type (!) devient enfin stable après 10 ans de développement et 5 tentatives précédentes, permettant de nommer ce type uninhabité partout dans le code et complétant l'alias Infallible
- L'Allocator API se stabilise, permettant aux auteurs de bibliothèques de définir des allocateurs personnalisés utilisables avec Vec et Box, fondation du projet Allocators 1.0
- DropGuard est introduit comme nouveau type helper exécutant une fermeture à chaque sortie de fonction, simplifiant les patterns de nettoyage et les transactions avec rollback
- Cargo peut désormais rapporter les dépendances inutilisées et stabilise la résolution aware du min-publish-age (délais de refroidissement), permettant d'attendre avant d'adopter les nouvelles versions
- Le répertoire de build de Cargo applique maintenant consistemment un hash de configuration pour réduire les collisions de cache et améliorer les performances, notamment avec les git worktrees

## Discussion sur Hacker News (206 commentaires)

**Avis positifs** :
- Stabilisation du never type (!) après des années d'attente, avec des cas d'usage concrets comme Result<T, !> pour les erreurs impossibles
- Allocateurs personnalisés stabilisés et cargo-install utilisant désormais le lockfile par défaut, résolvant des problèmes de long terme
- Dépôts de temps de publication minimum (dependency cooldowns) configurables pour la sécurité de la chaîne d'approvisionnement, avec équilibre entre stabilité et correctifs de sécurité
- Détection automatique des dépendances inutilisées dans Cargo, améliorant la qualité du code et l'ergonomie pour les agents IA
- Amélioration continue des temps de compilation et de la taille des répertoires de build à travers plusieurs initiatives techniques

**Avis négatifs** :
- Absence toujours d'ABI stable natif Rust, limitant la distribution binaire et le partage de bibliothèques entre générations de compilateur
- Temps de compilation toujours élevés et accumulation massive de fichiers temporaires (90GB+) sur les gros projets, malgré les améliorations
- Les generics compliquent fondamentalement une ABI stable et obligeraient à utiliser des trait objects ou des interfaces C, compromettant l'expressivité
- Stabilisation du never type arrive très tard (11 ans après la v1.0), illustrant un processus de stabilisation parfois trop conservateur
- Préoccupations que les cooldowns de dépôt puissent faire manquer les correctifs de sécurité (zero-days) si mal configurés
