## Résumé de l'article

BUI est une bibliothèque d'interface utilisateur qui extrait et réutilise le code graphique de Blender sous forme de composants indépendants. Elle fonctionne en Python, Rust, JavaScript (React, Svelte), C, C++ et Dear ImGui, tout en reproduisant fidèlement l'esthétique, les interactions et l'efficacité énergétique de Blender.

- Noyau C partagé : BUI conserve un moteur C unique (le « kit ») qui gère les widgets, la mise en page, l'entrée utilisateur et le rendu, identique pour tous les langages de liaison
- Compatibilité directe : les programmes tkinter existants peuvent s'exécuter sur BUI sans modification, Qt et les composants Blender offrent aussi des syntaxes directes
- Performance optimisée : rendu par dégâts (redessine uniquement les régions modifiées), idle zéro-CPU, environ 2–4 fois moins de CPU par image que GPUI, avec GPU optionnel (Direct3D 11/OpenGL 3.3)
- Rendu fidèle : widgets dessinés d'après le code source de Blender, thèmes Dark et Light identiques à Blender, 781 icônes SVG incluses, police Inter embarquée
- Petite taille : exécutables autonomes de 5–7 MB (JavaScript/QuickJS), premier affichage en ~70 ms, zéro dépendances de navigateur ou serveur web

## Discussion sur Hacker News (213 commentaires)

**Avis positifs** :
- Blender's UI design est reconnu comme excellent et mériterait d'être réutilisable dans d'autres applications complexes (éditeurs vidéo, DAW, logiciels audio, FreeCAD, etc.)
- Les performances affichées sont impressionnantes et représentent un vrai gain par rapport à GPUI dans plusieurs benchmarks de mise à jour UI
- Le README est exceptionnellement clair et informatif, expliquant rapidement le projet et ses cas d'usage sans jargon technique superflu
- L'approche de décortiquer le code Blender plutôt que de le générer de zéro est astucieuse et montre une bonne compréhension du problème par l'IA
- Proposer plusieurs bindings (Python, Rust, JavaScript, C++) offre une flexibilité réelle pour différents contextes de développement

**Avis négatifs** :
- La licence GPLv3 est un obstacle majeur pour l'adoption : contrairement aux alternatives comme GPUI (Apache) ou Egui, elle interdit l'usage dans la plupart des projets propriétaires ou non-GPL
- Les démos web ne reproduisent pas fidèlement les interactions fines de Blender (édition multi-saisie en glissant, copier-coller entre champs, shift-drag, tooltips, raccourcis auto, etc.) ; le projet promet plus qu'il ne livre actuellement
- C'est un fork généré par IA d'une personne seule avec fort risque d'abandon ou de bitrot, sans garantie de maintenance long terme ou de révision humaine rigoureuse du code
- Blender's UI, bien que respecté par les pros, reste polarisant : nombreux commentaires affirment qu'il est complexe, contrintuitif ou pire que les alternatives (Maya, 3DS Max, Inkscape selon les utilisateurs)
- Manque d'accessibilité (a11y) mentionné nulle part, rendant l'outil inadapté aux applications grand public ; absence d'intégration aux thèmes natifs du système d'exploitation
