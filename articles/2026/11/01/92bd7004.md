## Résumé de l'article

Un développeur a mené une expérience systématique où Claude Opus 5.5 a construit la même application Pokémon cinq fois avec différents frameworks JavaScript (Next.js, SvelteKit, React Router, Nuxt, Astro, Angular, Qwik, Hono+htmx, Gracile+Lit, Vanilla), mesurant le coût en jetons API, le temps de développement, les lignes de code et les performances Lighthouse. L'article remet en question la tendance des développeurs à justifier leurs choix de frameworks par des impressions plutôt que par des données objectifs, particulièrement dans l'ère de la génération de code par IA.

- SvelteKit, Gracile+Lit et Angular se sont avérés significativement plus coûteux en jetons API que les autres frameworks (vraisemblablement parce que les agents n'avaient pas accès à des guides à jour dans leurs données d'entraînement)
- Hono+htmx et React Router offrent les meilleurs rapports coût-performance, générant du code performant et accessible avec moins de jetons
- Les frameworks multi-pages (MPA) obtiennent de meilleurs scores Lighthouse que les applications mono-pages (SPA), particulièrement sur la métrique Largest Contentful Paint (LCP)
- La taille du code varie considérablement : Hono+htmx accomplit une fonctionnalité similaire à Angular avec environ 70 % du code
- Les outils MCP et skills pour IA ne sont pas systématiquement utilisés par les agents, et leur impact réel sur la qualité du résultat reste incertain

## Discussion sur Hacker News (167 commentaires)

**Avis positifs** :
- Astro et HTMX se distinguent par leur efficacité en termes de temps, de coûts et de JavaScript côté client minimal, offrant une approche pragmatique pour les sites orientés contenu.
- Les frameworks simples et bien documentés (comme Nuxt, SvelteKit, Astro) facilitent le travail des agents IA en réduisant la surface d'API à explorer et en s'appuyant sur des abstractions claires et éprouvées.
- Les benchmarks objectifs sur des métriques concrètes (jetons, lignes de code, temps) sont préférables aux affirmations sans fondement et aident à sortir de la culture du 'vibe-coding'.
- L'article met en évidence que les frameworks imposant une structure et des conventions réduisent les bugs et facilitent le travail des agents IA, notamment pour la synchronisation d'état complexe.
- Astro avec escape hatches pour interactivité légère (React optionnel) offre un équilibre pragmatique entre légèreté et flexibilité pour la plupart des cas d'usage.

**Avis négatifs** :
- Angular performe mal même dans ce benchmark simple, mais les comparaisons globales sont trop simplifiées pour refléter des applications complexes (formulaires avec validation avancée, gestion d'état sophistiquée).
- Le benchmark sur une application Pokémon triviale ne représente pas les réalités des applications commerciales complexes avec authentification, contrôle d'accès et interactions intensives.
- HTMX montre ses limites avec les AI agents sur des formulaires complexes avec gestion d'état avancée, tandis que React gère ces cas mieux malgré un coût supérieur.
- La notion que 'les frameworks ne sont pas nécessaires' ignore que les applications complexes finissent toujours par avoir besoin de structures pour éviter le 'spaghetti code', que ce soit avec ou sans agents IA.
- Les résultats reflètent surtout que les modèles IA sont entraînés sur les frameworks populaires, ce qui biaise les performances observées plutôt que de mesurer l'efficacité réelle des abstractions elles-mêmes.
