## Résumé de l'article

Un utilisateur rapporte que le paramètre de partage de données pour l'entraînement des modèles OpenAI a été réactivé automatiquement dans Codex sans consentement explicite, ce qui inquiète les entreprises soucieuses de protéger leur propriété intellectuelle contre les fuites vers les laboratoires d'IA.

- Le setting "Improve the model for everyone" aurait été réactivé sans action de l'utilisateur, malgré la désactivation antérieure de cette option de partage de données
- Les utilisateurs peuvent vérifier et ajuster leurs préférences de partage de données via les paramètres de contrôle des données de ChatGPT ou les politiques de confidentialité d'OpenAI
- Cette réactivation silencieuse semble être un problème connu ayant déjà été soulevé sur d'autres forums technologiques
- Les entreprises utilisant Codex pour du code sensible sont particulièrement préoccupées par le risque d'exposition de leur propriété intellectuelle à travers l'entraînement des modèles

## Discussion sur Hacker News (132 commentaires)

**Avis positifs** :
- Plusieurs utilisateurs confirment avoir observé la réactivation non consentie de l'entraînement du modèle, ce qui renforce la crédibilité de l'observation initiale face aux accusations de preuve insuffisante.
- Le problème révèle un pattern comportemental cohérent chez les entreprises de modèles frontier (OpenAI, Anthropic, Google) : design trompeur, flou contractuel, et incitations financières massives à exploiter toutes les données disponibles.
- Les cas documentés (Tristan Buckmaster avec Codex, Mistral changeant opt-in en opt-out, Anthropic avec Daybreak Blue) montrent que ces pratiques ne sont pas isolées mais systémiques dans l'industrie.
- La confiance résiduelle envers ces entreprises est justifiée : elles ont historiquement violé les droits d'auteur, utilisé des données sans consentement et construit leurs modèles sur du contenu volé.

**Avis négatifs** :
- Aucune preuve technique définitive n'a été fournie que l'entraînement s'effectue réellement ; il peut s'agir d'erreurs logicielles, de changements UI ou de malentendus sur les fonctionnalités (certains utilisateurs rapportent que leurs paramètres sont restés désactivés).
- L'alternative proposée (héberger soi-même les modèles) est impraticable pour la plupart : coûts prohibitifs, complexité technique, et modèles propriétaires inaccessibles localement.
- L'hypothèse de malveillance délibérée pourrait relever de la paranoïa organisationnelle ; des bugs, des refonte UI ou la incompétence logicielle suffisent à expliquer les dysfonctionnements observés plutôt que conspirations coordonnées.
- Les données de conversation ne représentent pas nécessairement un avantage d'entraînement déterminant, et même si elles étaient utilisées à d'autres fins (analytique, sécurité), cela ne signifie pas qu'elles améliorent directement les modèles de production.
