## Résumé de l'article

Nvidia Auto Ontology est une librairie open-source (Apache 2.0) qui crée une couche sémantique au-dessus des métadonnées d'entreprise pour permettre aux agents IA d'accéder, de comprendre et d'interroger les bases de données avec fiabilité. Elle réconcilie les définitions inconsistantes entre systèmes et expose le contexte par MCP, CLI et API.

- **Fonctionnalités principales** : génère des ontologies d'entreprise à partir de métadonnées, crée des graphes de connaissances, réconcilie les définitions divergentes et valide les requêtes générées contre les définitions certifiées
- **Traduction naturelle en SQL** : convertit les questions en langage naturel en requêtes SQL exécutées contre les bases de données connectées (Databricks, Postgres, Snowflake, DuckDB) via les modèles Nvidia NIM
- **Déploiement flexible** : supporte Docker Compose pour les déploiements locaux et Kubernetes pour la production ; authentification par SSO et RBAC (contrôle d'accès basé sur les rôles)
- **API et intégrations** : expose les données par chat conversationnel, endpoints REST, et protocole MCP (Model Context Protocol) pour les agents comme Claude Desktop ou Cursor
- **Traçabilité et gouvernance** : stocke l'historique des conversations, retourne la provenance avec chaque réponse, et intègre optionnellement un gestionnaire de secrets (Vault) pour les données sensibles

## Discussion sur Hacker News (111 commentaires)

**Avis positifs** :
- Peut réduire les erreurs en séparant la phase de création d'ontologie (exécutée une seule fois) de la phase de requêtes répétées, éliminant ainsi les variations dues à différentes interprétations du même document.
- Force les entreprises à documenter et formaliser les connaissances tacites (règles métier, définitions, exceptions) dispersées entre les systèmes et dans la tête des experts, créant une source de vérité unique et traçable.
- Combine des systèmes imparfaits de manière à potentiellement améliorer la fiabilité globale, comparable à comment TCP a construit de la fiabilité sur IP non fiable ou comment les systèmes biologiques créent de la prévisibilité à partir de processus non déterministes.
- Fournit une couche d'abstraction qui rend les résultats traçables : on peut identifier précisément quel outil ou dataset a produit quel résultat, plutôt que de dépendre de la randomness du modèle.
- Simplifie le travail des Data Engineers/Data Scientists en les libérant de requêtes ad-hoc répétitives, les recentrant sur la gouvernance et la qualité de l'ontologie.

**Avis négatifs** :
- Le problème fondamental demeure : les LLMs ne peuvent pas contraindre leur comportement pour considérer uniquement les données pertinentes, créant des hallucinations qui contaminent les résultats même avec une ontologie bien structurée.
- La documentation est du pur charabia généré par IA (non édité), rendant impossible de comprendre ce que fait réellement l'outil; c'est un mauvais signal sur la qualité du projet lui-même.
- Les erreurs des agents LLMs composent et s'amplifient dans les systèmes non déterministes; ajouter plus d'agents imparfaits n'élimine pas les problèmes, ils s'entrelacent de façons imprévisibles.
- N'améliore pas substantiellement par rapport aux technologies établies (OWL/RDF/SPARQL, Datalog) et demande une clé API NVIDIA, tandis que des alternatives open-source existent.
- Ne résout pas le problème critique de la connaissance tacite inexacte : si les analystes de données ont des règles métier implicites non écrites (exclure les comptes de test), l'ontologie codifie l'imprécision existante.
