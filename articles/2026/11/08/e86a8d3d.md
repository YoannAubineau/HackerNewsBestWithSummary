## Résumé de l'article

GitHub introduit une nouvelle page d'aperçu pour les pull requests, disponible en préversion publique opt-in. Cette refonte place les informations critiques (statut de fusion, actions suivantes) en haut de page dans un résumé compact, réduisant le besoin de défilement sur les longues discussions.

- La boîte de fusion est redessinée pour afficher les mêmes informations en moins de la moitié de l'espace, avec une vue compacte des vérifications, commentaires et approbations
- Nouveaux filtres de conversation : possibilité de filtrer les conversations non résolues ou ses propres commentaires, et de trier les commentaires du plus récent au plus ancien
- Résumé d'activité en haut à droite pour accéder rapidement aux commentaires de révision, demandes de révision et autres mises à jour
- Actions directes depuis l'en-tête : marquer un brouillon comme prêt pour révision ou fermer une pull request selon les permissions
- Accès via un bouton « Try the Overview page » dans l'en-tête, avec possibilité de revenir à l'ancienne interface pendant la préversion

## Discussion sur Hacker News (115 commentaires)

**Avis positifs** :
- La nouvelle mise en page améliore l'accessibilité en plaçant le bouton de fusion et les informations critiques en haut de page, évitant ainsi de devoir scroller excessivement ou ouvrir l'onglet diff
- Les améliorations de présentation rapprochent GitHub de solutions meilleures comme Graphite (sidebar pour les discussions, meilleure organisation des métadonnées)
- C'est un pas positif dans la direction, et les récentes améliorations UI de GitHub montrent une tendance encourageante

**Avis négatifs** :
- Les changements UI sont mineurs et ne résolvent pas les vrais problèmes : navigation encore compliquée entre onglets, pas d'amélioration du diff, pas de support pour les workflows avec agents d'IA
- La performance générale du site reste mauvaise (chargement lent des PRs, «load more» répétitifs, UI lourde et boguée) ; GitHub devrait corriger les bugs existants plutôt que d'ajouter des UI
- Les bugs critiques restent non résolus depuis plus d'un mois (merge queue défaillant à 60-70%, workflows retardés, navigation vers fichiers instable), ce qui rend les nouvelles fonctionnalités secondaires
- La rédaction marketing («The merge box, distilled», style pseudo-Apple) semble générée par IA et déconnectée des véritables besoins des développeurs
- Le problème fondamental persiste : avec les PRs générés par agents IA devenant massifs, aucun outil d'interface ne peut compenser l'absence de stratégies de review sémantiques, d'architecture préalable et de processus SDLC améliorés
