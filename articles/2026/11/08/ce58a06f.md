## Résumé de l'article

Claude Code est un assistant de codage développé par Anthropic, intégré à Visual Studio Code via abonnement Claude Pro. Un utilisateur de longue date explique pourquoi il a décidé d'abandonner Claude Code pour Pi, un outil de codage open source concurrent.

- L'auteur critique l'accumulation de petites frustrations : l'impossibilité d'avoir plusieurs sessions connectées à l'IDE simultanément, des commandes slash dysfonctionnelles dans l'extension VSCode, et une organisation confuse des résultats des sous-agents en cas d'exécutions multiples.
- Anthropic a publié 244 mises à jour pour Claude Code cette année, modifiant fréquemment les instructions système et descriptions d'outils, ce qui affecte la performance du modèle et crée des instabilités pour les utilisateurs existants.
- Claude Code contient un surcoût considérable : sa description d'outil Bash occupe près de 3 000 tokens pour des instructions redondantes que le modèle maîtrise déjà.
- L'auteur décrit le produit comme manquant de vision ou de direction claires, avec des fonctionnalités ajoutées rapidement (workflows dynamiques, équipes d'agents) davantage orientées vers les clients entreprise sans considération pour les autres utilisateurs.
- Pi, en contraste, offre une approche minimaliste, stable et hautement personnalisable via des extensions, avec un exemple : l'auteur a créé une extension en 20 minutes pour supporter plusieurs onglets.

## Discussion sur Hacker News (198 commentaires)

**Avis positifs** :
- Pi offre une flexibilité supérieure : configurabilité complète, extensibilité facile via des extensions, et contrôle total sur le système de prompts comparé à Claude Code qui est une « boîte noire ».
- Les modèles open source et moins chers (Deepseek, GLM, Qwen) offrent un excellent rapport coût-bénéfice pour Pi, particulièrement avec des optimisations d'inférence locale (kapitsa, ollama) sur du matériel standard.
- Claude Code souffre de problèmes structurels : changements constants du system prompt (244 releases en un an), support fragmenté des fichiers de configuration (AGENTS.md vs CLAUDE.md), et interface TUI/VSCode maladroite.
- L'écosystème Pi s'enrichit rapidement d'extensions tierces (compaction, permissions, outils) créant une communauté active où les problèmes se résolvent plus vite que chez Anthropic.
- La portabilité : Pi fonctionne sur SSH, tmux, conteneurs et accepte plusieurs fournisseurs de modèles sans lock-in, contrairement à Claude qui force une dépendance à Anthropic.

**Avis négatifs** :
- Claude Code offre une intégration native optimisée pour les modèles Opus 5.5 : meilleure compaction, gestion du cache plus fiable, support officiel complet et pas de risque de bannissement.
- Pi nécessite une maintenance technique conséquente : il faut gérer les extensions soi-même, écrire du code personnalisé, et gérer la sécurité des tokens OAuth, ce qui n'est pas accessible à tous.
- Les modèles open source sur Pi restent significativement moins performants qu'Opus 5.5 pour la résolution de problèmes complexes, le débogage et la planification, particulièrement sur machines avec peu de RAM.
- L'utilisation de la souscription Anthropic sur Pi contrevient formellement aux conditions d'utilisation et peut mener à un bannissement, alors que l'utilisation via API est bien plus chère.
- Les GUIs de Claude et Codex offrent une meilleure expérience utilisateur avec support du contexte visuel, gestion des sessions, artifact viewing et synchronisation cross-device, malgré leurs défauts.
