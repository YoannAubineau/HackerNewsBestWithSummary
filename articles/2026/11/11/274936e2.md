## Résumé de l'article

Modern Web Guidance est un outil open-source développé par Google Chrome, Microsoft Edge, Mozilla Firefox et MDN qui fournit aux agents de codage (IA) des guides actualisés sur les meilleures pratiques web modernes, les API natives du navigateur et les données de compatibilité. Il résout le problème des agents de codage qui génèrent du code legacy basé sur des données d'entraînement obsolètes, en injectant directement dans leur contexte des recommandations expert-curées, des motifs de code production-ready et des directives de compatibilité.

- L'outil propose 250 fonctionnalités web modernes couvrant les APIs navigateur, les layouts CSS, les performances, l'accessibilité, la sécurité, les formulaires, les composants et les interactions;
- Disponible via npm (`npx modern-web-guidance`) avec une recherche sémantique locale hors ligne et des récupérations de guides ciblés sans appels réseau;
- Intégrable dans des agents (Claude, OpenAI Codex, GitHub Copilot, Vercel Skills, etc.) via plusieurs méthodes d'installation standardisées;
- Utilise une évaluation robuste (Playwright graders, tests e2e multi-agents) pour calibrer continuellement le contenu et mesurer l'amélioration réelle des performances des agents;
- Distingue les améliorations progressives des comportements critiques, privilégie les fallbacks légers (<50 LOC) plutôt que les polyfills lourds, et tient compte des données de compatibilité Baseline en temps réel.

## Discussion sur Hacker News (107 commentaires)

**Avis positifs** :
- Adresse un besoin réel : les agents IA produisent actuellement du code obsolète et verbeux alors que les primitives web modernes offrent des solutions plus élégantes et efficaces
- Maintainabilité et efficacité des tokens : code concis et bien structuré réduit la charge cognitive des agents et économise les tokens, bénéficiant à tous les utilisateurs d'IA
- Approche pragmatique avec améliorations progressives : documente fallbacks cross-navigateur, guide les agents sans les forcer, permet l'amélioration itérative basée sur des données de réussite
- Initiative multinavigateur sincère : Mozilla et Microsoft Edge contribuent activement, les recommandations ciblent les APIs avec large consensus cross-browser plutôt que Chrome-only
- Utile au-delà des agents : développeurs humains trouvent aussi la ressource précieuse pour moderniser leur code et comprendre les meilleures pratiques actuelles

**Avis négatifs** :
- Risque de monoculture Chrome déguisé : liste substantielle de features stables uniquement sur Chrome (fetchLater, scroll-related APIs, etc.), accusé de reproduire le problème d'IE6
- Incitation à une complexité inutile : encourage progressive enhancement et fallbacks complexes alors que les équipes typiques préfèrent cibler l'intersection des navigateurs supportés sans comportements conditionnels
- Coût élevé en tokens : utilisation pratique très onéreuse (~$5 par utilisation selon utilisateurs), neutralisant l'argument d'efficacité énergétique
- Flou entre documentation et instruction : formulations comme 'MUST use fetchLater()' font que les agents interprètent les recommandations comme des commandes plutôt que des conseils nuancés
- Distribution via package managers jugée inefficace : distribuer du texte via npm/MCP au lieu de simplement fournir une URL accessible questionne le design et crée une friction inutile
