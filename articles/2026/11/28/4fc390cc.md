## Résumé de l'article

Convex Backend Skill est un plugin Claude pour faciliter l'intégration avec la plateforme Convex (backend-as-a-service). Un audit de sécurité identifie trois pratiques problématiques : l'envoi non consentie de l'idée projet vers un serveur distant, l'exécution de scripts téléchargés dynamiquement, et la contournement délibéré des vérificateurs de sécurité.

- Trois compétences (quickstart, add, labs-quickstart) envoient les données de l'utilisateur à basic-anteater-667.convex.site sans l'en informer, présenté comme de la télémétrie
- Le code de labs-quickstart scinde intentionnellement le téléchargement et l'exécution en deux appels Bash pour éviter que les classificateurs de sécurité ne bloquent la commande
- Les scripts proviennent de serveurs à noms générés et ne sont pas épinglés par hash, empêchant l'utilisateur de les auditer
- L'auteur recommande d'informer l'utilisateur avant tout envoi, d'inclure les scripts dans le plugin plutôt que de les récupérer dynamiquement, et de supprimer l'instruction contournant les vérificateurs de sécurité

## Discussion sur Hacker News (100 commentaires)

**Avis positifs** :
- Le problème central est que Convex Chef envoie les idées des utilisateurs à un serveur distant sans consentement explicite, ce qui viole la transparence attendue, contrairement aux appels API normaux aux services IA où les utilisateurs sont au moins conscients de l'interaction
- Le pattern de masquer la requête HTTP POST aux outils de sécurité (en scindant les commandes) est particulièrement problématique et renforce l'impression de comportement délibérément clandestin
- Dans un environnement où les millions d'applications/compétences arrivent quotidiennement, les entreprises n'auront qu'une seule chance de regagner la confiance publique ; le défaut par défaut d'une collecte de données détruit cette confiance de manière irréversible
- La confiance est devenue le nouvel atout critique face à l'inflation d'idées et d'implémentations bon marché générées par l'IA
- Convex héberge déjà le code et les données des utilisateurs ; extraire aussi les idées crée une asymétrie d'information inacceptable

**Avis négatifs** :
- Tous les services IA majeurs (ChatGPT, Claude, Gemini) envoient déjà les données des utilisateurs à leurs serveurs et les utilisent pour l'entraînement, souvent sans consentement explicite ou avec des paramètres réinitialisés à l'insu de l'utilisateur
- C'est une fonctionnalité prévue (génération de code backend à partir du prompt) et non une collecte de données malveillante ; la requête est supprimée en 30 secondes après la décision initiale
- Les idées brutes ont peu de valeur en tant que telles ; c'est l'exécution qui compte vraiment, et les grandes entreprises n'auraient aucun intérêt commercial à voler des milliers de petites idées d'applications
- La réaction confond une fonctionnalité légitime avec de la télémétrie malveillante, alors qu'il s'agit du fonctionnement normal d'un service de code-génération basé sur le cloud
- Les commentaires trompeurs du code (étiqueté 'telemetry') proviennent probablement de la génération IA elle-même et ne reflètent pas l'intention réelle de Convex
