## Résumé de l'article

Cet essai critique l'adoption irréfléchie de l'IA pour la programmation, arguant que les modèles de langage manquent de la sagesse et du jugement contextuel nécessaires pour produire du code maintenable à long terme. L'auteur, ingénieur logiciel expérimenté, soutient que les développeurs qui abandonnent la lecture et l'écriture de code au profit de l'IA renonçent à la maîtrise et à l'apprentissage.

- La maintenabilité du code et son architecture ne peuvent pas être évaluées immédiatement : leurs défauts n'apparaissent que sur des mois ou des années, ce qui rend impossible l'entraînement efficace des modèles d'IA avec des signaux de récompense instantanés.
- L'IA est entraînée sur des patterns issus d'un code réel majoritairement médiocre et sur des règles conçues pour les débutants, pas pour produire l'excellence que seule l'expertise peut atteindre.
- Les développeurs qui délèguent la génération de code à l'IA perdent l'occasion d'apprendre de leurs erreurs et ne peuvent jamais atteindre la maîtrise, transformant le code en « chaos » rapidement unmaintainable.
- L'auteur prédit que les entreprises adoptant une politique « sans IA » deviendront un avantage concurrentiel à mesure que les conséquences de cette délégation irrresponsable deviendront évidentes.
- L'IA reste un outil utile pour les tâches rébarbatives, mais elle ne doit pas remplacer le jugement humain et la responsabilité dans les décisions architecturales critiques.

## Discussion sur Hacker News (403 commentaires)

**Avis positifs** :
- Les projets générés par IA sans architecture réfléchie produisent du code complexe et fragile qui s'accumule rapidement, contrairement au code humain où la complexité s'ajoute plus lentement et peut être détectée à temps
- La maintenabilité du code est difficile à mesurer automatiquement et requiert une expertise accumulée par l'expérience; les LLM ne peuvent apprendre que des patterns moyens dans les données d'entraînement, pas l'excellence
- Les équipes doivent investir massivement en architecture, documentation et constraints pour guider les agents, sinon le code dégénère rapidement en dette technique; c'est un coût souvent sous-estimé
- Les développeurs juniors risquent de perdre les apprentissages fondamentaux en outsourçant tout à l'IA, causant une détérioration des connaissances institutionnelles et de la capacité à diagnostiquer les vrais problèmes

**Avis négatifs** :
- Le code humain dégénère tout aussi bien en chaos sans discipline; le problème n'est pas nouveau et l'IA n'est que plus rapide à créer du désordre qu'un mauvais développeur
- Les modèles s'améliorent rapidement; en moins de 2 ans, les capacités ont explosé (math, reasoning) et les critiques actuelles seront obsolètes; il est trop tôt pour des jugements définitifs sur la trajectoire
- Avec des refactors plus rapides et des contextes croissants, les architectures peuvent se plier facilement; les LLMs peuvent maintenir leur propre code mieux qu'on ne le croit si on les guide correctement
- Les mesures existantes (cyclomatic complexity, tests automatisés, performance) permettent de garantir une qualité correcte; le problème est culturel (managers pressant la vélocité) pas technologique
