## Résumé de l'article

Le Model Context Protocol (MCP) est un protocole lancé par Anthropic en novembre 2024 pour connecter les agents d'IA à des services externes. L'auteur argue que les modèles de langage sont désormais suffisamment avancés pour appeler directement les APIs et exécuter des scripts sans avoir besoin d'une couche d'abstraction comme MCP.

- MCP a résolu un problème réel en 2024 en permettant aux modèles primitifs d'accéder à des services externes, mais son adoption massive a créé une "complexité MCP" avec des problèmes de contexte surchargé.
- Les modèles actuels peuvent écrire du code, découvrir des interfaces (via `--help` pour les CLIs) et appeler des APIs non documentées directement, rendant MCP superflu.
- Des alternatives simples existent déjà : APIs HTTP standards, authentification mature, et négociation de contenu (comme l'en-tête Accept: text/markdown pour recevoir des réponses en Markdown au lieu d'HTML verbeux).
- L'auteur propose de standardiser l'accès direct des agents aux APIs HTTP plutôt que de continuer à développer l'écosystème MCP.
- Des exemples concrets montrent que certains services (documentation Shopify, sites de docs) adoptent déjà des en-têtes permettant aux agents de recevoir des réponses optimisées (Markdown, exemples spécifiques à la langue de programmation).

## Discussion sur Hacker News (270 commentaires)

**Avis positifs** :
- MCP offre un contrôle d'accès et une authentification sécurisée sans exposer les clés API à l'agent, contrairement aux accès directs CLI ou API
- MCP standardise la découverte et l'interface des outils, réduisant les tokens consommés par rapport aux agents qui réinventent à chaque fois comment utiliser une API
- MCP excelle pour les cas d'usage distribués et d'entreprise : auditing centralisé, gestion des permissions, rotation des credentials, et intégration multi-équipes sans CLI local
- MCP permet d'exposer des services sans API REST native (Jira, Linear) et facilite l'adoption par les utilisateurs non-techniques via les plugin stores (ChatGPT, Claude)
- MCP crée des limites de sécurité claires en tant que proxy, implémentant le principle of least privilege mieux qu'un shell avec accès complet

**Avis négatifs** :
- MCP consomme significativement plus de tokens que les CLIs ou APIs bien conçues, particulièrement pour les implémentations verboses (JSON, instructions intégrées)
- MCP résout des problèmes déjà résolus : des standards existants (OpenAPI, REST, OAuth) et des outils éprouvés (CLIs, curl, jq) suffiraient pour la plupart des cas
- L'architecture stateful originelle de MCP était mal pensée et inéfficace comparée aux patterns web modernes stateless; MCP reste une solution ad-hoc plutôt qu'une vraie standardisation
- Les MCPs surcharges les contextes au démarrage et forcent à charger toutes les informations à l'avance, contrairement à la découverte progressive via CLI ou terminal agent
- MCP ne résout pas le problème fondamental : les agents ont toujours besoin d'un vrai sandbox/bac à sable, et MCP crée une fausse sécurité qui ne tiendrait pas face à des modèles plus autonomes
