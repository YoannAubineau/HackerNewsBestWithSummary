## Résumé de l'article

Bend est un langage de programmation conçu pour fonctionner sur CPU et GPU avec une vitesse proche du C, permettant de spécifier des règles mathématiques (lois) que les systèmes d'IA ne peuvent pas violer. Le langage utilise un vérificateur de type basé sur des preuves, similaire à Lean, pour garantir que le code généré par une IA respecte les contraintes déclarées.

- Bend compile en code natif et atteint une performance similaire au C en single-core, tout en s'exécutant jusqu'à 100 fois plus vite sur GPU grâce au parallélisme automatique.
- Les "lois" (LAWS.bend) permettent de définir des contraintes que le code généré par IA ne peut pas contourner ; violer une loi est mathématiquement impossible puisque le compilateur en demande une preuve.
- Le vérificateur de type fonctionne en moins d'une seconde sur un codebase de taille moyenne, contrairement aux vérificateurs Lean ou Rocq qui prennent plusieurs minutes, rendant possible une vérification après chaque modification d'IA.
- Bend gère automatiquement le parallélisme : le développeur déclare simplement comment diviser le travail, et le compilateur le distribute sur tous les cœurs disponibles sans gestion manuelle de threads ni locks.
- Le langage est destiné principalement aux backends sur Linux et macOS, toujours en évolution avec une documentation et des guides disponibles.

## Discussion sur Hacker News (155 commentaires)

**Avis positifs** :
- Bend représente une avancée intéressante en théorie des types : utilisation de QTT (Quantitative Type Theory) et de types affines pour garantir des propriétés de performance GPU tout en permettant la vérification formelle.
- Le travail antérieur significatif de l'auteur (HVM, recherche sur les interaction combinators depuis 10+ ans) démontre une crédibilité académique réelle, bien au-delà d'un simple projet 'vibecoded'.
- L'approche pragmatique séduisante : plutôt que de chercher la perfection mathématique, Bend offre un compromis explicite entre verbosité et vérifiabilité, adaptant les preuves formelles à une ère d'agents IA.
- Démonstrations concrètes fonctionnelles : le projet peut bloquer effectivement certaines modifications de code en appliquant des lois formelles, même si de manière imparfaite.
- Les lois simples peuvent prévenir des classes entières de bugs critiques (exemple : la loi du 'zéro sum' aurait empêché l'attaque DAO d'Ethereum) sans nécessiter une vérification exhaustive.

**Avis négatifs** :
- La suppression du journal de commits crée une opacité problématique : impossible de reproduire les résultats de benchmarking cités (SHA pinned), violation des pratiques scientifiques standard et destruction de la traçabilité du développement.
- Suraffirmation des capacités : comparer Bend aux assistants de preuves modernes (Lean, Agda, Isabelle) sans démonstration empirique sur des projets de grande taille ni citation des travaux académiques pertinents sur les systèmes de types substructuraux.
- Le problème fondamental des lois sous-spécifiées : les démonstrations montrent que l'IA contourne les lois par créativité non-intentionnelle (diagonal movement, force fields) quand elles sont mal définies, ce qui est inhérent au problème plutôt qu'une force.
- La stdlib insuffisante rend les preuves pratiques laborieuses (60 lignes de faits arithmétiques basiques manquants, absence de théorèmes sur les données clés) ; reconstruire mathlib sera un effort massif et inefficace comparé aux solutions existantes.
- Ambiguïtés de conception non résolues : syntaxe confuse (paramètres de quantité universelle), retours de fonction incompréhensibles (Array & U32), limitations arbitraires (puissances de 2 pour les tableaux, récursion bornée à 2^48) qui suggèrent un travail inachevé.
