## Résumé de l'article

Shopify, plateforme de commerce électronique, revient aux applications natives en Swift et Kotlin après cinq ans d'investissement dans React Native. L'amélioration drastique des modèles de langage (LLM) a changé les calculs économiques en rendant le développement natif simultané sur deux plateformes moins coûteux qu'avant.

- Shopify avait adopté React Native en 2020 pour réduire la duplication de code et permettre aux développeurs de travailler sur plusieurs stacks, mais les avantages se sont érodés avec l'émergence d'agents IA capables de convertir automatiquement du code entre plateformes
- L'entreprise a construit un système appelé Helix qui migre progressivement les applications en décomposant le travail en petits points de contrôle testés, validés visuellement et revus avant validation
- L'architecture des applications est réconçue pour découpler la logique métier de l'interface, permettant aux agents d'itérer via une CLI en millisecondes plutôt que via des simulateurs en minutes
- L'application Shop a été entièrement migrée vers le natif en 12 semaines avec l'aide d'IA ; l'application Shopify (plus grande avec 300+ écrans) est en cours de migration et sera livrée cette année
- Shopify continuera à parrainer ses bibliothèques React Native open-source jusqu'à fin 2026, avec transfert progressif de FlashList vers une nouvelle gouvernance communautaire

## Discussion sur Hacker News (239 commentaires)

**Avis positifs** :
- LLMs changent l'équation économique : maintenir deux codebases natives devient viable quand les agents peuvent générer et synchroniser le code automatiquement, ce qui n'était pas rentable avant.
- Les performances et l'expérience utilisateur native sont supérieures à React Native, et sans crise technique existante, le coût supplémentaire devient justifié avec l'assistance par IA.
- Les frameworks natifs modernes (SwiftUI, Jetpack Compose) offrent des avantages significatifs en termes de productivité et d'intégration système que React Native ne peut pas égaler.
- La séparation architecture entre logique métier et UI, couplée aux tests automatisés et révisions par agents, réduit drastiquement les coûts de synchronisation des features entre plateformes.
- Pour les grandes organisations bien capitalisées comme Shopify, cette approche démontre que les réécritures natives deviennent tractables grâce aux agents de codage et aux itérations rapides.

**Avis négatifs** :
- L'article manque de données concrètes (heures-ingénieur, taux de défauts, coûts des tokens, temps de revue) pour appuyer les affirmations sur les économies réalisées—il montre des prototypes, pas la maintenance à long terme.
- Les agents codent rapidement mais ne garantissent pas la parité des features : divergences sur les edge cases, accessibilité, comportements de plateforme et décisions architecturales s'accumulent dans le temps.
- Cette stratégie ne vaut que pour Shopify et les géants bien financés ; les startups et petites équipes ont toujours intérêt à React Native ou Flutter pour aller plus vite avec moins de ressources.
- Les délais d'App Store Review restent imprévisibles et frustrants (jusqu'à 2 semaines), ce qui rend les mises à jour urgentes difficiles comparé aux mises à jour OTA possibles avec du web/RN.
- Dépendre des modèles LLM (coûts, tarification, capacités instables, termes de service) introduit une nouvelle fragilité par rapport à des frameworks stables maintenus communautairement.
