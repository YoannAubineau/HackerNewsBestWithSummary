## Résumé de l'article

Whiteboard est une application de bureau open-source (MIT) qui permet aux humains et aux agents IA de collaborer à l'architecture logicielle dans un espace de travail commun. Elle s'intègre avec des outils comme Claude Code et Codex, offrant aux agents un SDK pour dessiner sur un canevas et visualiser leur travail de conception.

- L'application fournit un visualiseur de diff sémantique et AST-aware écrit en Rust, qui résume les grandes fonctions en pseudocode et masque les changements non pertinents (tests, documentation)
- Elle relie les visualisations (diagrammes de séquence, relations d'entités, traces d'agents) directement au code sous-jacent, avec support LSP et raccourcis clavier VSCode
- Whiteboard trace les décisions autonomes des agents et permet de visualiser les exigences, leur implémentation et les choix effectués par l'IA
- L'application fonctionne localement, inclut une telémétrie anonyme qui n'expose pas le code ou les prompts, et une version hébergée pour les équipes est prévue
- Les limitations actuelles incluent l'absence d'édition de fichiers in-app, le support limité pour les reviews multi-dépôts, et l'absence de synchronisation live des reviews partagées

## Discussion sur Hacker News (107 commentaires)

**Avis positifs** :
- Répond à un besoin réel : comprendre et visualiser l'architecture générée par les agents de code, en particulier les compromis et flux d'exécution qui restent opaques autrement
- Approche bien pensée du problème : lier les diagrammes au code réel via des diffs sémantiques intelligents élimine les hallucinations et les divergences doc/code
- Excellente intégration dans l'écosystème existant : fonctionne en complémentaire avec Cursor/Claude/les agents terminaux sans remplacer ces outils, accès local aux ressources git/LSP
- Design UX convaincant : les animations fluides et la visualisation en temps réel des traces d'agent facilitent la compréhension vs lire du code brut ou du markdown
- Résolve un problème cognitif concret et fréquent : la charge cognitive quand on revoit du code généré, particulièrement pour les PRs complexes ou explorer une nouvelle partie du codebase

**Avis négatifs** :
- L'utilisation du terme 'IDE' est problématique pour un outil qui ne peut pas éditer les fichiers, ce qui crée une confusion sur le positionnement produit
- Risque classique de source de vérité dupliquée : les diagrammes divergeront du code à mesure que l'implémentation évolue, créant une charge de maintenance
- Peut être redondant avec des solutions légères existantes : Mermaid en markdown + agents pour générer les artefacts ou simples extensions VSCode couvriraient déjà une bonne partie du cas d'usage
- Footprint applicatif lourd (736 MB sur macOS) basé sur VSCode/Electron, sans support Windows ni Linux initialement, limitant l'accessibilité et ajoutant au 'tool sprawl' du marché
- Questionnement sur le modèle économique : le saut vers une version hébergée multi-utilisateur risque d'aliéner les utilisateurs corporate qui ne peuvent pas autoriser de nouveaux services SaaS externalisés
