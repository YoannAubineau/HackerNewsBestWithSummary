## Résumé de l'article

Ollaya est un serveur local qui exécute des modèles de décision open-source (classification, scoring, yes/no) conçus pour répondre en une seule passe forward sans génération de tokens. Compatible avec l'API TypeSafe, il offre des réponses en 8–10 ms sur GPU et fonctionne également sur CPU, garantissant la confidentialité des données traitées localement.

- Réponses ultra-rapides : les décisions s'exécutent en une seule passe forward (8–10 ms end-to-end sur RTX 4090) sans génération de tokens token par token
- Compatible API TypeSafe : accepte les requêtes et réponses TypeSafe ; le SDK Python 0.7.1 fonctionne sans modification
- Modèles open disponibles : Laya (Convai Innovations, 100+ langues), Decider (Qwen3.5), NLI, GLiClass et d'autres, téléchargeables depuis Hugging Face
- Confidentialité garantie : données traitées localement sur CPU ou GPU NVIDIA, sans frais par token ni appels d'API externes
- Multi-plateforme : application desktop, CLI et image Docker pour macOS, Windows, Linux ; installation simple via `ollaya run laya`

## Discussion sur Hacker News (85 commentaires)

**Avis positifs** :
- Ollaya offre une alternative open-source utile et pratique pour exécuter localement des modèles de décision, avec une API compatible à Jev facilitant la migration
- Les modèles ouverts concurrents se rapprochent de Jev en performance, et les petits modèles offrent un bon compromis vitesse/coût, particulièrement pour les tâches bien définies
- Jev et les modèles de décision remplissent une vraie lacune : classification zéro-shot rapide et très bon marché comparée aux LLM, avec des gains de coût réels en production (75% de réduction dans certains cas)
- L'écosystème s'enrichit (vLLM, GoModel) et offre flexibilité via l'API standardisée, permettant de changer les modèles de support sans refonte du code
- Des cas d'usage pratiques existent au-delà de la classification basique : grep intelligent sur logs, analyse de signaux avec contexte variable, automation résidentielle

**Avis négatifs** :
- Les critiques soulignent que « modèle de décision » est principalement du marketing pour un classificateur standard avec probabilités calibrées, sans innovation technique majeure
- Les modèles ouverts actuels (Laya 421M, Kev 4B) restent bien en retrait de Jev sur les tâches complexes et instables en pratique, malgré les améliorations récentes
- Ollama pourrait intégrer ce support nativement à tout moment, rendant Ollaya potentiellement superflu ; l'absence d'implémentation suggère un manque de priorité
- La copie rapide des innovations par l'open-source soulève des questions sur le moat compétitif et la viabilité commerciale, avec Typesafe accusé d'avoir gonflé la terminologie sans fondement technique solide
- Les exemples d'utilisation dans la documentation sont simplistes et trompeurs (exemple refund_request insuffisamment nuancé), obscurcissant les vrais cas d'usage et la complexité réelle des intégrations
