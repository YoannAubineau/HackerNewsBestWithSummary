## Résumé de l'article

Un développeur de logiciel de traitement de données (Easy Data Transform) a découvert en août une imitation malveillante de son produit sur GitHub, usurpant son nom et logo, contenant des fichiers exécutables infectés de malware. Malgré un signalement initial et des informations supplémentaires fournies en septembre, GitHub n'a pris aucune action pendant 23 jours, jusqu'à ce que le post soit visible sur la première page de Hacker News.

- Le dépôt contrefait utilisait le nom et le logo du produit original sans autorisation
- Un fichier .dmg téléchargeable contenait des détections de malware multiples selon VirusTotal
- L'image d'arrière-plan du fichier avait été modifiée pour encourager les utilisateurs à ignorer les avertissements antimalware
- GitHub n'a fourni aucune réponse substantielle en 23 jours malgré deux signalements détaillés
- Le contenu a été retiré environ 10 minutes après la publication du post sur Hacker News

## Discussion sur Hacker News (115 commentaires)

**Avis positifs** :
- GitHub pourrait utiliser des mécanismes légaux plus efficaces (DMCA) pour obtenir des réponses plus rapides, ce qui fonctionne automatiquement
- La réactivité rapide une fois qu'un problème est médiatisé montre que GitHub a la capacité technique de traiter ces demandes, confirmant qu'il s'agit d'une question de priorisation
- Les problèmes de modération et de malveillance ne sont pas spécifiques à GitHub mais systémiques dans les grandes entreprises technologiques
- L'escalade vers les équipes de sécurité ou les cadres supérieurs permet effectivement une résolution bien plus rapide que les canaux de support standards

**Avis négatifs** :
- GitHub et d'autres géantes du tech sous-financent délibérément les équipes d'abuse/modération malgré leurs profits massifs, ce qui est une forme de malveillance par négligence
- L'absence de support accessible et réactif pour la sécurité est une décision consciente de maximiser les profits plutôt qu'une contrainte technique ou de ressources
- La dépendance à la viralité sur HN pour obtenir une action révèle une culture systémique où seule la pression publique compte, au détriment des vrais utilisateurs
- Les entreprises comme GitHub nient ou rationalisent cette inertie intentionnelle en invoquant la charge de travail, alors que le problème est l'absence de volonté d'investir dans la capacité de support proportionnée à leur taille
