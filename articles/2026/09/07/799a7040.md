## Résumé de l'article

Un développeur a relevé le défi de construire un interpréteur Python fonctionnel en seulement 1024 octets de code C, sans macros ni bibliothèques externes. L'interpréteur exécute un sous-ensemble du langage Python incluant les boucles, les fonctions et les structures de contrôle de flux.

- L'interpréteur utilise un parseur récursif descendent qui exécute le code à la volée sans générer de bytecode intermédiaire, en s'appuyant sur la pile d'appels du programme C pour gérer les fonctions et blocs
- Les boucles sont implémentées en relisant et retraitant le code source à chaque itération, tandis que les appels de fonction sauvegardent la position actuelle, sautent au corps de la fonction, puis restaurent la position après exécution
- Le code original lisible fait plus de 4800 octets ; l'auteur a optimisé la version finale en utilisant des techniques de code golf comme l'exploitation de valeurs ASCII, l'utilisation d'opérateurs logiques à la place des conditions, et la suppression systématique des espaces
- L'interpréteur supporte les variables monocatégories (a-z), les expressions arithmétiques, les boucles for/while, les fonctions définies par l'utilisateur, les instructions if/else et print, et maintient un état minimal avec seulement quelques variables globales
- L'implémentation assume que le code source est correct (pas de gestion d'erreur) et supprime la plupart des espaces tout en préservant l'indentation et les espaces dans les littéraux chaîne

## Discussion sur Hacker News (85 commentaires)

**Avis positifs** :
- L'implémentation démontre des techniques ingénieuses de code-golfing et de minification, comparable aux approches historiques des interpréteurs 8-bit qui exécutaient directement le code source sans AST.
- L'article est bien écrit et pédagogique, expliquant clairement les compromis et choix de conception pour atteindre la limite de 1024 bytes.
- C'est un exercice créatif et ludique qui inspire la curiosité sur ce qui est vraiment nécessaire dans un langage, rappelant SectorLISP et l'esprit du code-golfing.
- Pour un subset très limité, le résultat fonctionne effectivement (le code FizzBuzz s'exécute correctement en CPython et dans cet interpréteur).
- La version lisible accompagnant le code minifié rend le projet accessible et pédagogiquement utile.

**Avis négatifs** :
- Ce n'est pas réellement un interpréteur Python mais un interpréteur d'un langage minimaliste inspiré de Python : les variables à une lettre, l'absence de listes/dictionnaires et les raccourcis de mots-clés (f=for, w=while, p=print) le rendent incompatible avec la majorité du code Python réel.
- L'approche ne fait aucune vérification d'erreurs et suppose que tout l'entrée est correcte, contrairement à des projets plus sérieux comme C4 qui maintiennent la rigueur sémantique.
- La mesure en bytes de code source plutôt qu'en taille de binaire compilé est trompeuse et peu représentative de la complexité réelle de l'implémentation.
- Les raccourcis pris (comme traiter n'importe quel 'p' comme print) créent des ambiguïtés bizarres rendant le langage peu pratique, même comme exercice pédagogique.
- Le projet aurait eu plus de valeur en implémentant des structures de données pratiques (listes, dictionnaires) comme le ferait un vrai interpréteur minimaliste.
