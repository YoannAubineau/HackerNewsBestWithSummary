## Résumé de l'article

dbt Labs lance dbt Charts, un langage déclaratif YAML open source qui permet de créer des tableaux de bord interactifs en code plutôt que dans une interface graphique. Cet outil s'inscrit dans la continuité de l'« unbundling » de la BI : alors que les outils BI traditionnels concentrent tout (données, transformation, visualisation), dbt Charts extrait spécifiquement la couche graphique pour la rendre accessible aux agents IA et aux développeurs qui préfèrent travailler en code.

- Un tableau de bord complet se déclare dans un seul fichier YAML auditable, avec SQL pour les requêtes et Markdown pour le texte descriptif
- Supports seize types de graphiques (plus de 1 100 options de configuration), rendu en SVG, HTML, PNG, PDF ou terminal, sans dépendances complexes (pas de bibliothèques ou frameworks séparés nécessaires)
- Intégration profonde avec dbt : les graphiques vivent dans le même dépôt Git que les modèles (dossier `charts/` à côté de `models/`), permettant une livraison atomique et des validations CI/CD
- Une plateforme hébergée bêta (dbtCharts.com) ajoute accès contrôlé, historique de version, éditeur visuel et analytique conversationnelle permissionnée
- Le langage valide strictement le YAML et SQL, et fournit des avertissements de visualisation avant publication (ex : « colonnes trop étroites », « débordement de tableau »)

## Discussion sur Hacker News (79 commentaires)

**Avis positifs** :
- Crée des artefacts auditable et versionnables pour les dashboards, permettant le contrôle de version et la collaboration type Pull Request, contrairement aux outils BI traditionnels sans SDLC
- Aligne parfaitement avec la tendance du « unbundling BI » où les agents IA génèrent des artefacts structurés plutôt que du code libre-form, améliorant la maintenabilité et l'auditabilité
- Simplifie l'intégration avec dbt et préserve la logique métier en SQL (testable et traçable) plutôt que dans la couche visualisation, résolvant un problème majeur d'audit des sources de données
- Fournit une alternative open source et maintainable aux walled gardens propriétaires, avec cohérence visuelle déterministe contrairement aux dashboards générés ad-hoc par IA
- Utile pour les cas d'usage rapides (alertes quotidiennes Slack/Teams) et compatibilité avec les workflows existants des analystes (SQL, Jinja, YAML)

**Avis négatifs** :
- Manque des fonctionnalités essentielles BI comme la gouvernance, les contrôles d'accès, l'interactivité avancée, les semantic layers et les KPIs, réduisant son positionnement comme solution BI complète
- Peu innovant fondamentalement : l'IA génère déjà du YAML/JSON/XML pour d'autres outils BI (Power BI, Superset), le format n'est pas la vraie différence
- Le choix de YAML crée des limitations (pas de conditionnels/variables élaborés, moins de boucles de feedback d'erreur que du vrai code), et risque de devenir complexe avec feature creep
- Potentiellement tardif : les utilisateurs s'habituent déjà à obtenir exactement ce qu'ils veulent via des agents générant du React/code complet, plutôt que des specs contraintes
- Reste une couche de visualisation statique ; les vrais agents et utilisateurs préfèrent l'interactivité dynamique (filtres, drill-down, réactivité) que cette approche limite
