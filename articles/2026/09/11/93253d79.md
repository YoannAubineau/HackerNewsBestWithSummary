## Résumé de l'article

Astra est le dernier modèle GPT-6 d'OpenAI, un modèle très performant spécialisé dans l'utilisation d'ordinateurs et la compréhension d'images complexes. Cependant, l'auteur (Armin Ronacher, contributeur CPython) le considère comme inadapté au développement logiciel pratique en raison de comportements problématiques observés lors d'une expérience d'usine logicielle autonome de 35 heures.

- Astra préfère générer des scripts Python pour les manipulations de fichiers plutôt que d'utiliser les outils standard (bash, sed), ce qui rend le code très peu lisible et difficile à suivre pour les humains.
- Le modèle optimise fortement pour l'efficacité des tokens et la complétude des tâches, mais génère un code incohérent : il utilise des constantes magiques aléatoires, imbrique des langages (Python → Node.js → PowerShell) et présente des styles de code qui ne correspondent à aucune base de code existante.
- L'usine logicielle a produit 75 000 lignes de code en 35 heures (79 commits à ~15,50 USD chacun) sans véritable résultat utilisable, révélant une trajectoire d'optimisation locale sans optimum global.
- Le modèle génère du « code médiocre » selon les normes humaines parce qu'il est récompensé par des métriques facilement quantifiables (tokens, complétude) qui ne tiennent pas compte de la lisibilité et la compréhension humaines.
- L'auteur conclut que malgré les capacités impressionnantes d'Astra, ces modèles semblent conçus pour d'autres domaines (art 3D, droit, mathématiques) et ne constituent plus une amélioration viable pour l'ingénierie logicielle par rapport aux versions précédentes.

## Discussion sur Hacker News (235 commentaires)

**Avis positifs** :
- Les modèles récents comme Astra démontrent des gains de productivité mesurables : certains développeurs rapportent que des tâches prenant des semaines ou des mois se font maintenant en heures, avec tests et expérimentation intégrés.
- Sur les codebases établies avec bonnes pratiques (architecture claire, contexte fourni, processus de revue humaine), Astra produit du code de qualité professionnelle et accélère significativement le développement des nouvelles fonctionnalités.
- L'amélioration continue est réelle depuis Opus 4.5 : les modèles gèrent mieux la complexité, offrent des propositions architecturales solides, et peuvent guider les développeurs dans la compréhension des concepts qu'ils implémentent.
- Comparé aux compilateurs de jadis, les LLMs representent une abstraction utile : on n'a pas besoin de lire l'assembleur généré, tout comme on n'a pas besoin de lire tout le code généré par l'IA si les tests passent.
- Les modèles excellents pour certaines tâches ciblées : débogage, réponse à des questions spécifiques, et refonte de code dans des contextes bien définis, où la surface à réviser est maîtrisée.

**Avis négatifs** :
- Astra produit du code lisible de mauvaise qualité : commandements bash/Python obsédés d'options, mégafunctions avec ternaires condensés, réinvention systématique de la stdlib, et manque de réutilisation de patterns existants.
- Surengineering chronique et goldplating involontaire : le modèle ajoute continuellement 'une chose de plus', lance des suites de tests complètes en boucle, crée des refactorisations non sollicitées, et peut transformer une simple tâche en marathon de 6+ heures.
- Coût exorbitant : Astra consomme 2.5× plus de tokens que Sol pour des résultats égaux ou pires, multiplie ce coût via ses sous-agents, et les sessions longues accumulent rapidement des factures massives pour peu de progrès tangible.
- Dégradation apparente des capacités : les modèles semblent moins précis avec des instructions vagues qu'avant (février 2024), et requièrent maintenant plus de spécification que jamais, ce qui remet en question le gain réel par rapport au développement manuel.
- L'approche agentic 'sans relecture' crée de la dette technique insurmontable : dans les codebases de production, les équipes qui ne lisent pas le code ralentissent à mesure que l'incompréhension s'accumule, avec des effets externalisés sur les pairs et incidents en production devenant inévitables.
