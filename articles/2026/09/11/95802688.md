## Résumé de l'article

L'Agents API d'OpenAI est une interface gérée qui permet aux applications de créer des agents autonomes exécutant des tâches complexes. OpenAI gère les sessions, l'orchestration et la compaction du contexte, tandis que l'application fournit les outils et choisit l'environnement d'exécution (sandbox hébergée ou auto-hébergée).

- Les agents peuvent exécuter du code, modifier des fichiers, se connecter à des serveurs MCP et générer des artefacts dans des environnements sandbox
- L'API facture l'utilisation du modèle aux tarifs standard d'OpenAI, incluant les outils et les sandboxes hébergées
- Une session persiste l'état de l'agent permettant de poursuivre le travail entre les tours sans reconstruire le contexte de conversation
- Les agents supportent les sous-agents concurrents, la recherche web, les outils personnalisés et les instructions spécialisées
- Les données résident actuellement aux États-Unis uniquement ; ZDR (Zero Data Retention) n'est pas supporté

## Discussion sur Hacker News (161 commentaires)

**Avis positifs** :
- Simplifie le déploiement des agents en gérant l'infrastructure (sandboxes, scaling, sécurité) sans que l'utilisateur n'ait à maintenir ses propres VMs
- Offre une abstraction utile pour les cas d'usage en production où la simplicité opérationnelle et la conformité comptable/de conformité sont importantes
- Permet de paralléliser facilement des centaines de sessions d'agents sans infrastructure locale, résolvant les limitations de scaling des solutions auto-hébergées
- Fournit une couche de gestion cohérente pour la mémoire, la gestion du contexte et l'orchestration des workflows persistants
- Représente une direction sensée pour intégrer les capacités agentiques dans les produits sans gérer directement les sandboxes

**Avis négatifs** :
- Crée un verrouillage fournisseur préoccupant au moment où aucun gagnant clair n'existe ; beaucoup préfèrent construire leurs propres harnesses avec des outils open-source sur l'infrastructure cloud existante
- Les exemples de documentation GitHub pointaient initialement vers des URLs 404, suggérant que le produit n'était pas prêt pour une sortie publique réelle
- Les restrictions de sandbox (hostnames, domaines autorisés) ont déjà été contournées dans le passé ; la sécurité de ces restrictions reste douteuse
- Force à utiliser les modèles propriétaires d'OpenAI au lieu de permettre de choisir entre fournisseurs ; les modèles moins chers (DeepSeek, GLM Flash) peuvent être meilleurs pour la plupart des cas d'usage agentiques
- Combiné à une facturation minimale par session activée, le coût peut être prohibitif pour les petites organisations ; nécessite une infrastructure côté serveur coûteuse ET les frais d'API
