## Résumé de l'article

Darling est un logiciel libre et open-source qui permet d'exécuter des applications macOS directement sur Linux sans émulateur matériel, fonctionnant de manière similaire à Wine pour Windows. Le projet implémente un environnement Darwin complet (incluant Mach, dyld, launchd) et supporte les applications graphiques simples en version expérimentale.

- Darling traduit les appels système et les bibliothèques Darwin pour que les apps macOS s'exécutent nativement sur Linux, sans violer la licence d'Apple en utilisant uniquement les parties libres de Darwin
- Le projet vise à intégrer les applications Darling dans l'expérience desktop Linux en les faisant apparaître et se comporter comme des applications natives
- Darling fonctionne sur Linux et également sur Windows via WSL 2 ; il est distribué sous licence GNU GPL v3 et développé publiquement sur GitHub
- Les applications graphiques sont actuellement supportées de manière expérimentale basique, tandis que le support des apps iOS sur appareils ARM est envisagé à long terme
- Le projet s'appuie sur le code source Darwin publié par Apple et réutilise des composants comme The Cocotron pour l'implémentation Cocoa

## Discussion sur Hacker News (73 commentaires)

**Avis positifs** :
- Darling est un projet intéressant basé sur le code Darwin open source publié par Apple, offrant une base solide pour l'émulation macOS sur Linux
- L'absence de rétrocompatibilité stricte chez Apple crée un vrai besoin : contrairement à Windows, chaque version majeure de macOS est un 'flocon de neige' avec ses propres dépréciations et changements
- Pour certains cas d'usage spécifiques (compilation croisée, outils CLI), l'infrastructure existe déjà : xcodebuild et les compilateurs Metal/Swift fonctionnent partiellement sur Darling
- Les applications ARM64 sur Linux ARM auraient intérêt à contourner les couches d'émulation x86, rendant un support natif potentiellement utile pour certains flux de travail

**Avis négatifs** :
- Darling manque cruellement de développeurs et de maintenance : seulement 20-30 commits tous les 5 ans sur l'implémentation AppKit, bien loin de la cadence nécessaire
- Les frameworks GUI macOS (Carbon, Quartz, AppKit) ne sont pas open source et sont intentionnellement liés à Apple Silicon/macOS, rendant une implémentation indépendante extrêmement difficile, contrairement à Win32
- Le support GUI reste 'expérimental et basique' : impossible de faire tourner des applications complexes comme Logic Pro, Xcode, Final Cut Pro ou Photoshop ; la majorité des utilisateurs Linux ne voit aucun logiciel macOS indispensable à émuler
- Wine a 30 ans d'avance (depuis 1993) avec une communauté, une base de données de compatibilité, et des suites de tests massives; Darling est à un stade précoce sans ces infrastructures d'appui
- L'audio sur Linux reste problématique pour les DAW : même avec Bitwig ou Reaper disponibles nativement, la majorité des utilisateurs Linux s'attendent à des logiciels gratuits, contredisant le modèle économique d'Apple (Logic offert à bas prix pour fidéliser l'écosystème Mac)
