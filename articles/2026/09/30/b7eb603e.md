## Résumé de l'article

Pi, un assistant IA, intègre désormais MCP (Model Context Protocol) en tant que fonctionnalité centrale, alors qu'il l'avait précédemment rejeté publiquement. Cette décision résulte d'une évolution de MCP lui-même et de la découverte que les modifications nécessaires pour l'intégrer apportent des bénéfices généraux à Pi, notamment en facilitant l'utilisation d'outils comme Jev.

- MCP a évolué au cours de l'année écoulée, et Pi a réévalué son approche pour l'adopter plutôt que de le laisser en extension
- Pi a introduit « Codemode », un mécanisme de sandbox JavaScript qui s'exécute côté harness pour orchestrer les appels d'outils avec plus de flexibilité
- L'intégration de MCP avec Codemode résout plusieurs limitations historiques de MCP, notamment la difficulté de composer les outils
- Pi envisage MCP comme devant se rapprocher d'OpenAPI avec découverte intelligente des outils, où les outils retournent des données structurées plutôt que du texte brut
- Cette approche permet des configurations avancées comme combiner l'API Linear MCP et Jev pour analyser des données directement dans Pi sans surcharger le contexte

## Discussion sur Hacker News (305 commentaires)

**Avis positifs** :
- MCP est devenu inévitable dans les contextes d'équipe et d'entreprise, offrant sécurité, télémétrie et gestion centralisée des credentials que les CLI ne fournissent pas
- L'intégration native de MCP dans Pi simplifie le flux de travail et élimine la friction des extensions tierces, notamment pour les utilisateurs non-techniciens des applications grand public
- Codemode résout les vrais problèmes de composition MCP en sandboxant l'exécution des scripts et permettant l'orchestration parallèle de multiples outils au sein d'une même harness
- Le changement d'avis de Pi démontre une flexibilité saine : MCP s'est amélioré (statelessness, OAuth), les use-cases se sont clarifiés (au-delà du simple développement local)
- MCP s'est révélé particulièrement utile pour les agents non-codeurs, les applications macOS complexes, l'automatisation domotique et les cas d'usage professionnels où bash n'est pas disponible

**Avis négatifs** :
- Pi abandonne son positionnement initial de harness minimal et extensible pour devenir une stack opinionnée, s'éloignant de sa philosophie fondatrice de flexibilité utilisateur
- MCP intégré ajoute de la complexité et du bloat au projet ; les mêmes fonctionnalités existaient déjà via extensions tierces bien maintenues depuis des mois
- OpenAPI était suffisant et déjà standardisé ; MCP réinvente la roue (XKCD#927) avec un protocole propriétaire et immature comparé aux APIs REST établies
- La composabilité revendiquée reste limitée : les serveurs MCP hétérogènes ne composent pas bien entre eux, et bash/Python natifs suffisaient déjà pour orchestrer les outils localement
- La marche hype anti-MCP de mars 2026 rend suspect ce revirement : le timing et les influenceurs créent une dynamique de FOMO plutôt qu'une décision technique rationnelle
