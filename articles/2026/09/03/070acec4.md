## Résumé de l'article

Polars, bibliothèque Python de traitement de données, publie son premier candidat à la version 2.0, prévue dans les semaines suivantes. Cette version majeure cherche avant tout à améliorer les défauts de conception antérieurs et à corriger les comportements par défaut, plutôt que d'ajouter de grandes nouvelles fonctionnalités.

- Le moteur de streaming devient le comportement par défaut pour les LazyFrame, promettant des améliorations massives en mémoire et performance (environ 5x plus rapide), mais garantit moins l'ordre des lignes dans certaines opérations (jointures, regroupements, etc.) — les utilisateurs peuvent passer le paramètre maintain_order=True si nécessaire
- Polars impose des comportements plus stricts : les opérations sur types de données incompatibles (is_in, concaténations) lèvent maintenant des erreurs au lieu de convertir silencieusement, forçant les développeurs à exprimer explicitement leurs intentions
- Les conversions de types ambiguës (cast) sont supprimées au profit de méthodes dédiées (.str.to_date(), .cat.to(), etc.) pour clarifier les opérations de parsing et transformation
- Des exceptions plus explicites (AttributeRemovedError, ArgumentRemovedError) remplacent les anciennes APIs, avec messages guidant vers les nouvelles méthodes équivalentes
- Les utilisateurs préférant le moteur précédent peuvent le conserver via pl.Config.set_engine_affinity("in-memory") ou par requête ; un guide de migration complet est disponible

## Discussion sur Hacker News (91 commentaires)

**Avis positifs** :
- Polars prend au sérieux la versification sémantique en utilisant les versions majeures pour éliminer la dette technique plutôt que pour ajouter des fonctionnalités flashy, ce qui favorise une évolution durable
- L'API est plus stable et stricte que Pandas en production, détectant les bugs lors du planning plutôt qu'à l'exécution, particulièrement pour les variations de types de données et valeurs manquantes
- Le moteur d'exécution « streaming » (par lots dans le cache) offre des améliorations de performance significatives en conservant les données dans le cache CPU plutôt que d'opérer à la vitesse RAM
- L'approche par expressions permet une composition et une abstraction supérieure à SQL ou Pandas, facilitant la réutilisabilité du code et la construction de logiques complexes par couches
- Polars offre une alternative Python cohérente qui peut être portée vers Rust pour des applications de production robustes, avec des garanties au niveau du compilateur

**Avis négatifs** :
- Polars nécessite de lire les notes de chaque version mineure en raison de dépréciations et changements fréquents, rendant la maintenance fatigante malgré une versification sémantique supposément stricte
- Le changement de défaut maintain_order=False pose des risques pour l'informatique scientifique où le non-déterminisme est un vecteur de bugs subtils et silencieux difficiles à détecter
- La syntaxe, bien qu'améliorée par rapport à Pandas, reste plus verbeuse que des alternatives comme R/dplyr ou SQL, et les nouvelles APIs rendent les connaissances antérieures rapidement obsolètes
- Pour les utilisateurs occasionnels ou ceux avec des besoins simples, Pandas reste plus ergonomique, et les avantages de performance de Polars ne justifient pas toujours la courbe d'apprentissage
- L'absence de requêtes paramétrées crée un risque élevé d'injection SQL quand on utilise l'interface SQL de Polars
